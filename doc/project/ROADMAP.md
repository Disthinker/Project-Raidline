# Project Raidline 产品路线

本文只维护产品阶段、顺序和范围边界。当前分支、PR、CI、测试数量和短期缺陷不属于路线事实。

## 交付原则

- 以完整玩家结果组织切片，不以 Week 编号或单个技术边界组织里程碑。
- 每个切片连续完成领域、服务、客户端、自动化、PR/CI；玩家可见行为最后由用户一次正常游玩验收。
- 架构保持 C++20/SDL3 模块化单体、Windows PC、键鼠优先、纯单机离线；不提前引入联机、主机、公开 Mod、ECS、服务定位器或通用事件总线。
- 长期 GDD 只决定兼容方向；功能必须进入当前范围合同后才能实现。

## 已接受基础

| 阶段 | 已形成的稳定结果 |
| --- | --- |
| Core Extraction Alpha | Persistent Base、唯一资产、真实库存/弹药/医疗、一张冻结快照地图、撤离/全损、幂等结算、经济救济与跨进程存档 |
| Survival Loadout 基础 | 防具与命中部位、流血/疼痛/战地医疗、武器耐久/故障/维护、多武器切换、防具维护 |

| 工程基础 | 四库模块化单体、版本化 ContentRegistry、schema v6、Windows/Ubuntu exact-head CI |

精确接受证据在 completed ExecPlan 与 PR #55～#68。

## 后续完整游戏阶段

| 阶段 | 目标 | 不提前实现的代表系统 |
| --- | --- | --- |
| Survival Loadout | 完成真实配装、损耗与医疗取舍 | 其余装备槽、组件/改枪、战术电子、复杂伤势与完整故障 |
| Raid Pressure & Variety | 增加固定地图、路线、撤离和持续压力差异 | 多固定地图、高危、特殊撤离、情报、尸体、更多敌人；随机地图后置 |
| Base Growth | 把带回物转化为长期能力与人群选择 | 唯一 WorldClock、商人、制造、设施、人口、士气与愿望 |
| Regional Campaign | 形成空间战略和周期危机 | 地点、旅行、迁徙、哨所、战斗小组、外围行动、尸潮攻城 |
| Content Beta | 形成内容体量和环境叙事路线 | 派系、敌人生态、剧情路线、系统商店、随机地图候选 |
| Release Candidate | 形成可发布 Windows 产品 | 正式美术/音频、性能、可访问性、本地化、打包、诊断、迁移演练 |

每个阶段仍需拆成独立范围合同。不得把完整基地经营、四人小队、愿望、多基地、尸潮或长期任务系统静默塞入近期 Combat/Inventory 切片。

## 长期边界

- 高倍光学视野等待合法瞄具和附件消费者；当前不先建通用相机框架。
- 固定地图定义、RaidSnapshot 和验证器稳定后，随机地图才单独立项。
- Base Growth 先建立唯一 WorldClock，再增加共享时间轴消费者。
- Week29 代码反馈只能按现有投影边界独立整理；正式攻击动画和未授权资源生产继续暂停。
