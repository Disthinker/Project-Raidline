# Project Raidline 项目概况

## 定位

Project Raidline 是一个使用 C++20、SDL3 和像素资源构建的 2D 游戏原型。产品方向由用户定义为“2D 斜俯视角像素风末日搜打撤”，当前代码仍处于垂直切片集成阶段；该方向不等于完整搜打撤循环已经实现。

## 技术基线

- 语言与运行时：C++20、SDL3、SDL3_image。
- 构建与依赖：CMake、Ninja、vcpkg manifest。
- 自动测试：GoogleTest、CTest；艺术管线另有 pytest。
- 持续集成：GitHub Actions 在 Windows 2022 与 Ubuntu 22.04 上构建全部 C++ target 并运行完整 CTest。
- 主程序 target：`Project_Raidline`。

## 当前可运行切片

- 顶层流程：启动于 MainMenu，经 Base 部署到 Raid，完整结算后进入 RaidResult 并返回 Base；非 Raid 屏幕冻结世界，Enter/点击只提交一次屏幕转换。Week25 已通过 PR #46 合入。
- 玩家：WASD 移动、鼠标独立瞄准、左键/Space 连续射击、确定性扩散与可视后坐力；默认拥有 3 HP 并显示调试生命文本。
- 敌人与战斗：水平移动和边界反弹、Health、AABB 命中、伤害、死亡、调试分数；敌人接触可按冷却伤害玩家并触发真实失败结算。
- 表现：玩家/敌人水平帧动画、代码准星、细小火光弹道、命中火花、背景与物品贴图。
- 世界物品：Cola、Medkit、Pistol、Rifle 与可堆叠 9mm 弹药；共享定义和 move-only 稳定 ID 实例分离，地面物品由 F 键拾取并可原子合并。
- 背包：玩家 10×6 与柜体 6×6、确定性 first-fit、footprint、四向物品方向、数量堆叠、稳定 ID 和事务式放置/移动/跨容器转移。
- 背包 UI：Tab/柜体上下文视图；纯鼠标阈值拖拽；平滑虚影与吸附 footprint 分离；F/Ctrl+右键整栈快捷转移；R 拖拽旋转；Ctrl/Shift+左键按数量拿取；Esc/Tab 取消优先；方向键和 Enter 无背包语义。
- 物品丢弃：玩家整栈或选中数量可拖到明确丢弃区并在角色脚下生成地面物品；第二容器物品不能直接丢弃。
- 搜索与 Loot：世界柜体首次近距离 F 交互按加权 LootTable 生成一次战利品；关闭、转移、取空和重开均保留当前世界生命周期内的真实搜索状态。
- Raid 与撤离：从 Base 部署后开始 180 秒 Raid；玩家中心进入左下撤离区并连续停留 3 秒可撤离，离开会清零进度；撤离、敌人攻击导致的玩家死亡或超时形成不可逆终局并冻结世界玩法更新。
- 敌人 AI 与攻击：敌人在活动 Raid 内以较低常速确定性二维追击，普通近战默认短前摇挠击；至少挠击一次后，玩家退到中距离并维持约 0.5 秒才会诱发带移动前摇的抱取冲刺。抱住后咬击造成高伤害和短暂控制，空冲则长时间倒伏失衡；敌人与玩家被命中都会短暂减速。App 用蓝青/金黄/红紫预警、倒伏旋转和调试文字显示阶段及三级速度。
- Raid 结算与 Stash：撤离把玩家背包完整堆叠原样转入内存 Stash，死亡/超时清空携带物并记录损失；结算反馈显示栈数和单位数，容量或 ID 冲突不会部分提交。
- 可重复会话：结算结果确认后返回 Base，再由 Deploy 以空背包开始下一 Raid；世界、柜体、敌人和倒计时重置，Stash 与稳定 ID 序列在当前进程内跨局保留。Week23 的直接 `N` 重开已由 Week25 流程取代。

## 当前产品边界

尚未实现：最终主菜单/基地美术与功能、地图副本选择、敌人视野/听觉/丢失目标、寻路/避障、多敌人协作、正式抓/挠/咬动画与音效、可操作 Stash UI、从 Stash 选择出战物、跨进程保存、局内重开、多柜体/搜索计时、外部数据驱动 Loot、治疗、击退/受伤表现、装备栏、上下文菜单、重量/耐久、音频、程序地图、尸体搜索和完整武器装填/弹匣系统。Week27 的全知确定性 AI 与代码预警只是 V0，不代表完整敌人智能或正式战斗表现；Week26 的代码准星、弹道和后坐力是可调 V0，不代表完整武器系统；Week25 只是代码绘制的单地图流程壳，不代表基地系统或多地图内容完成；新 Raid 使用空背包，也不代表配装或持久化已经完成。9mm 只是数量物品，不代表完整武器弹药系统已经完成。

这些内容只能作为候选路线，不能在当前任务中被当作现有能力或默认承诺。详见 [ROADMAP.md](ROADMAP.md)。

## 工程原则

- 以小步、可运行、可测试的闭环推进。
- 先建立核心模型和不变量，再接 SDL 输入与渲染。
- 区分共享定义与唯一实例，明确每次所有权转移。
- 区分纯查询与事务式提交，失败不改变状态。
- 使用稳定 ID，避免把容器下标、引用或迭代器当作跨帧身份。
- 不为未排期系统提前引入 ECS、SceneManager 或通用服务层。
