# Project Raidline 领域不变量

最后核对：2026-08-20。违反以下任一条都属于阻断交付的正确性缺陷。

## 所有权与实例

- 内容定义使用带领域标签的稳定命名 `DefinitionId`；不同定义域不能隐式互换，显示名称或枚举序号不得成为新内容的持久身份。
- `ContentRegistry` 构造后不可修改；任何不支持 schema、重复 ID、非法引用、非法数值、越界首图锚点或未发布资源引用都必须阻断内容加载。
- `ItemDefinition` 是不可变共享定义；`ItemInstance` 是 move-only 唯一资产并拥有稳定非零 ID。
- 当前 `ItemId` 只允许服务历史 V0 回归；生产 Alpha 已使用 Profile Asset Registry，新定义不得通过扩展该枚举绕过稳定字符串 ID。
- 每个实例任一时刻恰有一个权威 `AssetLocation`：Stash、装备槽、容器分区、武器/弹匣/枪膛、动作暂持、地面或结算中转。
- 容器内容跟随容器实例移动；非空容器禁止嵌套；空容器也必须满足固定占格与合法分区。
- 弹药单位只能处于散装堆、弹匣有序序列、枪膛、动作暂持或明确地面结果之一。
- 死亡、动作中断、Deploy 和结算必须收束全部暂持位置，不能遗留悬空资产。
- 稳定实例 ID 单调分配且不复用；删除实例不回退高水位。

## 查询、命令与事务

- 查询不修改状态。拒绝命令使所有参与者、货币、高水位和版本保持不变。
- 多所有者移动、交换、堆叠、装备、买卖、Deploy 和结算必须原子提交。
- 提交前复核源、目标、父容器、容量、版本和 ID 冲突；UI 预览不授予提交资格。
- 不得跨 `std::vector` erase/insert/reallocation/move/commit 保存引用、指针或迭代器。
- App 只提交领域命令并消费领域结果；名称、图标、颜色、动画、屏幕格位与碰撞标签不决定合法性。

## 当前 GridInventory 适配器

- 普通整堆拖拽的预览查询与释放命令使用同一规则；查询不得修改源、目标或 ID 序列。
- 空目标保持既有同容器 transform 或跨容器 transfer；同定义未满堆最多填充到定义的 `maxStackSize`。
- 完全吸收时移除源实例并保留目标稳定 ID；容量不足时目标补满，源以原稳定 ID、位置和方向保留余量。
- 满堆、定义不匹配、不可堆叠、缺失源和跨容器稳定 ID 冲突均失败且不改变状态。
- 整堆合并不分配新稳定 ID，也不推进高水位；不得跨删除保存业务指针或迭代器。
- Ctrl/Shift 数量拖拽仍是“精确请求数量或完全不变”的独立原子合同，不允许隐式部分提交。

## 流程与场景

- `GameFlow` 只拥有屏幕级状态；`GameSession` 是长期组合根。
- `BaseWorld` 与 `GameplayWorld` 互斥运行。Base 不推进敌人、Loot、战斗或 Raid 生命周期。
- Base 场景、设施对象与 UI 不拥有 Stash、装备、货币或唯一资产。
- Core Extraction Alpha 中时间不能产生 Raid 失败；只有撤离、死亡或玩家主动放弃能终结并结算 Raid。关闭程序或异常退出不结算，重新进入时必须恢复出击前持久化 Profile。
- Loot 和敌人部署在 Raid 创建时一次生成并保存快照；搜索、重载、接近和击杀不得重抽或补充。
- Raid 快照中的 Loot 实例 ID 是生成审计记录；拾取后可以通过合法堆叠或装填消耗该实例，但任一仍在 Raid 地面的资产必须继续能追溯到快照。

## 射击、命中与反馈

- 成功击发先形成 `ShotCommand`，领域解析为 `ShotResolution`；伤害与反馈只消费 `HitResult`。
- 生产射击不创建可渲染或可碰撞的场景弹丸。短生命值逻辑飞行只保存冻结本发值和已飞距离，不具有资产、场景或持久化身份。
- 本发终点在成功击发时冻结；后续鼠标、角色移动或 App 表现不得修改。短轨迹只能覆盖已经飞过的区段，不能预画未来路径。
- 实际准星中心决定本发总体方向；最终方向必须再由 simulation 在当前散布内抽取并冻结。稳定性和连续开火只改变散布增长，App 不得用原始鼠标点、准星图形或随机表现替代领域射击方向。
- 后坐力可以推动实际准星中心且不得随时间自动回正；停火恢复的是散布。后坐力控制、稳定性、操控速度、人机工效与精准度只能通过不可变 WeaponUse 定义和 simulation 映射生效，App 不得按武器名称重复解释。
- ADS、移动、射程和换弹上下文只能通过明确会话输入影响准星/散布。超过最大射程的减伤必须在伤害领域消费冻结射程结果；红色准星只是一份只读投影，不能成为伤害判定来源。
- 逻辑飞行使用连续线段扫掠并选择最先接触的活目标；一次最多命中一个活目标，死目标不能重复受伤或计分。未命中只在到达冻结终点时形成一个 World HitResult。
- 普通命中、爆头、弱点、防具和穿透必须由领域结果明确表达；App 不得根据碰撞或表现猜测。
- 武器定义必须显式声明一个或多个兼容武器槽；装备、快速装备和交换只能由同一 InventoryDomain 规则决定。长枪不能进入手枪槽，手枪不能进入长枪槽。
- Raid 当前武器只选择一个已装备实例。切换完成前不得改变当前槽；中断不能迁移弹药、耐久或故障。射击、换弹和清障必须作用于当前实例，不能回退为固定主武器槽查询。
- Rifle/Pistol 的自动或半自动输入语义、射击瞬态和切换耗时来自不可变 WeaponUse 定义；App 不得按显示名称猜测。弹匣兼容性仍由 WeaponAmmo 领域查询决定。
- 普通命中最终不显示准星 X；在命中部位合同形成前，不得把所有命中临时标成爆头或弱点。
- 敌人与玩家单纯重叠不造成被动伤害。Grab 本身 0 伤害，只能在接触后原子转换为 Bite；AI 不独立选择 Bite。
- Scratch/Bite 使用 `Windup → Active → Recovery → Idle`；未命中 Grab 使用 `Windup → Active → OffBalance → Idle`。一次动作链最多提交一次伤害。

## 持久化与幂等

- 保存稳定 ID、定义 ID、实例字段、所有权关系、货币、标志、版本和高水位；禁止保存指针、引用、vector 下标、UI 单元格或场景地址。
- 保存版本变化必须有迁移路径和默认值；主档写入采用校验后的原子替换。
- 滚动安全备份只用于主档损坏或迁移失败恢复，不作为玩家回档槽。
- Deploy 在进入 Raid 前原子持久化完整出击前 Profile；当前产品不保存可续玩的运行中 Raid。关闭程序后必须恢复该出击前状态。
- 同一结算 ID 最多改变长期档案一次；重放返回已提交结果。旧 schema 遗留的 pending Raid 加载时必须删除该局生成物并原子回滚到入场快照，不能产生重复结算或资产。

## 生命状态与医疗

- 伤害、护甲与伤势判定在同一 Profile 候选中提交；App 不得根据攻击名称、颜色或血条猜测流血。
- 轻度和重度流血任一时刻最多各自表现为单一权威等级；轻伤刷新、重伤升级，不允许叠加多个独立 DOT 实例。
- 流血不得把玩家降到 1 HP 以下。死亡只能来自明确的伤害结算；状态推进不得绕过 Raid 生命周期。
- 疼痛从有效伤势派生，不保存互相矛盾的第二份布尔状态。止痛药只压制疼痛表现与惩罚，不移除伤势来源。
- 医疗适用性、耗时、消耗与效果来自类型化内容定义和领域查询。拒绝与中断不能消耗物品；连续治疗在首个实际恢复点消费一次，已恢复 HP 不回滚。
- Base 不推进流血、疼痛叫声或药效计时；成功撤离保留状态，失败结算清除状态并恢复 100 HP。

## 防具维护

- 防具材质来自不可变内容定义，只决定维修成本；App 不得根据名称、槽位、颜色或图标推断材质。
- 甲修查询必须同时计划实际恢复、维修点消耗、当前最大耐久变化和动作时间；提交不得重新用另一套舍入规则计算其中任一值。
- 防具维护只能作用于一个真实甲修包实例和一个真实防具实例。Base 允许任意合法自有位置，Raid 要求两者均为随身资产；拒绝保持 Profile 指纹、revision、货币和稳定 ID 高水位不变。
- 每次合法维修永久降低当前最大耐久，但不得低于出厂最大耐久的 20%；当前耐久不得超过维修后的当前最大耐久。维修点不足时只能提交完整支付的整数修复量。
- Raid 防具维修在完整动作结束时一次提交。普通移动以基础速度的 45% 进行且不中断；战斗、冲刺、受伤、库存或受控中断时不修复、不消耗。受击与完成同帧时先按命中前防具状态提交伤害，再决定中断。
- Raid 内修复随其他运行中 Profile 状态参与撤离/失败；关闭程序仍恢复精确出击前档案，不得把局内自助维修提前写入主档。

## 美术发布

- runtime 只读取已批准并发布的 `assets/`；`art/work/` 永远不是运行时依赖。
- 未重新授权前不得生成、发布、接入正式 Grab/Scratch/Bite 或其他新美术/音频，不得修改 manifest。
- 代码 fallback 不得自行升级为“正式资产已完成”的项目事实。
