# Project Raidline 性能预算与扩展门槛

最后核对：2026-08-26。本文定义从 Raid World 阶段开始执行的最低性能防线。它不是最终发行性能承诺；Release 构建、真实 GPU、帧时间分位数和长时间运行门槛将在集中稳定性切片继续补齐。

## 当前帧预算

- Windows PC 目标仍为 60 FPS，即完整一帧约 16.67 ms。simulation、SDL 渲染、音频提交和系统调度共同消费该预算，任何一个子系统都不能把 16.67 ms 当作自己的独占额度。
- Windows Debug 无窗口压力门槛：8 名敌人、26 个静态障碍、120 次 1/60 秒更新，总耗时必须低于 1500 ms，任一 simulation 更新的粗粒度防卡死门槛为 100 ms；当前本机证据约为 422 ms 总耗时、最慢更新约 6.1 ms。每次 60 Hz 更新最多执行 2 条昂贵路径查询，并验证全部敌人最终获得预算。
- 上述 Debug 门槛是防止数量级回退的 CI 警戒线，不等价于真实窗口 60 FPS 证明。玩家正常游玩、Release/RelWithDebInfo 采样和 95/99 百分位帧时间以后分别记录。

## 每帧工作规则

- 静态空间数据只在 RaidRuntime 构造时准备。敌人导航按 `RaidSpaceDefinitionId + actorSize` 缓存障碍扩张和角点可见图，不允许每个敌人每个子步重建整图。
- 动态导航目标以 10 Hz 刷新；移动、攻击阶段和碰撞仍按现有细步推进。每个 simulation 子步全体敌人合计最多执行 1 次昂贵动态路径查询，超额敌人沿用已有路径并在后续子步公平获得预算。
- App 接收的单帧时间最多为 100 ms。调试器暂停、远程桌面抖动或窗口切换不会要求主线程在一帧内补算任意长的历史时间。
- 障碍、敌人、Loot、文本或粒子数量增加时，禁止在热路径中新增无界的全量交叉扫描、资源加载、纹理创建、磁盘访问或存档写入。静态预计算、低频刷新、空间索引或有界队列必须由真实消费者和测量数据驱动。
- 性能监视器的整机 CPU 百分比不能排除主线程瓶颈；必须同时检查单帧 wall time、最慢更新、单核占用及昂贵查询次数。

## 内容扩展门槛

每次提高敌人上限、程序化障碍上限或同时活动空间复杂度时，必须先扩展相应压力场景，并至少验证：

1. 所有敌人最终都获得导航刷新，不因预算饥饿停住。
2. 视线、贴墙接近、绕障、攻击窗口和碰撞行为未被性能缓存改变。
3. 总耗时、最慢帧和单帧昂贵查询数没有跨越当前门槛；若门槛本身需要调整，必须附带真实窗口或采样器证据。
4. 失焦、长帧和恢复不会产生追帧雪崩。

下一阶段集中稳定性门槛将加入多 seed、多局、跨进程、存档迁移、室内/室外切换、失败回退和 Release 帧时间采样；通过后才继续扩大 Raid 内容数量。
