# Project Raidline 性能预算与扩展门槛

最后核对：2026-08-28。本文定义从 Raid World 阶段开始执行的最低性能防线。它不是最终发行性能承诺；Release 构建、真实 GPU、帧时间分位数和长时间运行门槛仍需随对应产品切片补齐。

## 当前帧预算

- Windows PC 当前以稳定 60 Hz 作为最高显示提交节奏；低于 60 Hz 的显示器保留其原生刷新率。60 Hz 下完整一帧约 16.67 ms，simulation、SDL 渲染、音频提交、等待和系统调度共同消费该预算，任何一个子系统都不能把 16.67 ms 当作自己的独占额度。
- Windows Debug 低密度行为门槛：8 名敌人、26 个静态障碍、120 次 1/60 秒更新，总耗时必须低于 1500 ms，任一 simulation 更新的粗粒度防卡死门槛为 100 ms；当前本机证据约为 422 ms 总耗时、最慢更新约 6.1 ms。每次 60 Hz 更新最多执行 2 条昂贵路径查询，并验证全部敌人最终获得预算。
- Windows Debug 扩展门槛使用 1/120 秒固定子步且不包含世界构造：32 名敌人/64 障碍的 120 子步必须低于 750 ms、最慢子步低于 25 ms；100 名敌人/96 障碍必须低于 1000 ms、最慢子步低于 25 ms。2026-08-26 最终本机复测分别约为 117 ms/1.28 ms 与 173 ms/2.29 ms；100 名敌人全部在 120 子步内获得至少一次路径刷新。
- 上述 Debug 门槛是防止数量级回退的 CI 警戒线，不等价于真实窗口 60 FPS 证明。玩家正常游玩、Release/RelWithDebInfo 采样和 95/99 百分位帧时间以后分别记录。

## 每帧工作规则

- 静态空间数据只在 RaidRuntime 构造时准备。每个空间拥有不可变障碍宽阶段索引；低密度导航按 `RaidSpaceDefinitionId + actorSize` 缓存障碍扩张和精确角点可见图，高密度空间（当前阈值 48 个静态障碍）缓存 48px 四邻接可通行网格。网格边在构造时复验 actor-expanded 视线，薄墙不得落在采样点之间而被跨越。
- 动态导航目标以 10 Hz 刷新；移动、攻击阶段和碰撞仍按现有细步推进。每个 simulation 子步全体敌人合计最多执行 1 次昂贵动态路径查询，每个空间保存独立轮转游标；超额敌人沿用已有路径并在后续子步公平获得预算。
- 敌人分离使用 separation-radius 空间格，只检查相邻九格并按稳定敌人索引累加；视线与移动碰撞只检查线段/扫掠包围盒命中的稳定障碍候选。不得用容器迭代顺序改变模拟结果。
- App 接收的单帧时间最多为 100 ms。调试器暂停、远程桌面抖动或窗口切换不会要求主线程在一帧内补算任意长的历史时间。
- SDL client 初始化后请求 VSync 并读取实际状态，但无论驱动报告如何都保留最高 60 Hz 的绝对帧截止时间兜底。VSync 已经阻塞到截止时间时不会额外等待一整帧；高刷新显示或远程显示虚报 VSync 时由 `SDL_DelayPrecise` 补足剩余预算。错过截止时间后必须从当前时刻重新排期，禁止补交历史帧。本合同只稳定显示提交节奏，不等价于 simulation 已迁移为固定 60 Hz。
- 障碍、敌人、Loot、文本或粒子数量增加时，禁止在热路径中新增无界的全量交叉扫描、资源加载、纹理创建、磁盘访问或存档写入。静态预计算、低频刷新、空间索引或有界队列必须由真实消费者和测量数据驱动。
- 性能监视器的整机 CPU 百分比不能排除主线程瓶颈；必须同时检查单帧 wall time、最慢更新、单核占用及昂贵查询次数。
- 开发构建在 Base/Raid 可按 `F9` 打开只读性能面板，显示实际 `VSYNC + DEADLINE / SOFTWARE DEADLINE` 模式、目标刷新率，以及 120 帧 Event、Update、Render/Present、Pacing 和 Total 的平均、P95、最大值；同时保留 simulation 的敌人、障碍、子步、路径、延后、近邻、视线和移动候选计数。VSync 的等待会自然落入 Render/Present，截止时间补足只落入 Pacing。wall time 只存在于 SDL client，不得进入确定性 simulation；面板文字每 30 帧刷新，逐敌人标签最多显示 16 个。`UiTextRenderer` 达到缓存上限时只淘汰一个最久未使用项，禁止整库清空导致周期性纹理重建尖峰。

## 内容扩展门槛

每次提高敌人上限、程序化障碍上限或同时活动空间复杂度时，必须先扩展相应压力场景，并至少验证：

1. 所有敌人最终都获得导航刷新，不因预算饥饿停住。
2. 视线、贴墙接近、绕障、攻击窗口和碰撞行为未被性能缓存改变。
3. 总耗时、最慢帧和单帧昂贵查询数没有跨越当前门槛；若门槛本身需要调整，必须附带真实窗口或采样器证据。
4. 失焦、长帧和恢复不会产生追帧雪崩。

下一阶段集中稳定性门槛将加入多 seed、多局、跨进程、存档迁移、室内/室外切换、失败回退和 Release 帧时间采样；通过后才继续扩大 Raid 内容数量。
