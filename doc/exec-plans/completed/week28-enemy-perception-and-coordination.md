## 目标与玩家可感知结果

把 Week27“始终知道玩家位置、单敌人直线追击”的确定性 V0，深化为仍然简单但更可信的战术行为：

- 玩家进入感知距离后敌人才警觉；拉开到更远距离后，敌人不再继续全知追踪，而是前往最后已知位置并在记忆耗尽后停止搜索。
- 敌人的移动方向按有限转向速率变化，不在玩家横穿时瞬间反向；接近目标、保持近战/支援距离和停止搜索都有稳定边界。
- 正式 Raid 部署多个敌人。敌人基于同一子步开始时的只读位置快照做局部分离，不重叠成一个点，也不因 `std::vector` 遍历顺序产生不同 steering 输入。
- 同一时刻只有一个最近且可行动的敌人承担主攻；其余敌人保持支援距离和侧向空间，不同时堆叠 Scratch/Grab。主攻者死亡、失去目标或进入不可用状态后，职责可确定性转移。
- Week27 的 Scratch、条件 Grab→Bite、OffBalance、三级速度、受击顿挫、单次命中和终局优先级保持不变。

## 冻结范围

### 本轮实现

- 新增 `EnemyAwarenessState`：`Unaware`、`Alerted`、`Searching`。感知使用距离阈值滞回：未警觉时进入较近获取半径才发现玩家；已警觉时只有超出更远丢失半径才丢失视野。
- `EnemyAiState` 保存最后已知世界位置、搜索剩余时间和当前平滑移动方向。目标不可见时只前往最后已知位置，不更新为玩家真实位置；到达或记忆耗尽后进入 `Unaware` 并停止。
- 攻击只能由 `Alerted` 且获得本帧主攻许可的敌人请求；`Searching/Unaware`、支援角色和活动攻击中的敌人不得新开攻击。世界门控只决定“谁可以请求”，攻击距离、冷却与特殊武装仍由各自 `EnemyAiState` 决定。
- 新增 SDL 无关、按值输入输出的确定性小队协调层。它读取子步开始时的敌人中心、存活/感知/攻击快照和玩家中心，选择至多一名主攻者，并为每名敌人给出角色与局部分离向量。
- 主攻者保持 Week27 近战接近与攻击规则；支援者在玩家周围保持较宽距离带，并按稳定敌人槽位选择左右侧向偏置。过近时后撤，过远时接近，位于距离带时只做必要的分离/侧向调整。
- 局部分离只使用有限半径内的存活邻居，结果有界并归一化；所有指令先从不可变快照计算，再按敌人顺序提交，避免先更新者污染后更新者决策。
- 正式 `GameSession` Raid 使用显式默认敌人部署生成三名敌人；测试可通过显式 spawn 列表构造单敌人或多敌人世界。敌人不会在运行中从 vector 擦除，槽位可作为本局稳定的协调次序。
- App 显示每名敌人的感知状态与角色占位标识，并把 HUD 汇总为存活数/警觉数；渲染只读逻辑快照。

### 明确不做

- 不实现墙体/柜体遮挡、视锥、听觉事件、脚步/枪声传播、仇恨表或多玩家目标选择；本轮只有距离感知与最后已知位置。
- 不实现导航网格、A*、碰撞绕障、行为树、ECS、随机权重、通用 GOAP/Utility AI 或动态刷怪。
- 不制作正式攻击/搜索/警觉动画、头顶图标、音效或受伤美术；Week29 继续负责正式战斗表现。
- 不改变玩家武器、背包、Loot、撤离、Stash、结算或地图定义，不进行 GameplayWorld/App 大重构。

## 主要类型、调用路径与所有权

```text
GameplayWorld enemy substep
  -> capture Enemy value snapshots before mutation
  -> EnemySquadCoordinator::decide(snapshots, player center)
       -> at most one Engage directive
       -> Support directives + bounded separation vectors
  -> Enemy::updateTowardsTarget(player position, directive, dt)
       -> EnemyAiState updates perception/memory/turning
       -> Alerted Engage may request Week27 attack
       -> Enemy commits movement or owned attack update
  -> GameplayWorld resolves attack hit/control/terminal transition
  -> App reads awareness/role/attack snapshots for placeholders
```

每个 `Enemy` 唯一拥有自己的感知、最后已知位置、搜索计时、转向、攻击冷却与动作状态。协调层无所有权、无跨帧引用，只返回值类型指令；`GameplayWorld` 保存本子步角色快照供逻辑提交和只读 debug，不能保存 `Enemy&`、iterator 或指向 vector 元素的指针。

## 新增与受影响不变量

- `Unaware` 没有可用最后已知目标和攻击请求；`Alerted` 的目标来自本帧距离感知；`Searching` 只能读取进入搜索前冻结的最后已知位置。
- 获取半径严格小于丢失半径；记忆、距离、角速度和 steering 配置必须为有限正值且顺序合法。
- 每个子步最多一个 `Engage`；选择规则在相同快照下确定，距离相同按稳定 vector 槽位打破平局。
- 协调计算不得修改 Enemy；提交阶段不得持有跨 `std::vector` mutation 的引用。默认部署完成后本轮不增删敌人元素。
- 非有限玩家/敌人/邻居坐标不得产生移动、攻击、记忆污染或 NaN；非法协调输入退化为停止/无主攻。
- 平滑转向的角变化不超过 `turnRate * deltaTime`；不同合理帧切分得到近似等价方向和位置。
- 支援者没有攻击许可，即使进入 Scratch 距离也不提交攻击；它仍可移动、分离和更新感知/冷却。
- 活动攻击继续遵守 Week27 锁向/Grab Windup/Bite 原子转换；小队角色变化不能中断或重定向已开始动作。
- Raid 终局和非 Raid 屏幕不推进感知、搜索、协调或攻击；新 Raid 创建全新敌人状态。

## 分阶段实施与退出条件

2. 转向与距离保持：加入有限转向、主攻/支援移动策略和非法数值边界。退出条件：帧切分、反向目标、过近后撤和距离带保持有确定测试。
3. 小队协调：新增只读快照、单主攻选择、稳定平局和有界邻居分离。退出条件：专用测试证明同一输入同一输出且输入顺序规则明确。
4. 世界与部署接线：显式敌人 spawn、三敌人正式 Raid、子步快照后统一指令再提交，保持命中/终局优先级。退出条件：多敌人不会同时新开攻击，不聚成同一点，死亡/失去目标时主攻可移交。
5. 占位表现与收口：感知/角色 debug、聚焦/全量测试、C++ 安全审查、真实窗口验收和一次精确 head CI。

## 自动测试矩阵

- 感知配置非法顺序、非有限值和非正时间拒绝；零/NaN/Inf 目标不会改变状态。
- `Unaware → Alerted → Searching → Unaware` 顺序、获取/丢失滞回、最后位置冻结、到达停止、记忆超时与重新发现均可重复。
- `Searching/Unaware/Support` 不请求攻击；支援禁攻不妨碍冷却、感知和移动更新。
- 180° 目标切换不能单帧瞬间反向；最大角变化受限；不同小帧切分的位置/方向在容差内一致。
- 支援者过近后撤、过远接近、距离带内稳定；主攻者仍能默认 Scratch 并满足条件后 Grab→Bite。
- 协调层在 0/1/3 名敌人、死亡成员、活动攻击、等距平局和非有限坐标下输出至多一个主攻；分离向量有限且有界。
- GameplayWorld 正式部署三名敌人；同一子步只允许一名新攻击者，支援者保持间距，主攻死亡/失去目标后可移交。
- 投射物命中多敌人、计分、攻击致死、终局冻结、新 Raid 重置、GameFlow 非 Raid 冻结均不回归。
- `ctest -N`、compile database 或构建日志证明新增源进入主程序与对应测试目标。

## 人工验收草案

1. 进入 Raid 后可看到三名敌人；三者独立移动、受击和死亡，HUD 能辨认存活/警觉数量。
2. 玩家进入获取距离后敌人从 `Unaware` 变为 `Alerted` 并开始追击；在获取半径边缘来回移动不会每帧闪烁切换。
3. 拉开到丢失距离外后敌人进入 `Searching`，只走向最后看到玩家的位置；玩家继续远离或横移时敌人不会全知修正路线。
4. 敌人到达最后已知位置或约 2 秒记忆耗尽后停止并回到 `Unaware`；重新靠近可再次警觉。
5. 玩家快速横穿或绕到敌人背后时，普通移动方向平滑转动，不瞬间 180° 翻转、不抖动、不出现 NaN。
6. 多名敌人追击时不会长时间完全叠在同一点；接近后可观察到主攻者贴近、支援者保持更外侧距离。
7. 同一时刻只有一名敌人启动 Scratch/Grab；其他敌人不会同时重叠扣血，但主攻者原有攻击仍可正常命中。
8. 当前主攻者死亡、失去目标或倒伏后，另一名合格敌人可接替；选择稳定，不在每帧来回抢占。
9. Week27 的首次 Scratch、条件 Grab→Bite、空冲 OffBalance、三级速度和双方受击顿挫不回归。
10. 世界四边附近的搜索、转向、支援后撤和分离不越界，不出现卡死、瞬移或无限循环。
11. 鼠标瞄准/射击、命中火花、柜体、背包、丢弃、撤离、死亡/超时结算与跨 Raid 流程不回归。
12. MainMenu、Base、RaidResult 中敌人感知和小队状态冻结；新 Raid 的三名敌人均从干净 `Unaware` 状态开始。
13. 全流程无 Microsoft Visual C++ Runtime Library / `gtest_ar_` 错误，debug 文本足以区分 awareness、角色、攻击阶段与移动档位。

人工项目在用户实际执行前均保持“未验证”。

## 风险、替代方案与失败语义

- 风险：把真实玩家位置持续传给搜索逻辑会形成伪装的全知 AI。搜索只能使用进入该状态时冻结的最后已知世界位置；远处玩家位置只用于“是否重新进入获取半径”的距离判定，不更新记忆。
- 风险：边遍历边用已更新 Enemy 位置计算邻居 steering 会产生顺序依赖。必须先生成全体值快照与全体指令，再提交移动。
- 风险：多敌人同时攻击让 3 HP 玩家不可读地瞬间死亡。小队协调只授予一个主攻许可，已开始动作不被抢占，新主攻只在没有活动威胁时选择。
- 风险：默认三敌人破坏单敌人回归。通过显式 spawn 构造器保留单敌人集成测试，同时新增正式部署与多敌人专用测试；不靠测试内修改 const vector。
- 风险：把角色、感知和攻击阶段复制进 App 会形成平行状态。App 只查询 Enemy/GameplayWorld 的值快照，不拥有计时或选择结果。
- 回滚：感知/协调、三敌人部署和 debug 作为一个 Week28 切片回退，不迁移物品、Stash、GameFlow、武器或持久化数据。
