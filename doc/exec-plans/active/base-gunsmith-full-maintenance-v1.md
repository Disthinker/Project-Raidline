# Base Growth：枪匠全面维护服务 v1 ExecPlan

状态：本地实现与自动化完成，等待 exact-head CI 与用户正常游玩验收

基线：`origin/main@defaac0`（PR #80 已由用户正常游玩验收并普通合入）

分支：`codex/base-gunsmith-maintenance-service-v1`

产品输入：外部只读 GDD `systems/09_基地经济与长期成长.md` 与 `systems/21_世界时间与日程.md`。GDD 已确认基地 NPC 全面维护是付费、需要等待的服务，完成后恢复原武器实例的当前耐久和当前最大耐久至出厂值；具体费用和时长属于开发期平衡值。

## 1. 玩家结果

玩家可在 Base 的供应与回收界面选择 Stash 中受损武器，查看一次冻结报价并委托枪匠全面维护。武器在服务期间离开可用库存，世界时间达到完成点后可以取回；取回时同一武器实例恢复到出厂最大耐久、清除当前故障，同时保留弹匣、枪膛、弹药和救济批次关系。服务让 Raid、Base 有效时间和往返旅行第一次共同推进一个可见的长期日程。

## 2. 权威状态与领域合同

- `ProfileState` 同时最多保存一项 `GunsmithMaintenanceJob`，使用单调 `BaseServiceJobId` 和高水位；武器由 `BaseServiceAssetLocation` 明确占有，不能同时出现在 Stash、装备、Raid 或另一服务中。
- 委托只接受 Stash 根层武器；服务不读取显示名，不接受装备中、容器中、待分配、Raid 地面或已经在服务中的资产。
- 查询冻结费用、开始时间、完成时间、目标出厂耐久和原 Stash 格位。开发期报价为基础劳动费加当前耐久缺口与最大耐久缺口，时长来自版本化内容定义。
- 提交在候选 Profile 中原子扣款、迁移武器所有权、创建任务、推进 revision 并保存。货币不足、任务槽占用、revision 过期、时间溢出或保存失败全部零修改。
- 到达完成时间只改变任务投影，不在任意渲染帧静默修改资产。领取时重新查找 Stash 合法空间，优先原格位，必要时使用首个合法格位；空间不足时武器继续由服务持有且不丢失。
- 领取恢复当前/最大耐久至委托时冻结的出厂值并清除故障，不改变武器实例 ID、已装弹匣、枪膛、弹药或方向。重复委托/领取使用事务 ID 幂等拒绝。

## 3. 内容、持久化与 UI

- content v15 新增 `base_services.gunsmith_full_maintenance`：基础费用、当前耐久每点费用、最大耐久每点费用和服务分钟数；加载拒绝零时长、零总费用能力或溢出风险参数。
- schema v10 保存服务任务、高水位、资产服务位置和冻结报价；v1～v9 显式迁移为空任务且 `nextBaseServiceJobId=1`。
- 供应与回收页继续使用文字和几何占位。选中可委托武器后显示费用/时长/修复目标；存在任务时显示武器、剩余时间或可领取状态。按钮是正常 NPC 服务入口，不替代库存拖放、弹药或维修包操作。
- 所有新增可见文本提供 English/简体中文；不新增资源、不修改音频或美术 manifest。

## 4. 明确排除

- NPC 身份、招募任务、商人等级、并行服务队列、设施建设、人口岗位、离线推进和主动睡眠。
- 防具全面维护、组件级维修、改枪台、配装预设、维修动画和正式服务场景资源。
- 自动把服务完成品覆盖到已占用 Stash 格位、生成到地面或复制成新实例。

## 5. 验证门槛

- 领域：报价、费用不足、非法位置、单任务槽、时间溢出、原子委托、未完成领取拒绝、原位/备用格位领取、空间阻塞、耐久/故障恢复、实例/弹药关系保持、事务重放与指纹不变。
- 存档：schema v10 往返、v1～v9 迁移、非法任务/位置/高水位、损坏主档与备份恢复。
- 会话：原子保存成功后交换内存；保存失败不扣款、不迁移武器；Base 时间和 Raid 往返时间都能使任务变为 Ready。
- 客户端：供应页选择、报价、开始、进行中、Ready、领取、空间阻塞和双语文本投影。
- 交付：focused tests、Windows Debug 全目标、全量 CTest、exact-head Windows/Ubuntu CI；开发代理不启动游戏。

## 6. 人工验收（自动化与 CI 后）

用户在正常游玩中磨损一把武器，在供应与回收页委托全面维护；确认货币扣除且武器暂时不可配装，经过 Base 时间或完成一次 Raid 往返后取回同一武器，确认当前/最大耐久恢复且弹匣与枪膛状态未被重置。再验证服务进行中不能提交第二把武器、Stash 无空间时完成品不会丢失。
