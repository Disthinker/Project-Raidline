# 边境交换站高危封路与重型搜运 v1

**已验收 · RL-FRONTIER-HIGH-RISK-BLOCKADE-AND-SALVAGE-v1**

在「边境交换站」用情报选撤离路线。进入高危后，一段原本能走的路可能被封。玩家可以带着重型物资绕行，也可以消耗一组破拆楔开近路。把物资带回基地才有收益，可用于下一趟整备。

## 玩家规则

| 环节 | 拟实施行为 |
| --- | --- |
| 出击前整备 | 从「对局出击」选「边境交换站」。用河畔带回的交通图，或按现价 **58** 购买，提前看撤离点和条件。「敌情档案」沿用现价 **66**，提前显示危机类别。两类情报可分别选择。给机修工具组留出 **2×2 格**，可带 **1 桶燃油**和现有「破拆楔组」。也可直接出击。 |
| 道路封闭 | 新开的边境交换站普通对局，随本局危机冻结最多一处封路段及一条可走的绕行线。常规阶段道路畅通。通过「高危控制装置」主动触发，或由倒计时进入高危，都会先警示 **5 秒**；区域内还有玩家或活敌时最多再等 **5 秒**，到期仍被占用则本局跳过封路。封路发现后才在本局 `M` 地图标记，交通图继续显示撤离信息。 |
| 高危搜运 | 有合格封路点时，原有两份高危掉落中的首份改为冻结的「机修工具组 ×1」〔**2×2 格、3.2 kg**〕，第二份保留原抽取结果。占位导致跳过封路时，掉落仍以开局结果为准。没有合格点位的种子沿用原危机和原掉落。 |
| 绕行或破拆 | 可放弃重货、带货绕行，或在已封路障 **72 世界单位**内长按 `F` **3 秒**。成功只消耗一组楔，通道在本局保持打开，敌人也可通过。松键、走远、受控或受击、切地图空间及其他动作抢占时取消这次破拆，保留楔组。开启时调用现有局内发声机制，采用策划建议的 **400 世界单位**半径。 |
| 撤离与回营 | 使用普通撤离宽限、信号撤离、燃油撤离或凭证撤离的现行规则。封路时始终保留一条不用油、楔组或凭证的信号撤离路径。选燃油路线时在成功结算扣 **1 桶**。携带工具组成功撤离后，可在既有入口折 **5 建材**、提交为 **16 点安全资源**，或移入仓库后在「供应与回收」回收 **55**。 |

玩家死亡或主动放弃时，工具组按普通随身战利品处理。异常退出恢复出击前存档。封路、破拆和发现只属于当前对局。历史存档和旧冻结局按原规则读取。

## 实施范围

本方案将边境交换站现有高危阶段扩展为一处实际可绕行、可破拆的道路封锁。已有危机的增援编队、波次和风险继续使用。沿用正式地图、物品、短提示、地图标记和读条。正式新美术、音频文件、新地图、新管理页面、额外撤离方式及新的基地配方均在本方案范围之外。

| 工作 | 核查过的入口与拟实施做法 |
| --- | --- |
| 冻结封路点和掉落 | `src/raid_lifecycle.cpp` 已冻结危机目标、增援锚点和高危掉落，`src/raid_map_generation.*` 有原始布局连通性检查。对边境交换站普通出击，拟在已冻结道路和邻近物资区挑选一处实际有绕路价值的横断面。用独立选择流和稳定顺序，在部署阶段检查开放、封闭两态，目标绕路增加 **320–960 世界单位**。保持原物品/数量抽取次数，仅覆盖目标掉落，原版地图、敌群和其他掉落可逐种子比对。 |
| 证明不会无路可撤 | 用角色实际占地和碰撞净空验证封路两侧、出生位、室内返回口、既有撤离点、高危控制装置及目标物资可通行。拒绝与必要交互区、增援候选和其他固定锚点冲突的封路点。绕行线不得依赖破拆或消耗品。验证不过的种子保持原危机与掉落。现有连通性接口只验证原图，实施时需要新增封路态的专项验证。 |
| 启闭与破拆 | `src/raid_session.*` 归一两种高危触发，`src/gameplay_world.*` 拥有世界几何和活动空间。在加载阶段准备变化所需的局部索引/导航数据，切换帧发布同一室外几何版本供玩家碰撞、弹道、视野和敌人寻路使用。室内发生相位切换时只更新对应室外状态，返回室外后沿用更新后的几何版本。参考既有货运破拆的距离、打断和原子消耗，避免在触发帧重建整张大地图。 |
| 提示、权限和既有收益 | `GameSession::raidHighRiskCrisisProjection` 已按敌情档案或高危阶段提供危机信息。`src/app.cpp`、`src/raid_tactical_map.*` 和 `src/ui_localization.cpp` 投影警示、近距离破拆进度和本局已发现的封路点。警示沿既有 HUD 安全区，文字和形状区分状态，避免遮挡瞄准。机修工具组沿用 `core.json` 的现有定义及 `base_construction_domain.cpp`、`base_resource_domain.cpp`、`economy_domain.cpp` 的消费者。 |
| 存档、回退 | 可选封路数据属于已冻结的危机快照，采用稳定 ID 和显式兼容。运行时警示、开启和发现状态随对局结束清理。通过现有撤离结算和异常退出恢复处理物资。内容基线 **87／格式 69**，覆盖旧快照及历史存档副本。确需新增序列化字段时按项目版本规则升级，保留原主档、备份和固定入口。候选回退使用上一版构建和同版存档副本。 |

## 验证和正常游玩验收

- 自动化覆盖固定种子、有封路及无合格点位、两态绕路距离与免费出口、5 秒警示及占位跳过、自然和主动触发、跨室内外、破拆中断和只扣一次、视野/弹道/导航一致、既有随机流、一次结算及旧档回读。专项测试拟新增，范围集中在可复用实现入口。
- 保留原 **14 项 3 ms** 性能用例和阈值，以及基地存档等其他现有性能检查。另测密集遮挡和增援下的封路、占位跳过、破拆切换帧。用三档窗口和中英文本核对短提示、读条及地图标记。
- 联合验收按正常入口走一趟有封路的边境交换站。先用 `M` 看撤离点，找到原本可通的路，再触发高危看它预警并封闭。绕路取机修工具组，返程选破拆开路，核对只扣一组。走信号或燃油路线撤离，回基地用任一既有入口消费工具组。
- 获批后从经核对的主线建立独立工作树，按一次完整交付执行，完成后给一个候选和联合验收清单。
