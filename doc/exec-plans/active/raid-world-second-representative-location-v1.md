# Raid World 第二个代表性地点 v1

## 目标

在 `Frontier Exchange` 增加第二个独立室内 `Freight Service Bay`。它采用比交换站办公室更狭长、分道更明显的占位空间，拥有独立的敌人、Loot、入口候选、发现状态和永久内部图情报。玩家可在同一局分别发现、进入、清理并离开两个地点。

本切片用第二个真实消费者证明 Raid 空间链路没有把“办公室”或“第一个室内”硬编码进内容、快照、存档、世界投影和 UI。表现继续使用双语文字与代码几何，不生成或接入新资源。

## 基线与依赖

- 基线：`origin/main@95fcd23`，PR #98 的空间战术可靠性已通过用户验收并普通合并。
- 分支：`codex/raid-world-second-representative-location-v1`。
- 继续使用 schema v23；content 升至 v33；新 Deploy 使用 `raid-second-representative-location-15`。
- rules v12～v14 的旧 pending Raid 只要求并验证首个兼容办公室快照，避免添加第二地点后破坏旧未结算存档的读取与失败回退。

## 产品与领域合同

- 地图内容可声明 0～4 个稳定 `RaidSpaceDefinitionId`；每个地点独立拥有显示名、内部图价格、固定内部空间、敌人、Loot 和 2～8 个室外候选 Socket。
- Deploy 按定义顺序、独立命名随机流选择合法 Socket，并把每个最终入口与返回点冻结进 Pending Raid。
- 入口矩形与返回点安全区都必须避开出生、撤离、敌人、Loot、救援、高危区和已选特殊地点；二者都成为程序化室外布局的受保护、可达锚点。
- 同 seed 和内容版本产生同一组地点位置；任一地点没有合法候选时 Deploy 原子拒绝，不删除地点、不重叠回退。
- 室外投影返回全部已发现入口，不再只返回第一个；每个入口使用自身稳定 ID、显示名、边界和交互状态。室内只投影当前空间的返回出口。
- 两个地点的发现和永久内部图知识相互独立，均按稳定 ID 保存；UI 不以显示名、数组序号或地图行号作为权威身份。

## 第二地点占位内容

- `raid_space.frontier_exchange.freight_service_bay` / `Freight Service Bay`。
- 1120×520 狭长装卸空间；上下货架形成平行通道，东侧货物与服务隔断形成侧翼路线。
- 3 名现有敌人、4 个现有 Loot 插槽、6 个与办公室候选互不重叠的室外 Socket。
- 永久内部图价格 220；没有新物品、敌人类型、任务、设施、正式美术或音频。

## 明确排除

- 第三个地点、程序化室内、门锁/钥匙、多楼层、跨空间视线/弹道/AI。
- 新地图、区域旅行扩张、任务内容、商人/NPC、正式资源与 manifest 修改。
- 本阶段集中稳定性门槛；多 seed 长跑、跨进程矩阵和性能/fallback 审计属于下一独立切片。

## 验收阻塞：多人围攻性能

用户在第二地点正常游玩验收通过时发现：数名敌人同时追击会持续严重掉帧。无窗口复现确认旧路径在 8 名敌人、18 个障碍、120 帧中耗时约 6357 ms；根因是每名敌人每个 1/120 秒子步都重建完整障碍可见图，慢帧又增加子步并放大主线程负担。

PR #99 保持 Draft，不先合并。修复采用三层有界合同：静态导航图按空间与角色尺寸预计算、动态路径目标 10 Hz 刷新且每子步最多一条昂贵查询、App 单帧输入最多 100 ms。回归使用更高的 8 敌人/26 障碍场景，要求 120 帧低于 1500 ms、任一 simulation 更新低于 100 ms、每 60 Hz 更新最多两条昂贵查询，并且所有敌人均获得导航机会。
