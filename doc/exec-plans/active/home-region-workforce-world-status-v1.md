# Home Region 聚合岗位世界占位反馈 v1 ExecPlan

状态：开发完成，等待 exact-head CI 与用户正常游玩验收。分支 `codex/home-region-workforce-world-status-v1` 从用户已验收并合入的 PR #138 / `origin/main@5da9591` 创建。

## 玩家结果与依赖

工坊与医疗所不再只有抽象的“已分配专业人员”文字。基地世界会在对应工作台或医疗床旁显示一个聚合岗位占位，明确区分缺员、闲置、工作中和暂停，使玩家不打开管理页也能理解当前岗位状态。

本切片依赖 PR #138 的稳定设施作业点，以及既有 `BaseWorkforceProjection`、制造、居民治疗和设施升级事实。它只把现有聚合岗位投影到世界，不新增居民实例、排班、寻路、动画、房间或持久化字段。

## 领域与表现合同

- `BaseFacilityWorkerWorldProjection` 只对当前确有聚合岗位消费者的 Workshop 与 Medical 返回结果；其他设施不伪造工作人员。
- 状态优先级固定为：未分配专业人员为 `Missing`；设施未安装或处于储备为 `Paused`；建设、制造或居民治疗进行中为 `Working`；其余为 `Idle`。制造产物待领取表示作业已结束，因此岗位为 `Idle`，作业点本身仍由既有服务投影显示 `OutputReady`。
- 投影包含设施、稳定作业点职责、状态、可选专业、当前任务和剩余分钟；查询必须不修改 Profile、revision、资产、高水位或世界时间。
- App 只消费投影，在作业点绘制简单人形/空缺轮廓及中英文短标签；颜色和图形同时表达状态，不依赖颜色单独传达含义。
- 岗位占位没有碰撞、资产所有权或交互命令；既有入口、管理面板、分配/清除岗位命令和任务时间保持不变。

## 实施顺序与验证

1. 在设施管理领域增加类型化岗位世界状态和纯查询，覆盖状态优先级、专业、任务与剩余时间。
2. App 在 WorkshopBench 与 MedicalBed 作业点绘制聚合岗位占位和双语状态，不在客户端猜测 staffing 或 task。
3. 增加领域纯度、缺员、闲置、工作、暂停和产物待取回归，以及中英文文本门禁。
4. 重建受影响目标，运行定向回归、Windows Debug 全目标和完整 CTest；提交后核验 exact-head Windows/Ubuntu CI。
5. 交由用户正常游玩验收；Codex 不启动游戏。

人工验收：观察工坊和医疗所作业点的岗位占位；清除/自动分配岗位后确认缺员与闲置变化；开始制造、居民治疗或对应设施升级后确认显示工作中及剩余时间；将设施收入储备时确认显示暂停；制造完成后确认工作台保持待领取提示、岗位回到闲置。移动设施、迁徙和重启后状态仍与管理页一致。

## 风险、回滚与明确排除

主要风险是世界标签过密，因此只为两个真实岗位消费者绘制紧凑占位，并复用作业点位置。领域查询和 App 表现均为派生状态，回滚采用普通 revert，不需要 schema/content 迁移。

本切片不实现具名 NPC、逐人居民实体、NPC 死亡或库存、行为树、寻路、工作动画、排班、工资、独立室内、设施旋转、正式美术/音频、实时守城或 AI 小队；不修改 Manifest。
