# Frontier Exchange 超大主题分区随机地图 v3

## 产品结果与唯一范围

本宏切片把 `Frontier Exchange` 从 2560×1440 的道路样例升级为第一张 25600×14400、可承载完整 Raid 的单一无缝室外地图。地图使用 320×180 个 80 世界单位基础格，并按 16×16 格组织为 20×12 个运行时区块。每局固定包含八个连续主题大区，但其形状、相邻关系和位置随 seed 改变：两个工业厂区、两个物流堆场，以及公路换装区、施工空地、排水绿地/公园、公路服务区各一个。

范围来源为 GDD 的“首张可玩随机大地图”阶段裁决和用户 2026-08-28 批准的 v3 返工计划。PR #110 已以 `7bd3b02` 进入 main；本切片继续使用 `codex/procedural-raid-layout-v1` 和 Draft PR #111，原 2560×1440 验收范围作废。

本切片只使用中英文文字、SDL 几何与色块占位，不绘制旧整图背景，不生成或接入新美术，也不修改美术 Manifest。常规阶段为 20 分钟，归零后进入持续高危，不直接导致 Raid 失败。

## 状态所有权与领域合同

`RaidGeneratedMapLayout` 是 Pending Raid 中的唯一布局事实，并冻结：

- `RaidDistrictSnapshot`：八个连续分区及稳定身份、类型、标签位置和压缩格段；
- `RaidLandmarkPlacementSnapshot`：货运换装中心、制造厂区、公路服务中心三个固定内部模板及随机合法位置；
- `RaidTerrainSpan`：草地、水泥、土地、沥青和仅表现用水洼；
- `RaidOutdoorPropSnapshot`：建筑、车辆、集装箱、设备、路障与非碰撞环境占位；
- `RaidAnchorPlacementSnapshot`：出生、撤离、高危、救援、Loot、敌人、室内入口等玩法锚点；
- 主路、次路、接入路、生成尝试、回退原因和完整布局哈希。

随机流按 `districts / landmarks / roads / terrain / props / anchors` 隔离。道路宽度为主路 4 格、次路 3 格、通路 2 格；先形成连通骨架和至少两个环路，再连接地标 Socket 与全部玩法锚点。生成预算耗尽时使用同一份已验证 layout v3 固定安全骨架，不回退旧背景或 layout v2。

GameplayWorld、碰撞、导航、战术地图和 SDL client 只消费冻结快照。`RaidOutdoorPresentationProjection` 通过 16×16 区块索引仅返回摄像机及一圈缓冲范围；地表、道路、建筑和标签不逐帧遍历全图。权威布局始终完整保存在 Raid 快照中。

导航用静态障碍索引构建稠密可行走格；最近可行走点使用局部环形搜索，远距离路径先经过区块门户图，近距离再进入局部 A*。战术地图使用 80×45 揭图格，只更新玩家附近格并消费预压缩道路、分区与地标投影。

## 内容密度与固定地标

- 18～28 个大型厂房或仓库轮廓；
- 700～1100 个可碰撞建筑、车辆、集装箱或大型设备；
- 1200～1800 个非碰撞小型设备、碎屑和环境占位；
- 140～220 个道路车辆、路障或事故点；
- 60～100 个水洼区域。

三个固定内部结构地标分别为货运换装中心、制造厂区和公路服务中心。货运换装中心绑定现有 Exchange Office 与 Freight Service Bay 固定室内；所有地标通过道路 Socket 接入外部程序路网。

## 自动化与人工验收

自动化覆盖至少 128 个固定 seed：八个分区数量与连续性、地标合法分区和道路连接、全部关键锚点可达、空间不非法重叠、同 seed 跨实例哈希一致以及坏种子固定回退。保存测试覆盖 v3 往返、schema v34 快照兼容、非法引用和布局哈希篡改；序列化布局不得超过 4 MiB。

性能回归覆盖约 1000 个静态阻挡和 100 名敌人，Windows Debug 最慢子步保持低于 25 ms；单局生成和验证低于 5 秒；可见静态投影最多查询摄像机附近 12 个区块，成本不随整图面积线性增长。

首轮正常游玩暴露三个验收缺陷并已纳入同一 PR：平均帧率高但主线程存在可见顿挫、环境方块缺少身份、随机分区缺少可读规律。修复合同为：同一可见区块范围复用一份预分配表现投影，世界细节每帧只绘制一次；所有可见 Prop 显示双语类型标签；八区改用 4×2 受控宏观模板、有限边界偏移与镜像变化，工业/物流相邻，主次路沿分区骨架形成环路，大型厂房和仓库按 compound 网格成组放置；80×45 战术地图按已探索分区类型着色。随机差异仍保留在模板朝向、地标、局部支路、玩法锚点和环境细节，不退化为固定地图。

第二轮正常游玩确认移动仍存在规律性顿挫，因此客户端提交节奏继续在本 PR 收束：渲染器优先请求并读取 VSync 实际状态；不支持时按当前显示刷新率（不可用则 60 Hz）使用绝对截止时间和 `SDL_DelayPrecise`，错过截止时间后从当前时刻重新排期，不追赶历史帧。本轮不迁移固定 60 Hz simulation，也不修改移动、碰撞或最大 100 ms 输入时间限制。F9 同时显示 `VSYNC / SOFTWARE FALLBACK`、目标刷新率和 Event/Update/Render-Present/Pacing/Total 的平均、P95 与最大值。

F10 已扩展为通用运行时开发面板，`F` 可在 `FogOfWar / FullStaticMap` 间切换。完整静态地图只覆盖地表、分区、道路、静态建筑/障碍、地标、三类撤离、高危控制、高级资源区和固定室内入口；它不显示实时敌人、不授予敌情、不改写揭图格、Raid 快照或存档。每次成功部署新 Raid 都恢复为启用迷雾。

人工验收只通过正常游玩完成：至少三个 seed 中跨越多个分区、进入固定室内、战斗、搜刮并使用普通或特殊撤离，观察路线、地标和环境差异。没有调试按钮或单步验收页。

## 风险与回滚

- 大世界逐帧扫描：由区块化投影、空间索引、门户图和远处低频更新阻断。
- 随机布局产生坏种子：所有必要锚点在冻结前统一验证，失败使用固定合法 v3 骨架。
- 内容集中或语义混乱：分区先于填充生成，地标和玩法锚点按分区类型与道路 Socket 约束。
- 旧档漂移：schema v34/layout v2 只读取原快照，不用 v3 重新生成。
- 表现资产阻塞：代码几何与文字是可运行基线，美术以后只能替换投影，不能改变布局真值。

回滚按客户端投影、导航/服务、存档、生成器/内容、文档的逆序普通 revert；禁止重写历史、强推或删除分支。
