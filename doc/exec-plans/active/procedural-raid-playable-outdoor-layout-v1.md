# 程序化 Raid：可玩室外布局 v1

## 产品结果与唯一范围

本宏切片把 `Frontier Exchange` 从 1280×720 的随机掩体技术样例升级为第一张 2560×1440、可滚动视口、具备可读道路和街区的程序化室外 Raid。不同 seed 必须产生明显不同的主干路、支路、街区阻挡和绕行关系，同时仍能从任意已发布出生点到达本局撤离、特殊地点及全部必要玩法锚点。

范围来源为 GDD `systems/08_地图与局内结构.md` 及策划线程 2026-08-28 的“首张可玩随机大地图”阶段裁决。PR #110 已由用户正常游玩验收并以普通 merge commit `7bd3b02` 进入 main；本切片从该接受基线开始。

本切片使用中英文文字和代码几何作为权威占位，不再把旧 1280×720 背景图片绘制到 `Frontier Exchange`。开发主控可以只读盘点美术主控已经生成的测试资源，但不等待资源、不生成新资源、不写 `art/work`、不发布 runtime 图片，也不修改美术 manifest。

## 明确排除

- 资源点生态、Loot 风险收益重排和地点专属 Loot；这些属于 Macro 2。
- 巡逻、守点、伏击和新的部署生态；这些属于 Macro 3。
- 高危、情报、救援、寻回和外围清剿的随机合法区重排；这些属于 Macro 4。现有消费者在本切片只需继续可达、可运行和可结算。
- 程序化室内、多层建筑、第二地图主题、正式 Prefab 编辑器、实时守城、AI 小队及正式美术生产。

## 基线、分支与交付边界

- 分支：`codex/procedural-raid-layout-v1`。
- 基线：`origin/main@7bd3b02`。
- 预计内容/存档增量：content v43、schema v34、Raid rules v21；若基线在实现前变化，则从当时接受版本顺延，不能复用已有编号。
- 一个 PR 同时交付领域生成、冻结快照、迁移、摄像机、代码几何表现和回归，因为它们共同构成一个可正常游玩的玩家结果。
- Codex 不启动游戏；自动化和 exact-head CI 完成后交给用户正常游玩验收。

## 现状差距

### 可复用

- `MapDefinition::proceduralOutdoor`、稳定 PCG32、`generateRaidMapLayout()`、Pending Raid 的 `spatialLayout`、布局哈希和确定性回退。
- 既有碰撞、弹道、LOS、静态空间索引、导航场、公平寻路轮转、战术地图和 F9 性能投影。
- 室外根空间与两个固定室内实例、入口/返回 Socket 及冻结特殊地点位置。

### 必须重构

- 旧生成器只随机选择互不关联的矩形格，不能表达道路、街区或可学习路线。
- 旧连通检查只验证粗格可达；新布局必须以角色占用尺寸保留道路宽度，并验证全部必要锚点。
- `Frontier Exchange` 与窗口同大，没有摄像机；扩大世界后必须分离世界坐标和屏幕坐标。
- 程序化地图仍绘制旧背景纹理；本切片改为从冻结布局绘制地面、主路、支路和街区占位。

### 新建

- 版本化道路生成参数、冻结道路格/类别、布局版本和明确回退原因。
- 2560×1440 世界内容坐标及适用于该主题的出生、撤离、特殊地点和临时部署锚点。
- 纯表现摄像机投影：跟随玩家、约束在当前空间边界、屏幕抖动只叠加到世界视口，UI 与准星保持稳定屏幕坐标。
- 多 seed 结构差异、坏种子回退、跨进程布局往返和大空间运行回归。

### 停止扩展

- 不再向旧“随机散落 18～26 个矩形掩体”模型增加新消费者。
- 不允许 App 根据 seed 重建道路，不允许碰撞、战术地图和表现分别生成不同地图。
- 不把背景图片、纹理像素或文字标签作为碰撞、道路或可达性事实。

## 状态所有权与领域合同

`ProceduralOutdoorDefinition` 保存生成版本、网格、主路/支路数量、建筑阻挡数量、最大尝试次数和锚点净空。所有参数均由内容加载验证。

`RaidGeneratedMapLayout` 冻结：

- 布局版本；
- 主路、支路和锚点连接道路格；
- 最终建筑/街区阻挡矩形；
- 尝试次数、布局哈希及回退原因。

生成使用独立命名随机流。道路先形成至少一条横向和一条纵向主干，再生成有限支路，并把玩家出生、撤离及所有必要锚点连接到道路骨架。建筑只放置在非道路、非保留格中。验证失败进入下一尝试；预算耗尽后使用同一输入生成的确定性安全回退，不在运行时无限重抽。

Pending Raid 是布局唯一事实。GameplayWorld、碰撞、导航、战术地图和 SDL 客户端只消费该快照。schema v34 保存最终选择，不保存 PRNG 状态；旧 schema v33 布局按旧规则读取，不伪造道路数据。

摄像机只属于 SDL 客户端投影，不进入 Profile、GameplayWorld、存档或命中计算。世界输入与射击继续使用世界坐标；所有 HUD、背包、暂停菜单和战术地图保持屏幕坐标。

## 实施步骤与退出条件

1. 扩展内容定义和布局数据，升级 `Frontier Exchange` 世界尺寸与锚点；内容错误、重复道路格和不合法范围必须拒绝。
2. 重写生成器为道路骨架→锚点连接→街区阻挡→整图验证→确定性回退；多 seed 和坏种子测试通过。
3. 将新布局冻结到 Pending Raid，完成 schema v34 往返、v33 兼容、哈希与 Profile 不变量校验。
4. 增加纯表现摄像机与代码几何地面/道路/街区渲染，停止为该地图绘制旧背景；战术地图投影同一冻结道路。
5. 完成 Windows Debug、完整 CTest、提交、推送、Draft PR 与 exact-head Windows/Ubuntu CI。

## 自动化与人工验收

自动化覆盖：

- 同 seed 逐字段相同、不同 seed 具有道路和阻挡差异。
- 主路/支路连通、道路格唯一、建筑不占道路/保留区。
- 所有出生/撤离组合、特殊地点入口、救援、高危控制/资源区及既有 Loot/敌人锚点可达。
- 代表性种子批次无非法布局；强制失败使用确定性回退且仍可达。
- schema v34 往返、v33 兼容、损坏道路/哈希/版本拒绝。
- 摄像机在中心、四边、室内和小于视口空间的钳制；世界到屏幕投影稳定。
- 大空间碰撞、导航、射击、撤离和跨进程恢复回归。

人工验收只通过正常游玩完成：连续进入 `Frontier Exchange` 多次，观察不同道路和街区路线；验证视口跟随、准星、射击、碰撞、两个室内、战术地图、普通撤离和高危仍正常。没有调试按钮或单步验收页。

## 风险与控制

- 摄像机引入坐标错位：统一使用纯投影函数并保持领域世界坐标不变，准星单独减去摄像机偏移。
- 道路可达但角色被建筑角卡住：道路宽度按角色尺寸留余量，并继续使用真实空间碰撞回归。
- 大地图让既有内容集中一角：本切片迁移所有必要室外锚点到全尺寸坐标；资源和遭遇的真正随机化留给后续宏切片。
- 障碍数量增加导致寻路成本上升：复用现有静态索引、导航预算和 F9 指标，对多 seed 记录确定性工作量。
- 测试美术切片规则尚不稳定：代码几何永远是可运行回退，美术资源只能替换表现，不能改变布局身份或碰撞。

## 回滚

按摄像机/客户端、存档/服务、生成器/内容、文档的逆序普通 revert。schema v34 只扩展 Pending Raid 布局，不移动玩家资产；旧程序不得静默加载新布局。禁止重写历史、强推或删除分支。
