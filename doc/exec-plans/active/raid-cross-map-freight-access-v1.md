# 跨图后勤钥匙与封存补给 v1

**已验收，正在交付 · RL-RAID-CROSS-MAP-FREIGHT-ACCESS-v1**

在「河畔检查站」找到钥匙并带回基地。下一趟带钥匙去「边境交换站」，打开「货运装卸间」里的封存器材箱，把精密组件带回工坊。四个环节一起开发，交付一个候选。

## 玩家流程

| 环节 | 拟定规则 |
| --- | --- |
| 河畔搜获 | 每个新开普通对局固定一把「货运器材箱钥匙」。沿地图中央线路找原有物资位。钥匙占 1×1 格，拟重 50 克，单把存放。沿用正常拾取和撤离，供应及回收列表均无这件物品。 |
| 带回再出击 | 钥匙是可存放的普通物品。第二趟出击要装进随身容器，仓库里的钥匙无法开箱。开箱后钥匙可再次使用。死亡、主动退出和寻回沿用原规则。检视标明目标为「边境交换站 · 货运装卸间」，入口位置仍遵循已有探索和地图情报。 |
| 开封存箱 | 进入装卸间，靠近并看见封存箱后按住 **F 2 秒**。沿用 E/F 的交互映射及 72 世界单位的箱体距离。开锁开始与完成时都核对钥匙、距离及视线。松键、离开范围、换目标或受控中断会清零。成功即打开现有容器界面，本局再开可短按。 |
| 带回材料 | 封存箱内固定一件「精密组件」。取出后再次打开，原位置保持已取空的状态。正常撤离后可在「工坊与生产」用一件精密组件生产现有批次，120 游戏分钟后领取 18 发 5.45×39 扩张弹。 |

## 两处掉落的取舍

- **河畔检查站。** 生成器原本必选中央、外围、资源线路各一个点，再补到 6–9 个。取已选中央位中槽序最靠前的一个，保留原先两次随机抽样，然后把该结果替换为钥匙。它可能在三个中央位置中的任一处。被替换的一抽原本可能出水、医疗包、弹药、弹匣、卡宾枪或防具，按定义回收价计算的平均毛值约 21。
- **货运装卸间。** 保留前两次掉落所在的开放箱和第三处散落物。第四位原先是地面的普通随机掉落，平均回收毛值约 20。改为封存箱后固定产出一件精密组件，现有回收价 80，重量 1.2 公斤。两处都维持原奖励槽数和其余随机结果。
- **可重复收益。** 带钥匙的玩家每次新普通出击可取得这一个固定材料，需进入装卸间并成功把物资带回。钥匙可重复使用并承担随身失物风险。这两项是本版本待确认的经济规则。平均毛值按原表权重、数量均值和定义回收价计算。

## 实施与验证

1. **冻结内容和位置。** 在 `core.json` 增加钥匙定义。沿 `raid_lifecycle.cpp` 的原随机流替换两个指定槽的结果。将精密组件放入新场景箱的真实分区，钥匙和材料继续使用唯一资产实例。两处投放仅适用于新开普通对局，既有区域任务沿用原结果。内容 77 的旧掉落、夜视和瞄具合同继续适用。
2. **让开锁和库存共用权限。** 现有容器靠距离和同一份遮挡观测决定访问资格。新增箱的开锁进度归本局会话，锁状态绑定该箱实例。原入口、搜尸、散落物及普通箱保持现有优先关系。锁定时共用领域检查拦截内部投影、拖放和快捷转移。完成后复用原库存界面。既有受控、切换页面、建筑边界和瞄镜限制继续生效。箱体沿用现有资源和程序标记。
3. **保全存档与正常结算。** 冻结记录增加可选钥匙槽和封存箱身份及解锁状态，拟以内容 78／schema 62 写入。扩展既有内容兼容判定，保留 schema 61 与旧冻局的原物资、箱数量和访问规则。旧夜视投放与保存合同须有回归。正常撤离仅带回已拾取资产，失物与异常退出仍走原政策。用隔离副本验证升级和回读，保留原主档、备档和上一个候选，必要时由兼容读档版本回退。
4. **验证后交付一个候选。** 同种子对照三出生方向及三个中央槽，核对其他掉落、箱内容和高危规则。覆盖无钥匙、钥匙在仓库、隔墙、松手、重复开箱、物品转移、异常回滚和旧档。保留原 12 项及新增双设备 3ms 检查的负载和门槛，另测封存箱加入后的观察与转移路径。通过全量回归后继续用桌面 **Project Raidline Debug** 联合验收。

## 一次联合验收

1. 河畔检查站沿中央线路找到钥匙，正常撤离，回基地确认它在库存里。
2. 把钥匙带到边境交换站的货运装卸间。先验证原开放箱可搜，再按住 **F** 开封存箱。中途松手一次，确认重新按住会从零开始。
3. 开锁后拿走精密组件，重开确认箱内保持已取空，钥匙仍在随身容器。撤离后用组件启动「5.45×39扩张弹批次」。
4. 正常关闭并重开，核对钥匙和工坊订单。
