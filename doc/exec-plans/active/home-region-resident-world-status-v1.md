# Home Region 聚合居民空间状态 v1 ExecPlan

状态：本地实现与回归完成，待提交、exact-head Windows/Ubuntu CI 和用户正常游玩验收。分支 `codex/home-region-resident-world-status-v1` 从用户已验收并合入的 PR #140 / `origin/main@0f74a67` 创建。

## 玩家结果与依赖

宿舍床位不再只是一个无语义矩形。基地建设视图会在该稳定作业点显示聚合居民、健康/受伤、床位占用以及可用、已分配和建设占用人数；玩家左键床位可直接选中宿舍并在检查器读取同一组事实，右键可打开宿舍功能页或执行现有自动补员。

本切片依赖 PR #138 的 `DormitoryBunk` 稳定作业点和既有 `BasePopulationProjection`、`BaseWorkforceProjection`、设施管理查询。它只把已经持久化的聚合人口事实投影到 Home Region，不新增居民实例或状态所有权。

## 领域与交互合同

- 新增只读聚合居民世界投影，明确居民总数、健康、受伤、床位、床位缺口、可用、已分配和建设占用人数；最后一项由健康人数减去已分配与可用人数得到，并进行安全截断。
- 世界状态优先级为 `Empty → Overcrowded → Injured → Stable`；它只影响占位颜色和说明，不改变人口、治疗、口粮或士气规则。
- 投影只为 Dormitory 发布并绑定 `DormitoryBunk`；设施处于 Reserve 或未出现在世界时，App 不绘制也不产生幽灵命中区。
- 左键床位使用统一屏幕到世界投影选中 Dormitory；检查器显示聚合人口与劳动力事实。右键床位只公开既有 `OpenFunction` 和 `AutoFillWorkers` 动作，合法性与失败原因来自设施管理/劳动力查询。
- 成功自动补员继续通过 GameSession 原子保存命令提交；拒绝和保存失败保持 Profile、revision、人口、岗位与世界时间不变。
- 不增加 schema/content 版本，不建立具名 NPC、逐人位置、日程、寻路、动画、工资、精力或居民资产所有权。

## 实施顺序与验证

1. 建立 SDL-free 聚合居民世界投影及状态优先级，覆盖正常、受伤、拥挤、空人口、建设占用与查询零修改。
2. 在宿舍床位绘制明确的聚合人物图形和双行状态文本；设施检查器消费同一投影。
3. 增加床位命中、左键选择和右键 Open/AutoFill 菜单；普通设施和 Workshop/Medical 岗位菜单保持原语义。
4. 重建受影响目标，运行设施管理、人口、劳动力、建设镜头、BaseWorld、双语、GameFlow 与持久化定向回归；完成 Windows Debug 全目标、完整 CTest 和 exact-head Windows/Ubuntu CI。
5. 交由用户正常游玩验收；Codex 不启动游戏。

本地证据（2026-09-02）：Windows Debug 全目标构建通过；设施管理、人口、劳动力、建设镜头、BaseWorld、双语、GameFlow 与持久化定向回归 `158/158` 通过；完整 CTest `1424/1424` 通过。首次脱离 Developer Shell 的全目标链接因当前终端找不到 Windows `rc` 失败，按工具链规则导入 Visual Studio Developer Shell 后原构建目录完整通过，未清理或隐藏失败。

人工验收：按 `B` 打开建设视图，在不同缩放和平移位置观察宿舍床位的居民、健康/受伤、床位和人员占用信息；左键床位确认宿舍检查器显示一致事实；右键打开宿舍或自动补员，确认岗位数据刷新；宿舍处于 Reserve 时不应显示床位居民占位或响应点击；工坊/医疗岗位和普通建筑右键操作不得回归。

## 风险、回滚与明确排除

主要风险是聚合人数分类口径不一致以及床位与建筑命中重叠。实现只组合既有权威投影并用安全差值表示建设占用，App 不重新统计 Profile；床位命中优先于建筑本体，菜单按类型化动作过滤。改动只涉及查询和客户端表现，普通 revert 即可回滚，不需要存档迁移。

本切片不实现逐个居民 Sprite、具名角色、住宅分配、值班表、居民移动、疾病种类、诊所排队、情绪个体化、战斗小组、正式美术/音频或 Manifest 修改。
