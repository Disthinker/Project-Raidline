# 夜间接应与工坊带教 v1

**已验收 · RL-RAID-NIGHT-RENDEZVOUS-AND-ENGINEERING-TRAINING-v1**

让路线选择影响一次实际行动。玩家在基地看能否赶上灰烬工场的夜间接应，出击后选清场或冒险发信号。救回工程居民后，可以维持工坊生产，也可以暂时腾出工坊培养第二名工程居民。整个阶段交付一个候选，集中验收。

## 玩家会遇到什么

| 环节 | 拟定规则 |
| --- | --- |
| 出击前 | 新档首次从普通对局成功撤离后解锁。自第 3 日起每隔 4 日，按预计抵达的游戏日期和时间判断。接应窗口为 **18:00 至 22:00**，18:00 可参加，22:00 已错过。以「灰线场站」第 3 日 20:00 出发为例，直达 150 分钟，22:30 抵达。此例启用驻满两人的「老旧服务中继站」，其他捷径保持关闭，路程缩至 95 分钟，21:35 抵达。也可以沿直达路线提早出门。路线仍由现有规则选择，哨所照常消耗可用次数。错过可等下一轮，普通出击照常开放。 |
| 灰烬工场 | 接应点沿用地图掩体，独立于现有伤员救援点。可以先清附近敌人，再按 **F** 发信号，也可以马上启动并掩护 **12 秒**。建议警戒圈半径 **96** 世界单位，信号响一次，沿用同空间声响调查，建议半径 **400** 世界单位。掩护时可在圈内移动、开火。活敌进入圈内、玩家受控或打开阻断交互的界面时计时暂停，玩家离圈时清空当次进度。留在局内重试时无需再次发声。接应资格在出击时确定，局中沿用原撤离时钟。 |
| 安全转移 | 进度完成并保存成功后，**1 名健康工程居民**立即加入聚合人口，显示新增的床位和口粮需求。每档只接应成功一次。保存失败保留可重试的结果。玩家在接应办妥前撤离、死亡或放弃时，本局没有接应收益。成功转移后，居民在随后的死亡、主动退出或异常退出中也保留。携带物品仍按原撤离与失物规则结算。既有灰烬工场伤员和医院救援继续各自结算。 |
| 工坊带教 | 已安装的工坊可以开一单工程带教。由现有工坊岗位上的 **1 名健康工程居民**担任师傅，另占用 **1 名空闲健康通用居民**。从仓库预留 **废旧零件 ×2、铜线卷 ×1**，用 **12 游戏小时**完成。带教占用同一个生产位置，因此须先结束已有制造、研究并领取已完工产出。带教期间也暂不能提交这些订单。旧档已有合格工程居民即可开单。完成时消耗原料，把通用学员转为工程居民，释放人手，总人口、床位和口粮不变。 |
| 暂停与取消 | 工坊收起或迁徙时冻结剩余时长，重装后续作。培训保留人员占用。若师傅因既有事件无法工作，任务暂停，补上合格工程师后续作。取消退回所预留的材料，已用时间照旧计入世界时钟。仓库满时拒绝取消，清出空间即可重试。工坊等级、士气及燃油维持各自现有效果，带教用固定时长。 |

出击界面用现有「抵达」一栏表明能否赶上及下次开放日。接应点沿用场景提示和一条进度条，遇敌显示暂停原因。工坊沿用订单区域的列线，对齐材料、时长和操作按钮。窄窗优先收起附加说明，状态、确认和失败原因可读。使用现有图形、音效和 SDL 组件，范围为灰烬工场这一次接应、一级工程带教及必要提示。接应通过固定点掩护完成，居民继续采用现有聚合模型。

## 实施安排

1. **共享抵达时间。** 在 `raid_lifecycle.cpp` 复用 `queryRaidTravel` 和 `world_clock`，让 `ui_base_deployment_presentation.cpp` 与实际 Deploy 使用同一判断。首次成功标记只从普通局成功结算写入。旧档未保留完整的成功历史，迁移时将已有已提交对局结算的玩家视作已解锁，避免要求他们重打一局。其余旧档在首次成功普通撤离后解锁。新接应只进合法的新开普通灰烬工场对局，排除失物寻回、清场等特殊活动。
2. **冻结独立接应点。** 在 `assets/content/v1/core.json` 增加独立救援 ID。在 `raid_map_generation` 沿用避让、阻挡和通路检查，以独立的选位输入保持已有出生、撤离、掉落和伤员位置。覆盖合法掩体、接应点及离开的通路。若布局无法找到合法点，本局照常进入，并说明接应未开放。旧冻结对局按原快照恢复。HUD 和 M 地图沿用观察与发现权限。
3. **接入掩护及救援提交。** 在 `gameplay_world` 保存本局进度、首个信号及威胁状态。复用清障声响的本地调查入口，响应对象遵守现有敌人感知与战斗规则。独立接应与普通救援分别判定，重用 `raid_rescue_domain` 和 `GameSession` 的活动候选与出击前恢复候选。由已发布定义校验专业、健康状态与人数。保存失败不增加人口，成功才标记完成。结算按各自稳定 ID 汇总，允许同局完成两个合法救援。
4. **接入工坊订单、劳动力与世界时间。** 拟新增 `src/base_engineering_training_domain.h` 和 `src/base_engineering_training_domain.cpp`，复用 `BaseServiceAssetLocation` 及现有带原子保存的订单入口。用已有工坊岗位校验合格师傅，学员占用计入 `base_workforce_domain` 和 Profile 校验。治疗排班、驻哨、建设、攻城及自动填岗都按同一可用人数判定。与制造、蓝图研究互斥，枪匠独立服务维持现行规则。经 `synchronizeBaseWorkThrough` 结算世界时间，沿用工坊储备和迁徙的时间平移。对局中不物化培训结果，在原有结算推进的归队时间点处理，异常退出恢复原检查点。
5. **持久化与可回退。** 从格式 **72**、内容 **90** 拟升级到 **73／91**。旧档培训默认为空，保留已有职工、伤势、制造订单、物品和救援记录。保存校验包含接应冻结事实、已提交凭据、培训岗位与材料的唯一归属。开始、完成和取消都作为一次事务，重复调用只生效一次。以旧主备档副本做迁移验证。候选验证通过后才更新固定测试入口，保留当前可运行程序以及与程序匹配的存档副本作为回退。

## 一次联合验收

1. 用 **Project Raidline Debug** 的隔离验收档，在「灰线场站」第 3 日 20:00 核对直达预览。为「老旧服务中继站」驻满两人，再看抵达从 22:30 提前到 21:35，接应由错过变为可参加。
2. 从「灰烬工场」正常入口出击，到接应点按 **F**。确认敌人进圈时进度暂停，压住威胁后继续。完成安全转移，再走任一正常可用的撤离路线。回营核对新增一名健康工程居民。
3. 把工坊岗位设为工程并开始带教，核对材料、学员和生产位置占用。通过现有「宿舍与休息」推进时间并重开，确认增加一名工程居民、通用居民少一名，总人口一致。核对可分派的工程人数，再在工坊下单。
4. 隔离档复验一次收起工坊后时间暂停，重装后续作。取消分支核对原料退回，已用时间保留。

自动化覆盖时间窗口边界、直达和不同驻点路线、首次普通成功和旧档解锁、同图双救援、多种子通路、无额外刷怪、死亡/放弃/异常退出、满人口及保存失败。工坊覆盖人员互斥、满仓撤销、迁徙暂停、跨日完成、旧队列和重复执行。保留主线 **3358 项**基线和全部 **14 项 3 ms** 及其他现有性能门槛，原负载照旧。出击、掩护状态和工坊控件检查中英文及三档窗口大小。
