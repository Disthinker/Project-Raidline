## 三项服务的操作

### 购买：先看清，再执行

**由原来的“点商品立即买”，改为“选商品 → 看总价 → 点购买”。** 这是本版明确的取舍：多一次点击，减少误购。

- 弹药仍每次30发，其他商品仍每次1件；商品、单价、扣款和自动入库规则保持。
- 成功后更新余额并保留当前商品选择，下一次购买仍需再次明确点击，不因按住、滚轮或动画重复交易。
- 浏览、悬停、选中或切标签均不生成资产、扣款或保存。右侧展示批量、总价和“存入仓库”；不承诺落在当前浏览页。

### 回收：看清整个实例的数量和总价

- 浏览当前服务原有的**仓库直属实例**，去掉绘制／点击前12项限制。不同型号、同型号不同实例或不同堆叠都分别显示，不把耐久、数量和救济标记混成一项。
- 保留现有来源顺序，包括近战物品优先的相对顺序。不加入身上装备、背包／胸挂内部、失物或已安装组件作为独立来源。
- 明确提示本次处理**整个选中实例或整个堆叠**；已安装组件的价值及处理范围沿用现有命令，不只报裸枪价。
- 成功只处理一次，清除已不存在的选择并修正页码；失败保留目标和完整原因。救济锁定、非空容器等限制保持。

### 维护：保留现有服务能力

- 标签使用短名“维护”，详情标题为“武器维护”。普通列表为仓库直属、当前维护服务支持的武器，**保留原本已支持的近战武器**。
- 费用、即时完成、耐久恢复与故障清理沿用现有查询和命令，不增加等待时间、倒计时或运营加成。
- 旧档若已有待领取任务，仍单独显示原任务和领取动作；不能再开一项维护，仓库空间不足时保留物品与原因。
- 条件救济保持可见，资格和发放由原规则决定；组件改装仅接入现有页面并正确返回“供应与回收”，不翻新改装页。

## 输入与状态规则

列表使用稳定定义ID或实例ID，不以可变行号执行交易。每个标签各有临时页码；翻页／切标签清空当前选择和未完成按压，避免旧目标留在不可见页面。关闭后这些状态重置，不进入存档。

按钮必须在同一目标内按下、松开才执行一次。滚轮、切页、切标签、切窗口、Esc、打开其他菜单或进入／返回改装时，清理未完成的按压；不能穿透为世界开火、移动或下一页的操作。

执行前按当前Profile重新确认来源与稳定ID，不把失效选择替换成下一行。购买成功可保留商品；回收成功必须清除被消耗的实例；维护成功重新读取该实例状态。报价、选择与执行目标必须一致。

维护与救济使用现有只读查询。购买／回收目前没有完整只读资格API：本版不新增经济API、不在渲染时克隆Profile模拟交易，也不复制一套完整经济规则。无选择或来源失效时禁用按钮；有效选择只代表可发起操作，实际资金、空间与回收资格仍由原命令原子校验并清楚反馈。查询失败或无报价时显示原因／“—”，不能把0显示成免费服务。
