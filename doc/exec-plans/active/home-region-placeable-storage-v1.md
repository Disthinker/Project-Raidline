# Home Region 可放置储物箱 v1 ExecPlan

状态：建设面板返工实现完成；Windows Debug 全目标构建与 1372/1372 CTest 已通过，等待 exact-head Windows/Ubuntu CI 与用户正常游玩验收。

## 目标与基线

依赖基线为用户已验收并合入的 PR #125，`origin/main@03028bb`。开发分支为 `codex/home-region-placeable-storage-v1`。

本切片加入一个使用代码图形和文字占位的基础储物箱。玩家可从基地固定供应购买，在基地板块内选择世界位置放置；储物箱放置后成为持久化的真实资产根、空间阻挡和可近距离打开的库存容器。它复用 PR #124/#125 的 BaseGround 与世界容器事务，不建立第二套设施库存。

用户验收反馈确认“先进入供应设施购买、再打开背包寻找、再拖到基地地面”的路径过于繁琐。因此本 PR 同步交付基地建设面板 v1：基地世界中按 `B` 打开侧栏，统一完成视野缩放、购买并进入放置、放置已有设施，以及选择/移动/收回已放置设施。背包拖放继续保留为兼容路径，但不再是主要建设入口。

## 内容与领域合同

- 新增稳定定义 `item.container.base_storage_crate`，提供一个通用连续格区、明确世界占地、固定供应价格和回收价格；content 升级到 v58，schema 保持 v39。
- `ItemDefinition` 增加可选的 `base_placement` 能力，声明世界占地、是否限制在基地板块以及是否阻挡移动/弹道。只有当前消费者所需字段，不建立通用建造或家具框架。
- 放置查询由 GameFlow 组合当前基地板块、设施/环境阻挡、玩家占位和已放置空间资产；领域层统一验证完整位于基地板块、无重叠、方向合法、来源可访问与 revision。
- 合法提交只把同一个资产根迁移到 `BaseGroundAssetLocation`；内容继续跟随容器。失败、保存失败、重复事务或过期 revision 均零修改。
- 建设目录只投影带 `base_placement` 且可购买的内容定义；购买由 GameSession 返回实际创建的稳定资产 ID，App 不通过显示名或高水位猜测资产。
- 已放置设施的移动使用明确的 `RepositionBaseGroundAssetCommand`；查询和提交都排除自身占地但重新验证板块、阻挡、方向和存档事务。移动取消时资产始终留在原位。
- 空储物箱只能在仓库连接范围内收回 Stash；非空储物箱必须先清空再收回，避免大型固定容器被当作背包装备或整体随身携带。

## 客户端结果

- 将储物箱拖到“基地地面”后不立即落地，而是关闭库存进入鼠标放置模式。
- 鼠标控制储物箱中心，合法位置显示绿色占地框，非法位置显示红色；`R` 旋转、左键确认、`Esc` 取消。
- 放置模式冻结射击和其他模态入口，不修改资产直至左键成功提交。
- 已放置储物箱使用更接近真实占地的矩形和双语文字占位，并参与玩家移动与基地射击的阻挡。
- 靠近后继续复用 `E` 打开及统一双向拖拽界面；非空时“拾取容器”返回明确拒绝信息。
- `B` 打开建设面板并释放鼠标，阻断移动、射击和其他模态输入；`B`/`Esc` 关闭。面板提供鼠标可点的缩小、100%、放大按钮，建设观察范围使用离散缩放档位，世界和 UI 权威状态不变。
- 目录中的“购买并放置”一次购买一个定义实例并立即进入世界放置；取消放置后该实例留在 Stash。Stash 中已有的可放置资产可直接选择放置。
- 面板列出当前基地地点的已放置设施；可选择后快速进入移动或执行收回。打开容器仍保留近距访问合同，不提供跨地图远程仓库能力。

人工验收：在基地世界按 `B`，通过按钮缩放视野；直接“购买并放置”储物箱，分别在合法空地、基地外、设施上和另一储物箱上预览；旋转后放置，确认玩家与子弹受阻；再次按 `B` 选择已放置箱并移动；靠近打开并存入物品，确认非空不能收起；清空后从建设面板收回；重启确认位置和内容持久化。整个主路径不要求进入供应设施或打开背包。

回滚使用普通 revert。schema 未升级，回滚后 v39 存档仍可读取；若存档含新储物箱定义，则必须同时保留 content v58 或先通过正常版本回滚策略移除该新内容，不能把未知定义静默丢弃。

## 明确排除

本轮不做储物箱升级、命名、权限、锁具、损坏、建造耗时、材料施工、自动分类、远程仓库连接、自由平移建设镜头、批量购买、Raid 容器、载具货舱、NPC 使用、正式美术或 Manifest 修改。建设面板只建立当前设施消费者使用的薄目录和事务入口，不提前建立无消费者的通用建造科技树。
