# Raid 持续高危阶段 v1 ExecPlan

## 产品结果与范围

玩家进入 Raid 后先处于 180 秒常规阶段，可以使用当前普通撤离。常规时间归零只会原子进入持续高危，绝不产生时间失败；普通撤离停止接受新进度，切换前已经开始的同一次读条获得完成宽限，中断后不能重开。高危阶段开放一处地图数据定义的信号紧急撤离，玩家需要在区域内连续防守 12 秒。感染者压力按固定间隔持续补入，但活动敌人数量有硬上限；高危没有终局倒计时，直到玩家撤离、死亡或主动退出。

本切片属于 `Raid Pressure & Variety`，从已接受的三张固定地图继续纵向交付。它不实现随机危机池、停电/火灾、道路封锁、高级资源区、条件撤离、凭证撤离、任意位置发射信号、主动拉闸、地图情报、随机地图、新敌人类型、新美术或新音频。代码绘制的信号区是当前可玩 fallback，不代表正式地图/信号美术完成。

## 基线与依赖

- 分支：`codex/raid-continuous-high-risk-v1`，基线 `origin/main@6138da8`。
- PR #73 的三张固定地图和 PR #74 的准星连续性均已进入主线；没有开放依赖 PR。
- 外部 GDD 只读。已确认合同是“常规阶段归零进入持续高危、时间永不判负、普通撤离关闭、既有读条一次宽限、高危没有终局倒计时”。
- GDD 尚未冻结持续压力的最终危机组合和数值；本切片采用有界感染者补入作为第一个可测试消费者，不把它静默升级为最终危机池。

## 权威状态与数据合同

- `RaidSession` 唯一拥有 `Regular/HighRisk` 阶段、常规剩余时间、当前撤离路线、普通撤离宽限和撤离进度。时间不能直接写入 Settlement 结果。
- `MapDefinition::highRisk` 保存常规阶段时长、信号撤离区域/时长、首波延迟、波次间隔、单波数量、活动敌人上限和合法压力出生点。
- `PendingRaidSnapshot` 已冻结地图 ID、seed 和本局初始配置；当前不支持 Raid 中途续玩，因此高危运行时波次不新增持久化字段。相同地图定义和 seed 产生相同的出生点轮转顺序。
- `GameplayWorld` 拥有单局高危压力运行时，只能追加无资产/无存档身份的敌人实体；每个新敌人仍获得本局单调且不复用的 `CombatTargetId`。
- App 只消费 RaidSession 与 GameplayWorld 投影，不能自行关闭撤离、生成敌人或判断阶段。

## 默认玩法参数

- 常规阶段：180 秒；最后 30 秒显示明确预警。
- 普通撤离：3 秒；高危切换前已开始的读条只保留当前一次宽限。
- 信号紧急撤离：12 秒，离区、Grab/OffBalance 或死亡会清空；回到信号区可重新开始。
- 高危压力：进入后 3 秒出现首波，之后每 15 秒尝试补入 2 名现有感染者；同时存活上限 8 名。达到上限时停止补入，数量下降后继续。
- 出生点来自地图定义；运行时跳过与玩家过近或被活敌占用的位置，所有候选均不合法时保留压力待下一帧重试，不在玩家脚下强制生成。

## 实施与回滚边界

1. 扩展 RaidSession 为阶段与撤离路线状态机，保留历史硬超时测试路径但生产高危不使用。
2. 扩展内容定义、JSON 与验证器；将 content version 升为 v10，并允许 schema v6 的 v9 存档显式兼容加载。
3. 将地图高危配置接入 GameSession → GameplayWorld，完成持续补入、活动上限和稳定目标 ID。
4. 接入普通/信号撤离代码表现、常规倒计时、30 秒预警、高危无剩余时间 HUD。
5. focused tests、Windows Debug 全目标、完整 CTest 与 exact-head Windows/Ubuntu CI 通过后，交给用户正常游玩验收。

回滚为普通 revert 本切片提交；不得重写历史。旧 v9 存档兼容路径保留，回滚不依赖删除玩家存档。

## 自动化与人工门槛

- RaidSession：自然进入高危不终结；普通撤离关闭；宽限完成/中断失效；信号撤离只在高危工作；任意长时间不产生时间失败。
- ContentRegistry：三图配置完整；信号区/出生点越界、障碍重叠、非法时长/数量/上限均拒绝。
- GameplayWorld：阶段转换、首波/后续波、活动上限、过近/占用跳过、稳定非零目标 ID 和高危撤离。
- GameSession：自然高危后成功撤离仍只结算一次；死亡/主动退出/关闭程序合同不变。
- 人工验收：选择任一地图正常战斗；观察 30 秒预警和高危切换；确认普通撤离关闭、压力持续且不会无限同屏增长；在信号区防守撤离；第二局在切换前启动普通撤离并验证一次宽限。
