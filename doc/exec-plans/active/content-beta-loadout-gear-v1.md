# Content Beta 防具、胸挂与背包梯度 v1

## 产品结果、基线与范围

本切片让玩家在轻装搜刮、均衡生存和重装强攻之间做出可理解的配装选择。差异必须来自头盔/躯干防护、耐久、重量、维修成本、胸挂分区和背包连续容量；重量继续只影响现有高危轻装撤离资格，不增加移动速度、耐力或其他负重惩罚。

依赖基线为已经用户验收并合入的 PR #117，`origin/main@8164e66`。分支为 `codex/content-beta-loadout-gear-v1`。用户于 2026-08-31 要求仓库直接提供所有已发布物品，因此 content v54 继续使用版本化、一次性、幂等的完整目录补齐；它不是商店、救济或可重复奖励，Macro 3 仍需裁决正式发行形态。

明确排除：新防具部位、护颈/面罩独立槽、套装加成、随机词条、随机品质、移动/耐力负重惩罚、正式穿戴图层、新美术、资源 Manifest 和额外音频。现有七装备槽与 `1/2/3` 武器热键不变。

## 稳定定义与三类配装

保留现有 ID 与实例语义：

- `item.protective_gear.helmet_basic`
- `item.protective_gear.body_armor_basic`
- `item.container.chest_rig_small`
- `item.container.backpack_small`

新增稳定定义：

- 轻型防具：`item.protective_gear.helmet_scout`、`item.protective_gear.body_armor_light`
- 重型防具：`item.protective_gear.helmet_heavy`、`item.protective_gear.body_armor_heavy`
- 胸挂：`item.container.chest_rig_patrol`、`item.container.chest_rig_assault`
- 背包：`item.container.backpack_field`、`item.container.backpack_expedition`

代表性组合不是自动套装，而是对领域值的验收基线：

1. 轻装搜刮：轻型防具、小型胸挂、小型背包。最低自重、最低保护和容量，可保留高危轻装撤离余量。
2. 均衡生存：基础防具、巡逻胸挂、野战背包。中等保护、维修成本与容量。
3. 重装强攻：重型防具、突击胸挂、远征背包。最高保护和容量，但仅装备本身即可显著挤压或超过 22 kg 轻装撤离门槛。

武器仍不使用品质色。防具/容器可继续使用代码色块和双语文字，但玩家判断必须来自防护等级、耐久、重量、分区与容量，而不是颜色或名称猜测。

## 领域、内容与持久化合同

- `ArmorProtectionDefinition` 继续唯一描述部位、防护需求、材料、最大耐久和受击耐久损耗；新定义不增加第二套减伤公式。
- `ContainerCompartmentDefinition` 继续唯一描述胸挂/背包结构。巡逻和突击胸挂提供不同数量、尺寸及 `magazine_only/general` 分区；背包保持一个连续通用格区，但容量和物品自身占格不同。
- InventoryDomain 继续负责装备、卸下、原子交换、跨分区移动及非空容器禁止嵌套。拒绝操作保持 Profile 指纹、revision 和稳定 ID 高水位不变。
- 现有随身总重量查询与高危条件撤离继续消费同一 `unit_weight_grams`；本切片不得把重量接入移动或体力。
- 防具维修继续按 Soft/Composite/Metal 材料消费同一维修包规则；高防护内容通过更高重量、损耗和维修点成本形成代价。
- 新增物品只进入现有普通工业、高价值、地点专属或高危 Loot 表。只有轻型/基础开发内容可以出现在固定供应；重型内容不得进入无限基础供应。
- content 升至 `content-beta-loadout-gear-content-54`，schema 保持 v38、rules 保持 v28。实例结构和冻结 Raid 快照结构不变；content v53 显式兼容，旧 pending Raid 不重抽 Loot。
- 全目录补齐使用新事务 `bootstrap.warehouse_catalog.content_54`。已有 content v53 档案只补缺少的 v54 定义；既有物品不复制、不搬位。新档直接获得完整 v54 目录。仓库不足时整笔零修改且不锁档。
- Stash 从 20×12 扩为 24×16，只增加合法空间，不迁移旧坐标；客户端按新尺寸缩放仓库格，旧档保持原位置。

## 实施顺序与退出条件

1. 冻结本计划、ID、数值职责、content v54 与 v53 兼容。退出条件：旧档/旧 pending Raid 可读取，新档目录标记明确。
2. 发布八件装备定义并接入合法 Loot/供应来源。退出条件：每件物品至少有来源、装备消费者、回收去向和失败/寻回边界。
3. 把个人页胸挂/背包绘制改为定义驱动的动态分区布局，并展示重量、防护、耐久和总容量。退出条件：不同分区可被鼠标拖放命中，客户端不再假设四个胸挂格或一个固定尺寸。
4. 升级 Stash 与完整目录幂等补齐，覆盖 v53→v54、满仓拒绝和跨进程保存。退出条件：所有 v54 定义可直接在仓库中检查，重复启动不重复发放。
5. 完成自动化、Windows Debug、完整 CTest 和 exact-head Windows/Ubuntu CI，再交给用户正常游玩验收。开发代理不启动游戏。

## 自动化与正常游玩门禁

- 八件新定义的稳定 ID、槽位、防护、材料、重量、耐久和分区结构。
- 轻/均衡/重三套完整重量投影；轻装保留撤离资格，重装明确失去资格，且不存在只靠品质颜色的全面上位。
- 全部胸挂分区的弹匣限制、通用格、跨分区移动、原子交换及失败零修改。
- 三种背包连续空间、容器交换、非空嵌套拒绝和方向/占格验证。
- 防具受击、维修、最大耐久损失、死亡失物、NPC 寻回与自力寻回的唯一所有权回归。
- content v53/schema v38 往返、v54 目录补齐、重复补齐、仓库满载、未知定义和损坏存档。
- 中英文名称与检视字段；颜色关闭时仍可读懂重量、防护、耐久和容器结构。
- 全量 CTest、Windows/Ubuntu exact-head CI；开发代理不启动游戏。

用户最终只需正常游玩：在 Base 分别整理轻装、均衡与重装；向不同胸挂分区放置弹匣/医疗物，验证错误物品被拒绝；进入高危比较轻装撤离资格；完成一次成功撤离和一次失败后的任一寻回。验收不依赖调试按钮。

## 提交、PR、风险与回滚

本分支只交付 Macro 2。内部提交按计划/内容、客户端动态容器、迁移与测试、状态收尾组织，最终形成一个 Draft PR；不自动合并。

主要风险：完整目录超过旧 Stash 容量；客户端硬编码四格胸挂；重型防具因当前敌人穿透较低而成为无条件最优；重型背包容量掩盖撤离重量代价。通过 Stash 单向扩容、定义驱动布局、防护/重量/维修联合门禁和 22 kg 撤离回归控制。回滚使用普通 revert；已经写入存档的新 DefinitionId 即使停止投放也必须继续解析，不得重写历史或强推。
