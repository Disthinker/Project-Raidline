# Home Region 储备设施空间部署 v1 ExecPlan

状态：已完成。PR #133 通过 Windows Debug 全目标、1400/1400 完整 CTest、exact-head Windows/Ubuntu CI 与用户正常游玩验收，并以 merge commit `411aaed` 进入 main。

## 玩家结果与依赖

迁徙后进入设施储备的核心设施不再以完整建筑留在世界中，也不再产生碰撞或近距交互。玩家在基地按 `B` 打开建设面板，切换“已有”页面，选择储备设施后以绿/红虚像决定新址；合法位置左键部署，随后设施恢复原有等级、人员、任务和功能。旧区域页面不再提供绕过选址的即时安装按钮。

本切片复用 PR #132 的站点独立归一化布局、建设镜头和设施管理投影。仓库、医疗所、宿舍和工坊属于可空间部署的核心设施；供应、物资分配和 Raid 出击口继续是站点固定基础设施。

## 领域与客户端合同

- `InstallBaseFacilityAtCommand` 把储备状态恢复和空间位置提交合并为单一 Profile 事务；查询重验当前基地地点、设施所有权、Reserve 状态、暂停时间、基地边界及全部阻挡。
- 成功提交只推进一次 revision，并同时恢复设施任务时间线、删除 Reserve 起始时间、写入当前站点归一化位置。拒绝、过期事务、非法重叠和保存失败保持 Profile 指纹不变。
- `BaseWorld` 继续保留稳定七设施槽位以兼容既有消费者，但只有 active 设施参与绘制、地图标记、碰撞、近距交互与鼠标命中。Reserve 核心设施只存在于 Profile 和建设面板。
- “已有”页先列出可部署的 Reserve 核心设施，再列出仓库中的可放置资产。管理卡片若选中 Reserve 设施，操作按钮显示“部署设施”而不是不可用的“移动设施”。
- 所有新增提示提供中英文；不增加 schema 或 content 版本，因为状态和站点布局均已由现有字段持久化。

## 验证与人工验收

自动化覆盖安装查询零修改、位置与状态原子提交、事务幂等、阻挡拒绝、Reserve 设施不绘制/不碰撞的世界投影，以及现有迁徙、持久化、设施管理和本地化回归。完成 Windows Debug 全目标、定向测试、完整 CTest 与 exact-head Windows/Ubuntu CI 后交给用户正常游玩验收；Codex 不启动游戏。

人工验收：迁徙到会把工坊打包为 Reserve 的基地，在世界和 Home Region 地图确认旧工坊不再出现且不阻挡；按 `B`→“已有”，点击工坊卡片，确认合法位置为绿色、越界或与建筑/设施/玩家/地面储物重叠时为红色；放置后确认工坊出现并恢复功能，暂停任务保持剩余时长。退出到主菜单或桌面并重开，确认位置与安装状态保持。区域页面的设施储备入口只应引导到建设面板，不应直接安装。

回滚采用普通 revert。该切片不改变存档格式；回滚后已部署设施仍是合法 Installed 状态和 schema v40 布局，只会恢复旧客户端的表现行为。
