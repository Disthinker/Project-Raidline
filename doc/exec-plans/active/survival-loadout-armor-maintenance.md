# Survival Loadout：防具维护 ExecPlan

状态：实施中

基线：`origin/main@4c16596`（PR #64 已通过用户正常游玩验收并合入）

分支：`codex/survival-loadout-armor-maintenance`

产品输入：外部只读 GDD 的 `systems/02_玩家操作与装备槽.md`、`systems/03_武器装备弹药与治疗.md`、`systems/13_生命状态与医疗.md` 和当前仓库领域不变量。GDD 保持只读；本计划只交付防具自助维护闭环。

## 1. 玩家结果

头盔和护甲受损后不再只能报废。玩家可把基础甲修包拖到 Stash、随身容器或装备槽中的防具：Base 中即时维修；Raid 中关闭库存并执行六秒原地维修。甲修包按防具材质消耗真实剩余点数，每次维修永久降低防具当前最大耐久；零耐久防具也能恢复。移动、战斗、冲刺、受伤和受控会中断 Raid 维修，且不产生修复或资源消耗。

## 2. 权威状态与领域合同

- `AssetRegistry` 继续唯一拥有防具与甲修包。防具沿用出厂最大、当前最大、当前耐久；甲修包沿用实例 `remainingCharges` 保存剩余维修点。
- `ArmorProtectionDefinition` 增加材质：基础头盔为复合材料，基础护甲为软质材料。材质只决定维修成本，不由名称、颜色或槽位推断。
- 基础甲修包容量 50.00 点，占 `1x2`，软质/复合/金属每恢复 1 点耐久分别消耗 1.00/1.50/2.00 点。
- `queryArmorMaintenance()` 返回修复量、点数消耗、维修前后当前最大耐久和动作时长；查询不修改 Profile。
- Base/Raid 每恢复 1 点分别按 10%/20% 向上结算当前最大耐久损失，最低不得低于出厂最大耐久的 20%。点数不足时选择其能够完整支付的最大整数修复量。
- `executeArmorMaintenance()` 在 revision、位置、能力、剩余点数和目标状态重验后复制候选并原子提交。拒绝或中断保证 Profile 指纹、revision、货币、稳定 ID 高水位和维修点数不变。

## 3. 操作、动作与表现

- Base/Raid 共用现有拖拽内核。甲修包拖到合法防具显示蓝色 `REPAIR`；非法目标显示红色 `BLOCKED`。
- Base 可维修任意合法自有防具并按既有存档事务即时保存。
- Raid 可维修装备槽或随身容器中的防具；启动后关闭库存并建立类型安全 `ArmorMaintenanceRaidAction`。
- Raid 维修期间必须原地。移动输入在同一帧中断且正常移动；射击、换弹、切枪、治疗和冲刺的首次输入只中断动作，必须释放后重新输入；受到实际伤害时先完成该次护甲/HP 结算，再中断维修。
- HUD 显示 `REPAIRING ARMOR` 与进度；防具卡片、装备槽与甲修包显示当前/最大耐久或剩余点数。
- 使用代码 fallback 表现，不生成、发布或接入正式图像/音频，不修改美术 manifest。

## 4. 内容、持久化与生命周期

- 内容升级为 `survival-loadout-content-5`，新增 ArmorMaterial 与 ArmorMaintenance 定义校验。
- 新 Profile 获得一份基础甲修包；固定供应可购买后续甲修包。
- 在扩展固定供应时一并修正 PR #64 内容合同已声明、但客户端列表漏列的 Pistol 与 15 发弹匣；供应区改为不与 Stash 重叠的三列布局。该修复不改变武器领域或存档。
- 存档结构不增加第二份防具状态：现有 schema v6 已保存 `remainingCharges` 与防具耐久。本切片补充 v6 往返、旧内容版本兼容和非法点数/耐久拒绝测试，不为无结构变化空增 schema。
- Raid 内维修结果只在内存提交；成功撤离保留，死亡/主动放弃全损，关闭程序继续恢复精确出击前档案。

## 5. 明确排除

- NPC 全面维护、付费等待、维修队列和 WorldClock。
- 组件级耐久、插板、面罩、方向覆盖、改枪台、配装预设和战术电子。
- 新防具型号、特殊弹、贯穿、断肢、击退和新地图。
- 正式维修动画、图像、音频、runtime 资源发布及 manifest 修改。

## 6. 自动化与人工门槛

- 内容：材质、甲修能力、容量、动作时长、价格和非法组合校验。
- 领域：软质/复合/金属成本，Base/Raid 最大耐久损失，零耐久恢复，20% 下限，点数不足最大修复，满耐久/错目标/不在随身/过期 revision 拒绝不变。
- 会话：Raid 开始、六秒完成、移动/战斗/冲刺/受伤/控制中断，同帧移动与战斗输入释放门控。
- 客户端：装备与容器目标、拖放反馈、进度、耐久和甲修点数投影。
- 生命周期/存档：成功保留、失败全损、进程退出回滚、v6 往返、损坏主档/备份恢复。
- 交付：Windows Debug 全目标、focused、全量 CTest、exact-head Windows/Ubuntu CI。全部通过后由用户正常游玩验收，开发代理不启动游戏。

## 7. 提交、风险与回滚

- 内容/领域、会话/客户端、测试/文档形成可审计提交，同一 PR 交付完整玩家闭环。
- 最大风险是甲修点数、实际恢复与当前最大耐久损失不同步；三者必须来自同一查询计划并在同一候选 Profile 提交。
- 同帧受击按“先伤害、后中断”排序；维修计划不进入受击解析，避免未提交收益参与防护。
- 整个切片可回滚至 `origin/main@4c16596`，不影响 schema v6 档案读取。
