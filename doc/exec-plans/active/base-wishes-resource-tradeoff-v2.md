## 产品结果

每个五日周期按周期开始时冻结的人口规模生成一至三个愿望。玩家在既有资源分配页选择具体愿望，再从仓库、装备或随身容器中明确选择可贡献资产；界面在提交前显示贡献、门槛和超额。只有一次完整、原子的确认才消耗所选物品并完成该愿望。

愿望用于形成“保留个人物资还是支持基地”的实际取舍。完成和错过只进入既有士气账本，不发货币、奖励箱或任务直接奖励。正常游玩验收由用户完成，Codex 不启动游戏。

## 状态所有权与领域合同

`ProfileState::basePriority` 保存周期索引、冻结人口、愿望 ID/完成位、累计错过数量和仅供旧档当前周期使用的迁移标记。愿望数量只由冻结人口档位决定；同周期、人口和内容必须得到相同顺序，打开界面、重启或仅迁移 Profile 身份不得重抽。

`queryBasePrioritySubmission` 只接受当前周期未完成愿望与玩家明确列出的非重复 AssetInstanceId。每个资产必须存在、可在 Base 访问、没有子资产，并对目标分类提供正贡献。贡献不足、过期版本、无效位置、重复 ID、保存失败或任何坏引用均零修改。

提交会一次性消费所选完整资产堆、标记一个愿望完成、写入一次待结算士气事实并推进 ProfileRevision。它不增加货币、抽象基地资源或奖励资产。重复 TransactionId 只返回已提交，不重复消费或计分。

旧 schema v42 只保存一个愿望。迁移保留该周期、定义、完成状态和累计错过值，不为当前周期补抽额外愿望；进入下个周期后才按当前人口生成完整集合。Pending Raid 的出发前愿望使用相同兼容规则，异常退出仍精确回滚。

## 自动化与人工验收

自动化至少覆盖：

- 低/中/高人口分别生成一、二、三个不同愿望，周期内人口变化不改变当前集合。
- 同周期/人口跨进程选择一致；改变 Profile 身份不污染既有愿望或 Raid 部署，下周期才重选。
- 同分类不同物品可共同达标；预览显示准确总贡献与超额。
- 只消费明确选择的完整资产，不扫描同定义或同分类的其他资产。
- 贡献不足、混入错误分类、重复 ID、非空容器、Raid pending、stale revision、保存失败均保持完整 Profile 指纹和高水位不变。
- 完成/错过进入既有士气账本且不产生货币、资源或奖励物。
- schema v43 往返、schema v42 单愿望迁移、pending Raid 回滚与跨周期长序列。
- 运营总览、中英文和所有既有 Base/Raid 回归。

用户正常游玩验收：在资源分配页查看当前一至三个愿望，选择一个愿望和多件同分类物品，确认贡献/超额后提交；检查未选物品仍在原处、该愿望完成、其他愿望仍可处理。推进到下一周期，确认人口档位影响下一组数量；重启后当前组不变化。无需调试按钮或单步验收入口。

## 风险

- **静默吞物**：命令只消费显式 ID，按钮提交前显示总贡献与超额；无部分提交。
- **人口变化导致重抽**：周期人口写入 Profile 并参与验证，只有周期轮换更新。
- **旧档愿望被改写**：v42 迁移保留当前单愿望事实，以迁移标记跳过新选择一致性检查直至下周期。
- **愿望成为任务清单**：仅进入现有 Allocation/运营总览，不建立任务板、导航、直接奖励或全局追踪。
