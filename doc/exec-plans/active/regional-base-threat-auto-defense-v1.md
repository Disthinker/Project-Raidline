# Regional Base Threat & Auto Defense v1

## 产品结果与范围

本宏切片让区域经营第一次形成周期危机闭环。玩家在 Base 顶部持续看到基地威胁档位、进度和主要来源；完成 Raid、人口活动以及当前主基地地点噪声会通过权威世界时间增加威胁。威胁达到门槛且最低安全期结束后，只在玩家恢复 Base 操作时进入可保存的 3 分钟预警。玩家可以提前确认一次自动防守，使用公共 Security 储备结算成功或软失败；结算后清空本轮威胁，并分别进入 7/12 个游戏日最低安全期。

产品事实来自只读 GDD `systems/19_基地防御与尸潮攻城.md`、`systems/21_世界时间与日程.md` 和 `systems/22_基地地图与外围行动.md`。本切片只交付已有消费者的第一条防守路径。

明确排除：实时基地战斗、敌人波次、防御设施、战斗小组、NPC 逐人装备、自动防守多档投资、收藏品/系统商店兑换、外围清理、睡眠、正式美术、正式音频和 manifest 修改。实时防守将在同一威胁/预警/结算合同稳定后独立接入。

## 状态所有权与不变量

- `BaseSiegeState` 是 Profile 中唯一权威状态，保存三类累计来源、已结算日、最低安全期截止世界分钟、预警剩余秒数、攻城序号、自动防守预设和最近结果。
- 威胁总量由来源累计值投影并封顶。每日人口/地点噪声通过统一 Base 日结推进；每个非异常 Raid Settlement 只提交一次 Raid 来源增量。重复 Settlement、取消 Deploy 和异常退出不增加威胁。
- Pending Raid 冻结出击前 `BaseSiegeState`。关闭/异常退出恢复完整出击前状态；成功、死亡和主动退出保留 Raid 内世界时间产生的日结并在 Settlement 末尾增加一次行动威胁。
- 达到门槛只产生资格。迁徙、返程或其他原子时间事务先完整提交，玩家回到可操作 Base 后才激活完整 180 秒预警。
- 预警仅在未暂停的 Base 会话推进，页面切换不能暂停；退出游戏不推进。剩余时间由存档恢复。
- 首次预警没有自动预设，倒计时归零后停在明确确认态，不静默消耗资源或提交失败。玩家手动确认自动防守后保存预设；后续预警归零可以使用同一确定性事务自动执行。
- 自动防守纯查询显示所需 Security、预计成功/软失败和后果。提交使用候选 Profile；过期 revision、重复事务、校验或保存失败保持内存与磁盘状态不变。
- 成功消耗冻结的公共 Security，增加基地建材和下一日正向士气原因，并进入 7 日安全期。软失败耗尽当前可用 Security、损失有限公共储备和至多一名受保护边界以上的普通居民，写入下一日负向士气原因，并进入 12 日安全期；核心服务、科技核心、个人资产和最低四名居民不受损。
- 预警期间禁止主基地迁徙、从设施储备安装和开始新的建设；维修、医疗、库存、补给和已开始队列继续可用。
- content v41 为基地地点声明每日威胁强度；schema v32 保存状态，v31 及更早存档初始化为尚未经历攻城的空状态并沿用新 Profile 的初始安全窗口基线，不根据显示名推断地点噪声。

## 自动化与人工验收

自动化覆盖：新 Profile 初始安全期、每日人口与地点噪声、Settlement 单次威胁、异常回滚、阈值只在 Base 激活、180 秒分割一致、首次超时保护、保存恢复、成功/软失败、资源和人口保护、重复事务、保存失败、预警迁徙/设施门禁、schema v31→v32 与 v32 往返、中英文投影。

人工验收：正常完成若干 Raid 并观察威胁来源变化；预警激活时确认已打开的库存/设施页被关闭并进入专用警告界面，退出重开确认剩余时间恢复；确认迁徙/安装被阻止；Security 足够时提前自动防守并查看成功、安全期和材料/士气反馈；后续低 Security 情况确认软失败不损坏个人装备或造成死档。开发代理不自行启动游戏。
