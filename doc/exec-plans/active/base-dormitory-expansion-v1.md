# Base Growth：宿舍扩建 v1 ExecPlan

状态：本地与 exact-head CI 已完成，等待用户正常游玩验收

## 产品结果与范围来源

玩家可把待分配区中的废旧零件或损坏电子元件明确转化为独立的基地建材，并在宿舍启动一次真实扩建。项目锁定建材和聚合劳动力，持续占用唯一建设槽；世界时间达到完成节点后，宿舍等级与床位容量原子更新并释放劳动力。建设期间旧床位继续可用，取消项目会返还锁定的建材，但不会回退已经流逝的世界时间。

只读 GDD `systems/17_剧情路线与基地人口.md` 与 `systems/23_基地设施与建设.md` 已确认：普通居民使用聚合池；建设消耗材料、世界时间和临时劳动力；初期同时只允许一个项目；取消返还锁定材料并释放劳动力；升级施工期间保留旧设施功能。本切片只实现一项宿舍 1→2 级扩建，使用文字与代码图形占位。

## 领域合同

1. `ItemDefinition` 只为明确可加工的回收物声明建材点数；玩家必须在待分配区主动转化，转化后原物品实例消失且不能还原。
2. `BaseConstructionState` 独立保存可用建材、宿舍等级和至多一个活动项目；四项日常运营资源不承担建筑材料语义。
3. 查询与提交共用内容定义。启动项目必须同时满足等级、建材、劳动力、世界时间和无并行项目约束。
4. 启动扣除并锁定建材；取消返还同等建材；完成只发生一次，更新床位并释放劳动力。拒绝、过期 revision、重复 transaction 和保存失败均保持 Profile 指纹不变。
5. Base 实时流逝、休息、Raid 出发和返程都消费同一世界时钟并解析到期项目。异常退出 Raid 仍恢复出击前 Profile，不额外推进建设。
6. 领域与服务层不依赖 SDL；客户端只发送命令并消费只读投影。

## 玩家操作与验收路径

1. Raid 成功带回废旧零件或损坏电子元件。
2. 在资源分配页选择物品并点击“转化为建材”，确认独立建材池增加。
3. 在宿舍页启动扩建，确认建材扣除、3 名居民显示为建设占用、旧床位仍为 10。
4. 正常移动、进行 Raid 或使用宿舍休息推进 6 小时；完成后宿舍变为 2 级、床位变为 14、劳动力释放。
5. 另一次新档/测试流程中启动后取消，确认建材返还且世界时间不回退。
