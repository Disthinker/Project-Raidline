## 产品结果与范围来源

玩家可从统一的自有资产中明确选择废旧零件或损坏电子元件并转化为独立基地建材，再在宿舍启动一次真实扩建。成功撤离只确认所有权，绝不改写玩家身上、容器内或未来载具货舱中的物品位置；玩家回到 Base 后自行整备。基地供给菜单按食物、医疗、娱乐和安全分类列出当前拥有且具备对应贡献的物品定义，勾选只保存自动供给授权，物品直到每日需求确实需要时才从原位置消耗。

只读 GDD `systems/17_剧情路线与基地人口.md` 与 `systems/23_基地设施与建设.md` 已确认：普通居民使用聚合池；建设消耗材料、世界时间和临时劳动力；初期同时只允许一个项目；取消返还锁定材料并释放劳动力；升级施工期间保留旧设施功能。本切片只实现一项宿舍 1→2 级扩建，使用文字与代码图形占位。

## 领域合同

1. `ItemDefinition` 分别声明建材点数与四类基地贡献。建材必须由玩家显式选择自有资产加工；自动供给以“物品定义→唯一分类”策略授权，不存在结算待分配容器这一正常流程。
2. `BaseConstructionState` 独立保存可用建材、宿舍等级和至多一个活动项目；四项日常运营资源不承担建筑材料语义。
3. 查询与提交共用内容定义。启动项目必须同时满足等级、建材、劳动力、世界时间和无并行项目约束。
4. 启动扣除并锁定建材；取消返还同等建材；完成只发生一次，更新床位并释放劳动力。拒绝、过期 revision、重复 transaction 和保存失败均保持 Profile 指纹不变。
5. Base 实时流逝、休息、Raid 出发和返程都消费同一世界时钟并解析到期项目。异常退出 Raid 仍恢复出击前 Profile，不额外推进建设。
6. 成功 Settlement 对所有随身资产保持精确 `AssetLocation`；拾取时发生的合法堆叠也保留合并后的真实位置。`BaseIntake` 仅作为旧存档恢复位置，不再接收新的撤离物。
7. 每日需求仅在储备不足时按稳定实例 ID 顺序消耗最少的已授权完整数量；一件物品定义同时只能分配给一个类别。Pending Raid 期间不自动消耗任何库存，避免异常回滚重建资产。
8. 领域与服务层不依赖 SDL；客户端只发送命令并消费只读投影。

## 玩家操作与验收路径

1. Raid 中把战利品放进指定背包格并成功撤离；回到 Base 后确认玩家身上全部装备、弹药和战利品仍在撤离前的原槽位/格位，没有进入待分配区。
2. 打开资源分配页，在食物、医疗、娱乐、安全分类间切换；确认只显示玩家拥有的可用定义及每件贡献值。勾选可乐作为食物来源不会立刻移动或删除可乐，重新读取存档后勾选仍保留。
3. 推进到每日需求边界；只有相应储备不足时才自动消耗已勾选物品，未勾选物品、Raid 期间随身物以及不匹配分类均保持不变。
4. 在资源分配页选择废旧零件并点击“转化为建材”，确认只消耗该实例且独立建材池增加。
5. 在宿舍页启动扩建，确认建材扣除、3 名居民显示为建设占用、旧床位仍为 10。
6. 正常移动、进行 Raid 或使用宿舍休息推进 6 小时；完成后宿舍变为 2 级、床位变为 14、劳动力释放。
7. 另一次新档/测试流程中启动后取消，确认建材返还且世界时间不回退。
