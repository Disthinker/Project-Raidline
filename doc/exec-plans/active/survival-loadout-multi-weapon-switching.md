# Survival Loadout：多武器配装与切换 ExecPlan

状态：候选冻结中

基线：`origin/main@b8ddbe3`（PR #63 已通过 exact-head CI 和用户正常游玩验收并合入）

分支：`codex/survival-loadout-multi-weapon-switching`

产品输入：外部只读 GDD 的 `systems/02_玩家操作与装备槽.md`、`systems/03_武器装备弹药与治疗.md` 和阶段式减法规划。GDD 保持只读；本切片只建立有当前玩家消费者的多武器边界。

## 1. 玩家结果

玩家可以在 Base 将长枪配入两个独立槽位，并将基础手枪配入独立手枪槽。三个槽位各自保留真实武器、弹匣、枪膛、耐久和故障状态。Raid 中使用 `1/2/3` 进行有耗时的武器切换，HUD 明确显示当前武器和其弹药/状态；射击、换弹、清障和维护都作用于正确的当前实例。

## 2. 权威状态与领域合同

- `EquipmentSlotKind` 增加第二长枪槽与手枪槽；武器定义显式声明可兼容槽位集合，非武器仍使用单一专用槽。
- `AssetRegistry` 继续唯一持有每件武器、弹匣和弹药。切换只改变 Raid 运行时的当前使用槽，不复制或迁移资产。
- 装备、快速装备、替换和卸下继续通过 InventoryDomain 查询—预览—原子提交；被拒绝时 Profile 指纹、revision 和 ID 高水位不变。
- 出击时按第一长枪、第二长枪、手枪的稳定顺序选择初始当前武器。空槽输入零修改，对已当前槽输入是明确无操作。
- `WeaponSwitchRaidAction` 保存来源/目标槽、进度和耗时。完成前当前武器不变；中断不保留进度。
- 长枪切换基准 0.65 秒，手枪切换基准 0.35 秒；未压制的疼痛沿用 10% 武器操控惩罚。数值来自版本化武器使用定义，不按显示名称分支。
- 切换完成后重置射击冷却/散布的瞬态表现，不修改任何弹药、耐久或故障事实。

## 3. 内容、操作与表现

- 基础 Rifle 可进入两个长枪槽；既有已批准 Pistol 资源进入生产内容，只可进入手枪槽。
- 新增 15 发手枪弹匣，与 Rifle 共用现有 9mm 普通弹；两种弹匣不互换。手枪、弹匣和弹药进入固定基础供应，依旧遵守 25% 回收价基线。
- Rifle 保持自动扣扳行为；Pistol 只消费新的射击边沿，按住不会自动连射。两者的间隔、散布、后坐和切换时间来自强类型内容定义。
- `1/2/3` 分别选择第一长枪、第二长枪和手枪。武器切换期间允许普通移动，禁止冲刺和战斗；开库存、受控、冲刺或首次战斗输入中断切换，必须重新输入才执行后续战斗动作。
- 主动切枪中断换弹、压弹、卸弹、医疗和维护。医疗/维护的首次切枪输入只中断动作，不同帧开始切枪；其余资源动作可以同帧转入切换。
- Base 和 Raid 共用扩展后的七槽个人页。快速装备按定义兼容顺序选择第一个空槽；显式拖放可选择任一兼容长枪槽。HUD 显示三个武器槽和当前高亮。
- 不生成、发布或接入新正式美术/音频，不修改美术 manifest。未发布弹匣使用代码 fallback。

## 4. 持久化与生命周期

- 内容版本升级，并校验武器可兼容槽、手枪弹匣引用、射击和切换数值。
- schema v6 支持新装备槽枚举并继续读取 v1～v5。旧档保持原主武器槽；不凭空生成第二武器。
- Deploy 快照、成功撤离、死亡/放弃全损和异常退出回滚覆盖三个武器根。运行中当前武器不写入本地存档，因为当前仍不支持 Raid 中途恢复。

## 5. 明确排除

- 快速近战槽、投掷物、战术电子、电池、武器组件、改枪台和配装预设。
- `B` 射击模式循环、点射队列、最终开镜/逻辑弹道和武器切换动画。
- 多口径弹药、特殊弹、紧急换弹、任意物品落地和 Misfire/Double Feed。
- 新正式美术/音频、runtime 资源发布和美术 manifest。

## 6. 自动化与人工门槛

- 内容/领域：兼容槽校验、两长枪槽、手枪槽、快速装备顺序、占用槽原子交换、拒绝不变和弹匣不互换。
- 会话/动作：初始槽选择、空槽/同槽输入、切换耗时、中断、疼痛惩罚、当前武器射击/换弹/清障/维护和武器独立状态。
- 模拟：Rifle 按住连射、Pistol 单次输入单发、切换时重置瞬态射击反馈、不同定义配置被 GameplayWorld 消费。
- 存档/生命周期：schema v6 往返、v1～v5 迁移、三武器根 Deploy/撤离/全损/退出回滚及损坏主档/备份恢复。
- 客户端：`1/2/3` 输入、七槽布局、快速装备、任意武器的拖匣/维护目标、当前高亮与 HUD 弹药/耐久状态。
- 交付：Windows Debug 受影响目标、全量 CTest、exact-head Windows/Ubuntu CI。全部通过后才交用户正常游玩验收，开发代理不启动游戏。

## 7. 提交、风险与回滚

- 内部按定义/领域/存档、会话/动作/模拟、客户端/文档形成可审查提交，同一 PR 交付完整玩家闭环。
