## 当前实现

- `weapon_component_domain` 提供纯预览、原子提交与唯一有效属性解析；组件仍是独立真实资产，
  `InstalledWeaponComponentLocation` 只记录父武器 ID。默认结构不占资产 ID，拆空仍可用。
- schema 49 / content `weapon-components-content-63` / Raid rules 29；旧 schema 48、医院 content 62
  可读，无组件的武器属性不变。新安装关系禁止序列化为 schema 48；旧冻结 Raid 不重抽。
- 精确枪管：精度 +12、有效射程 +180、操控 -12、人机功效 -5；导轨护木提供下挂接口；
  垂直握把：后坐力控制 +12、稳定性 +8、操控 -5。数值为本片开发值，非最终平衡结论。
- Ashworks 工业表提供护木；Frontier fabrication 提供护木/握把、secured cargo 提供枪管/握把，
  industrial breach / freight lockdown 高危表分别提供枪管/握把。医院表不投放。
- 背包/仓库右键枪械打开“枪械详情 / 改装”菜单，保留既有可用动作。详情展示当前有效属性及已装组件；
  改装直接选中该枪。Esc/返回按钮回到背包，Tab 关闭背包与子页；Raid 中只可查看详情，改装明确拒绝。
- 供应设施与背包共用“枪匠 — 武器组件”页，支持武器/槽位/组件选择、属性前后对比、级联回收位置与确认；
  六行分页可访问全部合法资产，预览按 Profile revision、档案身份和选择缓存，提交再次校验。
- NPC 寻回仍按原概率决定整枪是否找回，已装组件共享整枪结果；没有提高概率或承诺必得。
  自力寻回保留原父子关系；整枪回收包含已装组件价值，普通库存不能单独拔下或回收已装组件。
- 普通流程通过 Loot 获得组件。既有“发放内容包”按版本发放：本轮开发包标记升级为 `developer.warehouse_catalog.content_63`，旧 56 标记不阻挡领取本版；重复领取不变，满仓/保存失败全量拒绝。不新增发放按钮或直接改用户存档。
- 本轮只做本地实现，没有提交、推送、PR 或游戏启动；原有指令维护及医院收尾文档保留。

## 一次正常游玩验收

1. 从 Ashworks/Frontier 搜集组件并撤离；回基地按 Tab，在背包/仓库右键 5.45 Service Rifle。先打开详情，返回后选择改装；应直接选中此枪。既有开发内容包也包含三件组件，旧版已领存档可再领本版一次。
2. 未装导轨护木时选择垂直握把，确认有明确拒绝原因且物品不移动；装护木后再装握把。
3. 查看前后属性，携改装枪出击，确认准星扩散/后坐力的变化；其他枪的原有行为保持。
4. 拆护木时预览同时回收握把；仓库放不下时全部拒绝，腾出足够空间后一次回收，枪保持可用。
5. 保存重开，组件和位置不变；携改装枪经历失败，再用一种既有寻回方式检查整枪组件关系。
   NPC 仍可能未找回整枪；不能把合法概率失败误判为组件丢失。

## 风险与回滚

最大风险是父子树消费者遗漏、属性只在 UI 生效和级联回收吞物。优先用真实 Profile/Session 失败路径验证。
