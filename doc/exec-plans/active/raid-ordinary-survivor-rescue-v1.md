# Raid 普通幸存者安全转移与基地接纳 v1

状态：进行中。最后更新：2026-08-25。

## 产品结果与范围来源

玩家在三张现有固定 Raid 地图中各有一次发现普通幸存者的机会。接近文字/图形占位救援点并持续交互，可完成短时安全转移；成功事实立即、原子且幂等地增加基地普通居民，并同时增加次日口粮需求和床位占用。安全转移一旦持久提交，玩家之后撤离、死亡、主动退出或异常关闭都不能撤销该名居民。

唯一产品来源是只读 GDD `systems/17_剧情路线与基地人口.md` 的已确认规则：普通人口使用聚合池；救援对象必须预先声明类别；安全转移不要求全程护送；已提交救援不因同局失败回滚；接纳不受床位或口粮硬阻止，但必须预警新增缺口。

本切片明确排除：具名 NPC、一次性事件角色、传统护送 AI、逐人模拟、受伤居民、专业人口、拒绝/再次遭遇、士气、岗位、建设、公共医疗储备、新美术和新音频。

## 现状差距

### 可复用

- `MapDefinition`、Deploy 冻结快照、`GameSession` 活动 Raid 编排与现有持续交互输入。
- `ProfileState::BasePopulationState`、人口口粮投影、床位缺口及 schema v12。
- 出击前干净 Profile 持久化、活动 Raid 内存状态、成功/失败 Settlement 与异常退出回到磁盘检查点。

### 需要重构

- 活动 Raid 目前只允许最终 Settlement 写档；需要一个只提交救援事实、但不持久化当前装备/战利品/HP/时间的干净恢复检查点。
- `RaidResult` 目前不投影已安全转移的居民数量。

### 需要新建

- 强类型 `RescueDefinitionId`、救援对象类别、地图救援定义与冻结 `RaidRescueSnapshot`。
- 幂等 `OrdinarySurvivorAdmissionCommand` 及 receipt。
- GameplayWorld 短时转移状态、GameSession 双候选原子提交和存档迁移。

### 停止扩展

- 不以“成功撤离才加人口”替代已冻结的安全转移事实。
- 不生成可跟随的幸存者实体，不增加传统任务面板或基地招募按钮。
- 不借此切片提前实现士气、岗位、专业、伤病或具名 NPC 注册表。

## 所有权、命令与持久化

- 内容注册表不可变地拥有每张地图的救援定义：稳定 ID、对象类别、转移区域、交互时间和人数。
- Deploy 将尚未完成的一次性救援定义冻结到 `PendingRaidSnapshot`；重复进入同地图不会重新生成已提交的救援。
- `GameplayWorld` 只拥有转移区域、持续时间和瞬态进度，不拥有人口和救援事实。
- `ProfileState` 通过 `committedRescues` 持有稳定事实；`BasePopulationState` 持有聚合人数。
- `OrdinarySurvivorAdmissionCommand` 对一个稳定 Rescue ID 和正人数执行一次接纳；重复事务或 Rescue ID 幂等，拒绝保持 Profile 指纹、revision 与人口不变。
- 活动 Raid 开始时 `GameSession` 保留一份干净恢复 Profile。安全转移完成时先分别构造并验证活动 Raid 候选和干净恢复候选，再原子保存干净候选，最后交换两份内存状态。保存失败不增加人口、不标记转移完成。
- 成功/失败 Settlement 使用带救援事实的活动候选；异常关闭加载磁盘中的干净恢复候选，因此保留救援人口但恢复出击前装备、HP、资源和时钟。
- schema v13 保存 `committed_rescues`、pending rescue 和结果中的救援人数；schema v12 明确迁移为空救援账本。

## 实施步骤与退出条件

1. 内容与领域：加入强类型 ID、地图定义/验证、救援接纳命令和不变量测试。退出条件：重复 ID、非法类别/几何/重叠、重复提交、溢出和拒绝不变均覆盖。
2. 生命周期与持久化：冻结 pending rescue、实现双候选恢复检查点、schema v13 往返/迁移/损坏保护。退出条件：救援在成功、死亡、主动退出和跨进程异常关闭后各结算一次。
3. Simulation 与 Client：加入可中断持续交互、区域/进度/接纳压力投影和 RaidResult 反馈。退出条件：正常游玩无需调试按钮即可发现、预览并完成救援。
4. 文档与证据：同步架构、不变量、状态、路线和问题清单；运行 Windows Debug、全量 CTest 与 exact-head CI。

## 自动化与人工验收

自动化必须覆盖：三图唯一救援定义；区域不与阻挡物或其他交互区重叠；交互离区/松键/受伤/控制/背包中断；接纳后的居民、床位缺口和日口粮投影；保存失败零提交；成功/死亡/主动退出保留救援；异常关闭只保留救援事实并恢复出击前其余 Profile；重复 Raid 和重复命令不重复加人；schema v12→v13 与 v13 往返。

交付前运行 Windows Debug 受影响目标和完整 CTest，并要求精确 head Windows/Ubuntu CI。Codex 不启动游戏。用户最后通过正常游玩验证：在一张尚未救援的地图完成安全转移，观察床位/口粮预警；随后以任一结局结束 Raid，回到 Base 核对人口；重启确认持久化；再次进入同图确认不能重复救援。

## 提交、风险与回滚

本分支只包含普通幸存者安全转移与接纳闭环。自动化通过后形成一个功能提交，推送并建立 Draft PR；未经用户新一轮验收与明确授权不合并。

主要风险是把活动 Raid 状态写入恢复档、救援点与现有交互区重叠、持久化成功但世界未确认、以及利用同一地图无限刷人口。控制方式分别为独立干净恢复候选、内容加载几何验证、先保存后交换/确认、稳定 Rescue ID 全局幂等。

回滚为普通 revert 该 PR；schema v13 只增加可缺省字段，回滚前产生的 v13 存档需要继续由迁移兼容版本读取，不通过重写历史处理。
