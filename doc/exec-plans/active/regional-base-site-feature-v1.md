# Regional Base Site Feature v1

## 产品结果与范围

本宏切片让主基地候选点的“独特设施”从说明文字变成可修复、可持久化并有真实消费者的区域运营能力。玩家在 Ashworks Logistics Yard 清剿并建立前哨后，即可在区域页使用基地建材和健康劳动力提前修复一次“重型物流工坊”；修复作为原子世界时间事务推进基地日程，完成后仅当 Ashworks 是当前主基地且普通工坊已安装时，缩短新的基地制造订单时长。迁出后该效果暂停，回迁后自动恢复，不建立重复维护循环。

产品事实来自只读 GDD `systems/24_区域交通基地迁徙与哨所.md`：独特设施必须先修复、只在该地点作为主基地时运行，工业地点的重型机械工坊只缩短加工/维修时间，不降低材料、不提高品质、不增加队列或解锁独占配方。当前玩家枪械维护已按已接受合同即时完成，因此本切片只把制造队列作为第一个真实消费者。

明确排除：第二套 Stash、独特设施持续维护、设施耐久、额外制造槽、材料折扣、品质加成、独占配方、Greyline 新事件/商人系统、尸潮威胁增长、夜战、更多基地候选点、新美术、新音频和 manifest 修改。

## 状态所有权与不变量

- `RegionalBaseSiteDefinition` 保存独特设施稳定名称、初始修复状态、修复建材、修复分钟和制造时长百分比；内容加载拒绝零倍率、无成本却未修复和无实际消费者的坏定义。
- `RegionalBaseSiteState` 唯一保存该地点独特设施是否已永久修复。迁徙和哨所状态不复制或重置此事实。
- 修复查询允许当前主基地，或已清剿并建立前哨的远程候选点；同时要求设施未修复、当前主基地已安装普通工坊、足量 `BaseConstructionState::materialUnits` 和一名未被其他任务占用的健康普通劳动力。
- 修复提交在 Profile 候选中一次性扣除准确建材、推进世界时间、结算跨过的每日需求/士气/愿望/事件、建设/制造/居民治疗/NPC 寻回，并永久标记修复；保存成功后才交换内存。
- 拒绝、过期 revision、重复 transaction 或保存失败保持 Profile 指纹、revision、世界时间、材料、队列、人口与 ID 高水位不变；同一 transaction 重放返回幂等成功。
- 制造开始查询按固定顺序应用配方时长、士气、工人/工坊等级，再应用当前基地的已修复独特设施倍率。既有订单冻结开始时的完成时间；迁入、迁出或修复不得追溯修改正在运行的订单。
- schema v31 保存修复事实；v30 及更早档案按内容定义的 `initially_repaired` 初始化，不能根据显示名推断。

## Step 1：内容、状态与迁移

- content v40 为 Greyline storage core 和 Ashworks heavy logistics workshop 声明类型化独特设施参数。
- Greyline 作为接受基线已有的核心能力标记为已修复且制造倍率 100%；Ashworks 初始未修复，使用 15 建材、6 小时和 75% 新制造时长。
- schema v31 往返并显式迁移 v30；Profile 验证检查所有地点状态齐全、未知/缺失地点及定义参数非法。

## Step 2：一次性原子修复

- 新增纯查询 `queryBaseSiteFeatureRepair()` 和命令 `executeBaseSiteFeatureRepair()`，返回材料、劳动力、到达时间与预计效果。
- `GameSession` 在保存成功后提交候选；保存失败不改变内存。
- 区域页显示当前基地独特设施的 `READY / REPAIRABLE / BLOCKED / INACTIVE` 状态、成本、时间与效果，并提供正常鼠标交互；不添加调试或单步验收按钮。

## Step 3：真实制造消费者

- `queryStartBaseManufacturing()` 消费当前主基地、永久修复状态和内容倍率，并在计划/UI 中显示基础时长与地点调整后的最终时长。
- 迁出 Ashworks 后新订单恢复普通时长；回迁后无需重复修复。已经开始的订单保持原完成时间。
- 自动化覆盖 100% 基线、75% Ashworks、迁出/回迁、已有订单冻结和材料/产物守恒。

## 验证与统一验收

自动化覆盖内容坏定义、v30→v31、schema v31 往返、查询纯度、非当前地点、未安装工坊、建材不足、劳动力不足/占用/受伤、成功修复、跨日结算、并行队列推进、重复 transaction、保存失败、迁出/回迁、制造时长冻结和中英文投影。最终运行 Windows Debug 全目标、完整 CTest 和 exact-head Windows/Ubuntu CI。

人工验收：清剿 Ashworks 并建立前哨后，在尚未迁入时确认可预先修复重型工坊；准备材料和空闲健康人口后修复，确认时间与基地日程推进但制造仍保持 Greyline 基线；迁入 Ashworks 后启动制造并确认显示时长缩短；迁回 Greyline 后新订单恢复普通时长；再次迁回 Ashworks 后效果自动恢复；退出重开确认修复事实保存。开发代理不自行启动游戏。
