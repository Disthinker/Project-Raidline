# Base 运营状态与即时枪械维护 v1

## 目标

让食物、卫生、士气支持和安全资源形成可读、非死档的基地运营投影，同时落实用户最新规则：枪械全面维护只支付货币并立即完成，不消耗世界时间、库存医疗物或基地资源。

## 范围

- content v18 保留紧张/充足储备日数阈值，并删除已无消费者的枪匠耗时与运营耗时倍率。
- Domain 只读投影 `Critical / Strained / Stable / Supported`、最短板资源和各项整日储备；查询完全无副作用。
- 枪匠全面维护在同一候选 `ProfileState` 中扣除报价、恢复当前/最大耐久到出厂值并清除故障；武器、枪膛、已装弹匣和 Stash 格位不变。
- 保存成功后才交换内存状态；保存失败或任意拒绝均零修改。
- schema 仍为 v11；显式接受 content v16/v17 存档。旧存档中的计时枪匠任务保留原数据格式，但加载后可立即领取。
- Allocation 与 Supply 页面显示运营档位和短板；枪匠报价明确显示立即完成，中英文共用既有本地化边界。

## 明确不做

- 不把当前 `M` 数值定义成完整版居民士气；人口、床位、生产、自动防守和正式居民恢复继续延期。
- 不让运营档位改变枪匠价格、时间、资格、战斗、Loot、旅行或商品价格；首版运营状态只提供可读风险投影。
- 不删除 schema v10/v11 的旧枪匠任务结构，避免破坏已存在存档。
- 不新增美术、音频或 manifest 修改。

## 领域合同

- 储备日数使用 `当前资源 / 对应每日需求`；少于下一日需求为 `Critical`，少于 3 日为 `Strained`，至少 7 日为 `Supported`，中间为 `Stable`。
- 四项中按精确有理数比例选择最短板；相同比例使用 Food→Hygiene→Morale→Security 的稳定顺序。
- `BaseOperationalProjection` 只读，不进入 Profile、revision、指纹或存档。
- 新维护不得创建 `GunsmithMaintenanceJob`、移动资产、分配任务 ID 或推进世界时间。报价只取决于出厂耐久缺口和 content 价格。
- 旧任务领取不再等待 `completionWorldMinute`；若 Stash 无合法位置则继续由服务位置唯一持有，零修改失败。
- 所有拒绝操作保持 Profile 指纹、货币、稳定 ID、任务高水位、弹药与世界时间不变；TransactionId 重放幂等。

## GDD 映射与冲突

- 对齐用户最新决策：玩家枪械维护是即时货币服务；玩家可自行消耗仓库/背包道具进行其他维护，未来 NPC 治疗才消费时间和库存医疗物。
- 当前运营储备仍是早期投影，不扩张成人口或正式士气模型；长期运营消费者必须等实际设施、人口或生产切片出现。
- 外部 GDD 保持只读；本次行为修订需要同步给策划线程更新旧“计时枪匠服务”描述。

## 验证

- Content：发布值、阈值顺序、正价格及 content v18。
- Domain：四档边界、不同每日消耗的最短板、投影无副作用；维护立即提交、不推进时间、不移动武器、不改变枪膛/弹匣，运营资源不影响报价。
- Failure：资金不足、装备中武器、revision 溢出、保存失败与 Stash 满时旧任务领取均零修改。
- Persistence：schema v11 当前往返、content v16/v17 旧档兼容、既有活动枪匠任务立即可领取。
- UI：中英文运营状态、即时报价与完成反馈；正常游玩无需调试按钮。
