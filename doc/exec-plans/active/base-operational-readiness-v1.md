# Base 运营状态与服务效率 v1

## 目标

让现有食物、卫生、士气支持和安全资源首次产生温和、可读、不会造成死档的实际玩法影响。四项资源按各自每日需求换算可支撑天数，最短项决定基地运营状态；既有枪匠全面维护成为第一个消费者。

## 范围

- content v17 定义紧张/充足的储备日数阈值，以及四档服务耗时百分比。
- Domain 投影 `Critical / Strained / Stable / Supported`、最短板资源、各项整日储备和服务耗时百分比；查询完全无副作用。
- 枪匠报价使用同一投影，将基础 240 分钟调整为 300/276/240/216 分钟；费用不变，任何状态都不关闭服务。
- 开工时把调整后的完成世界分钟冻结进现有任务，之后捐献、每日消耗或愿望完成不会改写进行中的任务。
- Allocation 与 Supply 页面显示运营档位、短板和服务耗时，中英文共用既有本地化边界。
- schema 仍为 v11；显式接受 PR #82 的 `base-periodic-wishes-content-16` 存档并原样迁入 content v17。

## 明确不做

- 不把当前 `M` 数值定义成完整版居民士气。居民士气仍按 GDD 保持低落/稳定/高昂三档与每日原因账本，等待人口和生产消费者。
- 不加入人口、床位、设施、制造、自动防守、睡眠、离队、资源损坏或死亡惩罚。
- 不改变玩家战斗、Raid Loot、伤害、撤离资格、旅行时间、商品价格、维修费用和核心服务可用性。
- 不新增美术、音频或 manifest 修改。

## 领域合同

- 储备日数使用 `当前资源 / 对应每日需求`，不能用统一裸数阈值忽略 8/6/5/4 的不同消耗。
- 少于下一日需求为 `Critical`；少于 3 日为 `Strained`；至少 7 日为 `Supported`；中间为 `Stable`。
- 四项中按精确有理数比例选择最短板；相同比例使用 Food→Hygiene→Morale→Security 的稳定顺序。
- `BaseOperationalProjection` 只读，不进入 Profile、revision、指纹或存档。服务命令只保存已有完成分钟，保证任务开始后的结果稳定。
- 内容加载拒绝颠倒阈值、超过 30 日、非 100% 稳定基线、加速/减速次序颠倒或超过 200% 的配置。
- 所有拒绝操作继续保持 Profile 指纹、货币、稳定 ID 与任务高水位不变。

## GDD 映射与冲突

- 对齐：基地状态应成为长期需求生成器；状态影响应温和且不得导致死档；士气长期可以影响维修速度。
- 暂时妥协：仓库当前已有四项 0～100 资源池，而新版 GDD 将正式居民士气定义为三档隐藏进度，并把首批人口日常需求收敛为口粮与床位。本切片只把四项池解释为早期“运营储备”，不扩张成人口或正式士气模型。
- 外部 GDD 保持只读；未来人口切片必须先决定四项运营储备与口粮/床位/居民士气的迁移关系。

## 验证

- Content：发布值、阈值顺序、稳定基线和耗时倍率非法值。
- Domain：四档边界、不同每日消耗的最短板、精确阈值、投影无副作用。
- Service：默认 240 分钟、危急 300、充足 216、开工后时长冻结、时间溢出与拒绝不变。
- Persistence：schema v11 当前往返、content v16 旧档兼容、既有活动枪匠任务不被重算。
- UI：中英文运营状态、短板与服务耗时；正常游玩无需调试按钮。
