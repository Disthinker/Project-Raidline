## 评审裁决与玩家结果

建议下一片只交付 **少量固定防御位 + 一种木制路障**：平时在建设面板消耗公共建材建造，
选择合法固定位置安装；来袭时改变敌人的接近路线或争取拆障时间，战后修复并再次使用。
不为凑满“1～2种”同时开发沙袋、减速网和木墙三套效果。

有意新增行为是路障阻挡、受损与修复，不称为行为保持型重构。尤其不能用永久无敌的
矩形封路冒充可承受压力的工事，也不能给挡住弹道的矩形贴上“沙袋射击掩护”标签。

本提案确认后，实施按一个完整玩家闭环连续推进，人工验收统一放在最后。
NPC 守军、自由筑墙、塔防、炮塔/陷阱、照明、动态难度重做、第二种工事、新美术和音频均排除。
不恢复 Daily 真实寻路、全局 Session/Persistence 重构或固定步长迁移。

## 当前差距与必须保留的合同

| 当前事实 | 下一片处理 |
| --- | --- |
| `BaseFacilityLayoutState` 每个地点按设施定义只存一个位置，且位置在核心区内 | 不把多件战术工事硬塞成仓库/宿舍，也不开放核心设施任意外围建设 |
| `BaseDefenseRuntime::prepare` 在开战时寻找合法来向，路线与几何写入快照 | 给新规则事件明确固定入口/防御位关联；旧规则事件继续消费自己的冻结路线 |
| `BaseWorld::movementBlockers_` 同时供移动和射击使用 | 第一种路障是实心阻挡，阻挡玩家、敌人与弹道；玩家从侧面射击，不许伪造单向穿透 |
| 防守敌人已有体积感知寻路、刷新预算和安全区掩码 | 复用现有能力；工事损坏只触发有界几何失效，不重建 Enemy roster |
| 接触解析返回玩家伤害及保护语义 | 工事损伤不伪装成 PlayerDamageObservation，也不继承玩家的 0.25 秒无敌间隔 |
| 自动防守只有公共 Security 抽象输入 | 同一工事状态以有界贡献进入自动防守预览与消耗；不建第二套独立工事库存 |
| 预警 / 实时防守禁止安装、移动、收起 | 保留布局冻结；修复不能在交战中瞬间无限恢复，具体阶段见下文 |
| 安全核心不可侵入、个人资产保留、公共软失败有上限 | 完全保留；工事消耗只来自玩家主动建造的工事，不扩大人口或库存失败损失 |

## 产品合同（待按本提案启动）

### 固定位置和建设操作

- 每个已发布主基地地块先配置最多四个候选防御位，按四个来向稳定命名。
  新防守仍至多选择两个来向；四个位置不等于四路同时进攻。
- 位置在核心外的过渡缓冲区，不能与安全核心、世界障碍、设施入口/作业净空、地面资产重叠。
  位置、占地、朝向由地点/地块定义决定，不由每次 Siege seed 或鼠标拖放重新随机。
- 每个位至多一件；地块只发布已验证可用的位置。不可用位置显示原因，不挪动旧设施或玩家物品。
  当前所有发布地块至少保证一条可用来向及一个能实际影响进攻的合法工事位；
  延续原来向上限，不为凑齐四个位重生成 Home Region 或搬动既有设施。
- `B` 建设模式沿用鼠标点击、缩放/平移、购买与已拥有目录、合法/非法虚像和右键菜单。
  工事属于独立目录分类，不另建全屏管理中心；不新增玩家路径导航功能。
- 购买得到一个持久工事实例并进入工事储备，再安装到合法固定位置；不能进入 Stash 或 Raid 背包。
  平时收起/换位不收费、不重置耐久、不退款。迁徙时随既有设施收进储备，不能复制到旧哨所。
- 候选调参：`fortification.wood_barricade`，占地约 `160×48` 世界单位，最大耐久 `120`，
  建造 `8` 公共建材，修复每 `30` 点需 `1` 建材（向上取整）。最终随真实空间门禁微调。
  只消费已转化的 `baseConstruction.materialUnits`，不从 Stash 隐式挑选/吞掉原物品。
- 修复在平时和三分钟预警内允许，消耗先预览；实时交战中本片不提供即时修复。
  损坏到零留下可修复的残架记录，不能通过收起/重放满血；无卖出/拆解返材套利路径。

### 通路、拆障与安全核心

- 安装查询验证完整脚印及全局最低通路；正常玩家通行、设施出入口和防线目标始终可达。
  即使工事完好，也不能把全部来向封成依赖未来破坏才能纠错的死图。
- 第一种工事不提供隔着射击、蹲伏、高低掩体、友伤或护甲数值加成。
  完好时真实阻挡弹道；玩家日常试枪不会损坏自有设施，拆障来自明确的入侵攻击事实。
- 防守目标策略仍在活动内：可见暴露玩家维持既有优先级；否则沿冻结来向接近防线。
  对挡住当前走廊朝防线直达段的近处路障，可选择拆障；不相关或远处工事不抢占目标。
  有可行侧路时允许绕行，不能因为遇到工事全体停住或反复重算路径。
- 拆障只复用既有感染者抓击时序，不对木头执行 Grab→Bite，不产生玩家控制/伤势。
  候选每次已消费的抓击造成 `12` 工事损伤；多敌同帧可以累计，但每次攻击窗口只能消费一次。
- 零耐久只产生一次失效事实，批次后退出碰撞/目标索引，后续敌人继续推进。
  拆障不计算 Enemy 击杀、突破或 Loot，不修改任何 Enemy 稳定身份或存活者位置。
- 拆障的接触/遮挡查询到工事可见表面，仅排除被攻击工事自己的阻挡，不忽略其他墙体。
  碰撞批次变化后只失效受影响路径/目标缓存；源 Enemy 已死或工事已失效的旧攻击不得补发。
- 工事仅改变缓冲区内路线；SafeCore 掩码、防线突破上限、三波数量/节奏、个人弹药与医疗、
  Base 救回、实时软失败与 7/12 日安全期不变。

### 自动防守与有界投入

- 已安装且完好的工事才能参与；储备、零耐久、非本次来向的工事不提供贡献。
- 实时和自动只读取同一实例及耐久状态；自动不偷偷使用另一份满血拷贝。
- 候选自动投影：参与来向上每件耐久不少于 `30` 的工事抵扣 `1` Security，
  总抵扣至多 `2`，原最低需求仍不低于 `8`；只对实际抵扣的工事扣 `30` 耐久。
  无工事时结果与当前自动防守完全相同，不增加个人消耗或失败惩罚。
- 自动确认前展示 Security 与工事磨损，确认/重试由同一事件幂等提交。
  来向与参与集合必须冻结，不能重开页面抽取更优位置，也不能只预览收益不承担磨损。
- 这是首片抽象贡献，不是完整实时结果预测；不调整敌人 HP、伤害、装备或奖励倍率。

## 技术边界与所有权

建议按消费者引入下列窄类型，名称在实施时可按现有代码规范调整：

- `FortificationDefinitionId`：不可变内容 ID；`DefenseSlotKey`：地点 + 地块 + 固定 slot。
- `FortificationInstanceId`：独立设施身份，复用项目强类型/单调高水位模式。
  不是第二个 Enemy ID，也不能借 vector index 或临时 BallisticBlockerId 表示永久身份。
- `BaseFortificationState`：Profile 唯一持有实例、当前位置（储备或 slot）、耐久及高水位。
  不冒充可背走的 ItemInstance，不按 DefinitionId 限制全基地只能有一件。
- `queryFortificationCommand` / command receipt：购买、安装、收起、修复/迁徙收纳的原子结果。
  command 只传稳定身份和意图；几何、费用和资格由领域/模拟查询验证，App 不能提交任意障碍矩形。
- `FortificationRuntime`：防守内部的工事目标、损伤与失效小组件，不拥有 Enemy、导航、保存器或奖励。
  `BaseDefenseRuntime` 组合它与既有 EnemyRoster，继续保持 mechanism / policy 分离。
- `FortificationDamageFact` / `FortificationDisabledFact`：来源 Enemy 稳定 ID、工事实例 ID、
  已消费攻击和明确损伤；绝不复用 EnemyRemovalFact 制造假死亡。
- 只在真实重复出现时提取不含玩家保护/伤势的接触消费小函数，并由原三环境合同与工事适配器验证。
  不创建通用目标总管或把 GameSession 扩展成逐敌攻击处理器。

活动期间工事运行状态是同一 Profile 工事状态的受控活动签出，与 Enemy 检查点一起冻结。
日常工事写命令在 activeDefense 期间拒绝；检查点一次写回同一实例记录，不存在两份可独立提交的 HP。
结束或恢复时按稳定实例 ID 校验合并；Session 只处理已验证的工事 delta、资源与活动结果。

### 快照与迁移

- 新结构确有持久消费者时才升级，不在本轮文档 PR 修改任何 schema。
  预计下一实现使用 schema **v47**、content **v61**、Base Defense rules **v2**；Raid rules 仍 v29。
  若启动前基线变化，按当时最新已接受版本顺序迁移，不抢占版本号。
- v46 迁移为空工事状态，保留旧资产、高水位、威胁、地点与活动，不免费生成工事。
- 旧 activeDefense rules v1 按原碰撞、路线、弹道与敌人恢复；不把新 slot 或工事混入旧事件。
  已处于旧三分钟预警的存档也继续本次旧规则，下一事件才采用新准备合同。
- v2 在预警开始时冻结候选来向/slot 身份与几何；修复可更新耐久，不改变来向或布局。
  开战/自动确认冻结本次实际耐久和参与集合；读档不按新内容重选位置或重抽来向。
  新随机流以 ProfileId、siegeSequence、地点和布局身份确定，不以当下库存指纹重新抽签。
- 碰撞变化用显式 geometry revision + 工事状态表达；immutable layout hash 不应被当成每帧 HP hash。
  零耐久撤除阻挡后的导航/索引必须与同一检查点一致，恢复不得再挡路或重新满血。
- 沿现有 250ms 合批检查点与 >1000ms 未持久暂停保护；不逐次拆障同步写整档。
  开始/结束/正常退出仍持久化屏障；坏引用、重复 slot/实例、非法耐久/高水位均拒绝。

## 实施顺序与 PR 边界

先确认此产品评审，再从最新已接受 `origin/main` 建 `codex/base-defense-fixed-positions-v1`。
若本评审尚未合入，明确带入已确认计划文本，不从未合并的其他功能分支隐式叠加。
一个完整宏切片 / 一个 Draft PR，内部分四个可回滚提交，不让用户逐按钮分次验收：

1. **固定位置与建造持久化**：slot、工事定义/实例、购买/安装/收起/修复、现有 B 面板及双语文字。
   退出：所有当前地块的合法位置/通路通过，拒绝操作零修改，v46/v47 往返；中间提交不单独发布，
   整片交付前目录不出售未接入战斗的成品。
2. **真实阻挡与受损**：实时防守按稳定目标选择绕行/拆障，单次损伤/失效、几何索引更新。
   退出：实体/弹道一致，三活动 EnemyLifecycle 合同不退化；无全体停滞或死亡复活。
3. **两种防守与恢复一致性**：新预警准备快照、自动贡献/磨损、同场恢复、旧事件保留、迁徙储备。
   退出：重复结算/保存失败/强退均不复制工事、返还磨损或丢失个人资产。
4. **整体回归与正常游玩**：全部自动化、双平台 exact-head CI，再交由用户完整试玩。
   不为完成计划追加 NPC、防御塔、自由筑墙或专门验收按钮。

若为上述消费者产生的大范围基础框架改动超过可审查边界，暂停实现并说明实际差距；
不能以“已规划”作为继续重写 Navigation/Session/Persistence 的理由。

## 门禁、验收与回滚

自动化至少覆盖：

- 所有当前地点 / 开局地块：slot 确定性、脚印与射线、重叠/净空拒绝、合法来向不被封死和核心保护。
- 购买/安装/收起/换位/修复/迁徙：唯一位置、高水位、重复事务、过期 revision、材料不足及保存失败零修改。
- 同帧多敌打工事但单个攻击只消费一次；死敌不能拆障，已失效工事不能成为目标；失效一次，
  首/中/尾对象移除保持其他身份与位置。敌人转打玩家时仍满足原接触保护与帧顺序。
- 开放路、绕障路、零耐久缺口、贴墙、核心旁连射；旧无工事行为、新旧规则事件与三环境真实适配器回归。
- 自动前后预览一致、磨损有界、零贡献零磨损、同 Siege 不得自动/实时各结算一次。
- 正常退出/异常退出/损坏档备份/同场恢复、旧 v46 活动与预警、Raid pending 不重抽。
- Windows Debug 全量至少保持当前 1697 项注册测试并新增合同；Windows/Ubuntu exact-head CI。
  继续原最慢模拟子步 <25ms、防守检查点复制 P95≤4ms/P99≤8ms 等门禁。
  增加最多四件工事同时失效、16 名防守敌人、约1000障碍场景；不得放宽阈值或重建全部敌人。

正常游玩集中验证：

1. 平时打开 B，建造/安装一个路障，缩放平移后仍能正确选中；尝试非法位置并收起重装。
2. 一场亲自防守：从侧面射击，观察敌人绕行/拆障、缺口打开和继续推进；安全核心仍受保护。
3. 保存退出再继续同一场，确认路障损伤、敌人死亡与真实弹药同步；战后用公共建材修复。
4. 后续自动防守确认工事贡献/磨损；再进行 Raid、回营及迁徙，检查物品与工事实例不复制。

开发代理不启动游戏；不要求玩家逐个测试故障注入或进行精确帧操作。
本评审文档可独立普通 revert，无运行影响。未来代码回滚按逆序普通 revert，并使用升级前另存的 v46
备份；已经升级到 v47 的滚动安全备份不是旧版本可读保证。不强推或通过读旧档刷回消耗。
