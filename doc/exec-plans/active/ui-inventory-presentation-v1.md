## 旧档怎样无损过渡

独立页与“所有旧坐标完全不动”无法同时覆盖已有跨页物品。本方案只调整必须迁移的跨页物品，不自动整理整仓，不读取或改写用户真实存档进行开发测试。

1. 原本完整落在某页内的物品保持原位置。
2. 对跨页物品，按稳定物品ID依次处理，先尝试原页的完整空位，再找其他页；不自动旋转、拆堆或改变物品状态。
3. 放不下的旧物保存在「旧档待整理」领取区。它只持有本次迁移剩余物品，禁止放入新物品，不增设普通仓库页；整理完成后入口消失。它不能用于Raid收纳。旧的20×12返还区保持原合同，不能假定其必有足够空位。
4. 迁移保留全部物品ID、数量、状态、安装件和容器内物品；原档先留备份，迁移结果验证及原子保存成功后才启用。重复读取不得重复迁移或复制物品。
5. 若旧档有未结算Raid，先按原规则恢复出击前状态，再迁移仓库布局。失败时保持磁盘原档和当前运行状态，不提交半份新布局。

「旧档待整理」是有限的旧数据兼容安排，会临时保留六页暂时放不下的旧物，不是新增可反复使用的收纳容量。它不接受新入库、结算、购买或制造输出。对正常仓库因分区而出现的“总空格够、但没有完整空位”，沿用明确拒绝与零修改，不把物品强塞进待整理区。

## 已确认的原因与开发范围

当前v1将24×16仓库视作连续空间。`src/profile_container_presentation.cpp`的viewport、pan和reveal只是显示窗口；`src/profile_state.cpp`的placementFits／findFirstProfileFit以及`src/inventory_domain.cpp`目前只验证整体容器边界，没有8×8页边界。因此只改App绘制或红框不能实现可靠隔离。

采用最小兼容方案：内部继续使用既有仓库坐标和资产身份，把六个固定8×8区域作为不可跨越的存储边界。页面隔离由领域层统一判断，既用于手动移动／旋转／交换，也用于自动查找空位与最终Profile校验。自动入库按第1–6页依次寻找完整空位；App只显示查询结果。

让仓库更容易浏览，让物品信息和装备图片看得清楚。**当前仅完成策划和代码核查，待用户批准 `RL-UI-INVENTORY-PRESENTATION-v1` 后实施。** 本文中的新界面、按钮名称和操作均为方案，尚未出现在游戏中。

## 1. 具体界面与操作

### 分页只改变视窗

仓库仍是一个连续容器。六页按从左到右、从上到下编号：第一页对应原坐标列0–7、行0–7；第二页列8–15；第三页列16–23；第四至六页对应行8–15。翻页不移动资产，不更新库存版本，也不写入存档。

提供页码、上一页、下一页及禁用状态。每页显示64个真实格位，不通过增加空白格扩容。当前位置、容器名称和页码要始终可见。

旧返还区在有内容时提供独立入口，保持20×12容量，不再挤在仓库下方并缩小格子。外部箱子和尸体沿用原容器与分区；超出视窗的分区分页，余页超出真实容量的格位禁用。10×8储物箱仍能访问全部80格，不能为了8列界面裁掉容量。

### 跨页长物品能完整查看、整件移动

页边界不是新的放置限制。旧存档中跨页的大物品保留原坐标，新的合法落点也可以跨页。

- 普通页显示与视窗相交的物品，边缘给出延续标记。图片先按完整占格等比适配，再由视窗裁剪；不把整张图压缩到露出的几个格子里。
- 从任何可见占格都能右键查看或拖动同一整件物品。抓取偏移使用真实格位，不能把可见片段误认为物品原点。
- 悬停给出完整图片与信息预览。普通点击跨页物品并松开后，视窗按格平移到能容纳整件的位置，显示“整件定位／返回原页”。按下瞬间不平移，避免干扰拖拽。
- 滚轮纵向、Shift＋滚轮横向平移鼠标所在网格；页码按钮恢复规则分页位置。视窗原点限制在真实容器内。页码按视窗原点所属规则页显示，偏移时注明“定位中”。
- “物品所在页”统一按资产真实原点计算。当前最大物品及合法旋转均须在定位视窗中完整显示。

### 大格子的版面

继续使用已验收1280×720逻辑画布和三档窗口映射，不把窗口缩放重复乘入格子尺寸。

| 区域 | 布局合同 |
| --- | --- |
| 左侧个人区 | 约576像素网格宽，顶部固定“装备／胸挂／背包”标签。 |
| 装备标签 | 保留角色预览及全部8个装备槽；角色在左、槽位在右两列四行，图片按槽内空间等比适配，标签不覆盖图片。 |
| 胸挂／背包标签 | 最大9列×8行的64像素格视窗。9×6远征背包完整显示；胸挂保留每个真实口袋和标签，超长布局滚动。 |
| 右侧容器区 | 8×8格，网格约512×512像素；标题与分页栏在上方，快捷操作提示在下方。 |

只有基地合法上下文显示仓库；Raid继续只显示当前获准打开的箱子或尸体。个人标签、容器页码、定位及滚动状态属于本次客户端会话，关闭或切换Profile时清理，不写入Profile。重新打开已有页面可以保留会话选项，但必须校正到当前有效容量。

物品名称、数量和耐久按优先级排布，实测文字宽度后省略过长名称，悬停展示全文；不靠再次缩小字体塞入。沿用现有字体、深色面板、按钮和悬停反馈，本项不重做整套视觉风格。

### 拖拽、快捷转移与菜单

1. 拖拽期间按PageUp／PageDown切换目标侧页面；鼠标所在网格决定目标侧，未指向网格时沿用最后目标侧。首尾页不循环。
2. 翻页或切标签保留源实例、真实源位置、抓取偏移、旋转与Ctrl／Shift锁定数量。原物仍在源容器，合法放手才提交一次事务。
3. 拖拽悬停左侧标签约350毫秒切换；不增加边缘自动翻页。完整落点占格继续交给现有库存查询，不能只检查画面内部分。
4. Esc先取消拖拽且资产零修改，同一次按键不继续关闭页面。Tab、Esc及原有数量锁定、旋转、合并、交换和非法落点规则保留。
5. F及现有快捷转移继续枚举整个合法目标容器，包括隐藏标签中的胸挂口袋和背包。保持现有选择顺序，不能只搜索当前页。
6. 转移到不可见位置时提示实际容器和“第N页”，提供定位入口，不强制跳页。成功、合并、交换或拒绝提示来自实际事务结果。
7. 翻页关闭绑定旧屏幕位置的右键菜单，重新计算悬停与命中。保留详情／改装。详情或数量模态界面打开时，不把翻页输入传给其下方容器。

### 图片保持原比例

以纹理原始宽高计算适配矩形，90／270度旋转交换显示宽高，统一居中并留边。完整展示区域内不拉伸、不裁切图片；跨页视窗边缘的裁剪仅用于显示连续容器，不改变图片比例。

物品完整占格、点击区域、选中边框、数量和耐久仍独立存在，不能跟随图像轮廓缩小。透明虚像保留正确透明度，失败绘制不能污染后续纹理状态。

不修改PNG、不裁透明边、不更换批准素材。素材自身留白可能仍使图片偏小，作为素材问题记录，不靠拉伸补偿。变更只进入库存物品展示路径，角色、世界武器及其他共用绘制路径保持现有行为。
