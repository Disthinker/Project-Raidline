## 1. 玩家结果

玩家能在 Base 将基础头盔与基础护甲作为真实资产穿戴，在 Raid 中由它们分别保护头部与躯干。射击敌人时，命中位置稳定解析为头、躯干或腿；爆头与弱点由领域结果驱动专用反馈，普通命中不显示准星 X。防具只有实际降低伤害时才损失耐久，归零后保留实例与装备位置但失去防护。

本切片形成第一个完整版配装取舍：额外防护会改变可承受伤害和资产风险，但不会提前引入整套伤势、维修或弹种系统。

## 2. 领域合同与所有权

- `HitRegion` 只包含 Head、Torso、Legs；手臂暂并入 Torso，不建立部位独立 HP。
- `HitSemantic` 明确 Normal、Headshot、WeakPoint。App 只能消费该结果，不从碰撞坐标、敌人名称或颜色猜测。
- 基线倍率为 Head 2.0、Torso 1.0、Legs 0.75；弱点额外 1.5。最终伤害使用全局 HP。
- 护甲穿透为确定性减伤：达到防护需求时完整伤害；不足时按穿透/需求比例保留伤害，最低 10%。
- 头盔只覆盖 Head，护甲只覆盖 Torso。未覆盖、零耐久或未产生减伤时不损失耐久。
- `AssetRegistry` 继续唯一拥有防具实例；实例保存出厂最大、当前最大与当前耐久。本切片不提供维修命令，但保存完整状态供后续消费者使用。
- 命中查询纯函数返回最终伤害、语义、护甲是否减伤及耐久损失。服务层在重验 Profile revision 后原子提交 HP 与耐久。

## 3. 内容与界面

- 新增 Helmet、BodyArmor 两个装备槽与 ProtectiveGear 类别。
- 新增一个基础头盔和一个基础护甲定义；在正式美术恢复前使用既有未发布资源占位表现，不生成资源、不修改美术 manifest。
- Base/Raid 个人页显示五个活跃槽；拖拽、快速装备、卸下、保存和失败结算复用现有库存领域。
- 新存档与固定供应提供基础防具测试入口；具体价格属于本切片平衡数据，不改变救济最低出击能力。
- 反馈只使用代码表现：爆头/弱点可读、护甲实际减伤可读；不加入伤害数字、精确护甲等级或普通准星 X。

## 4. 明确排除

- 流血、疼痛、骨折、内伤、夹板、手术和复杂医疗。
- 护甲维修物、Raid 维修动作、NPC 维修、最大耐久永久损失的实际操作入口。
- 特殊弹、混装弹扩展、生物贯穿、场景贯穿、硬直深化、击退、断肢和碎块。
- 武器耐久、故障、清障、组件、改枪台、战术电子、照明和新地图。
- 正式美术、音频、runtime 资源发布及 manifest 修改。

## 5. 实施顺序

1. 纯领域伤害解析与拒绝不变测试。
2. 内容定义、两装备槽、防具实例耐久、Profile 校验与 schema v3 迁移。
3. 库存/配装/快速装备和五槽 UI。
4. Raid 敌我命中解析、HP/耐久原子提交及 HitResult 投影。
5. 代码反馈、完整回归、CI 与用户正常游玩验收。

## 6. 自动化与人工门槛

- 领域：三部位倍率、弱点、覆盖、穿透充足/不足、10% 下限、零耐久、仅实际减伤磨损和非法输入零结果。
- 资产：两槽原子装备/卸下、占用拒绝、失败指纹不变、死亡全损、成功保留、高水位不回退。
- 存档：schema v3 往返、v1/v2 迁移、损坏主档恢复、未知防具定义和非法耐久拒绝。
- Raid：头/躯干/腿命中，头盔/护甲减伤，耐久归零后的下一击，无甲爆头与护甲命中反馈。
- 交付：Windows Debug 全目标、focused、全量 CTest、exact-head Windows/Ubuntu CI。
- 人工验收最后由用户正常游玩完成；开发代理不启动游戏。
