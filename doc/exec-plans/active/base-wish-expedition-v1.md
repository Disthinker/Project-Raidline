## 玩家结果与排除

在 Allocation 选择/取消一个未完成愿望为当前关注；出击口按真实 Loot 来源和合法物资情报展示各地图资源相关性。Deploy 冻结关注，成功结算只读统计真实随身资产的件数与贡献。返回后可过滤相关资产，但仍手动选择并用 PR #145 事务提交。跨周期显示原愿望已结束，物品保持原位置和完整所有权。

不改变 Loot、随机流、敌人、危机、撤离或任何奖励；不增加任务板、HUD 目标、导航、自动捐献、新物品/地图/设施/美术/音频。Home Region 外围不进入 Raid 生命周期。

## 架构与兼容合同

- 复用 BasePriority、AssetRegistry、情报归档/消耗、Loot 表、Deploy/Settlement、Allocation 和现有战术地图。
- 愿望实例身份使用 `cycleIndex + BasePriorityDefinitionId`，不以 UI 索引或显示名存储。当前关注由 Profile 的 BasePriorityState 持有，周期轮换/完成清除；Raid 出发前快照自然保存其回滚状态。
- 新 SDL-free `base_wish_expedition` 模块提供关注查询/原子命令、地图相关性、冻结值和带回统计。GameSession 负责候选保存，App 只消费投影。
- 相关性来自地图关联 Loot 表的正贡献权重占比：至少 50% 高、20% 中、正值低、零值无已知来源。无已拥有 Resource 情报先返回 Unknown，不提供内部表/点位/实际抽取信息。
- Raid 只保存关注实例、类别/门槛和研判版本；不复制物品。成功统计一次遍历唯一 Registry 的合法随身资产，数量按 quantity，子资产各计一次，不递归重复。失败为零，重复 Settlement 复用历史结果。
- schema v44 增加可选关注、pending 冻结关注与结果摘要；v43 及更早均迁移为空。不改变 content v59 或 rules v29，不重抽旧 pending Raid。非法引用拒绝加载；正常轮换清除。
- 战术地图只在已冻结 Resource 权限下复用现有模糊资源表达；不向无情报投影泄露目标点，不增加精确导航。

## 自动化与游玩验收

覆盖关注有效/取消/过期/重复事务/保存失败，未知或无来源与不同权重层级，查询指纹不变；同 seed 关注不改变地图/敌人/Loot；成功/失败统计、容器树不重复、跨周期失效、重复结算、v43迁移/v44往返/旧pending回滚、中文文本及全量性能回归。

用户从基地选择关注，查看有无物资情报的地图差异，正常出击/搜刮/撤离，核对结果贡献与原位置物品，再过滤并手动提交；另做一次失败和跨周期返回。无须调试按钮，开发代理不启动游戏。

## 风险与回滚

信息泄露通过领域入口先检查权限阻断；偏置 Loot 通过同 seed 对照测试阻断；资产统计仅生成数值不移动物品。当前关注不是任务状态。一个 PR 完整交付，后续功能不叠加。回滚代码前保留升级前 v43 安全备份，v44 不承诺被旧程序读取；不覆盖用户主档以验证迁移。
