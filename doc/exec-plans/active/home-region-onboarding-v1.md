# Home Region 新档起步与首次整备 v1

## 产品结果、基线与范围

本切片把已经完成的 Content Beta 成长链真正应用到普通新档。新玩家不再开局获得全部发布武器、弹药与装备，而是从一套有限但可出击的基础物资开始，在现有安全 Base 中依次找到仓储、完成轻型搜刮职责所需的装备与随身供弹，并前往 Raid Gate。已有档案不删除、不降级、不移动任何资产。

依赖基线为已通过用户正常游玩验收并合入的 PR #120，`origin/main@f48b954`。分支为 `codex/home-region-onboarding-v1`。这是 `Home Region & Onboarding Vertical Slice` 的首个玩家结果，不建立新地图主题、初始基地三选一或叙事角色系统。

明确排除：独立教学关、强制锁门、长对话、自动配装、赠送高级装备、第二地图主题、Tiled 转换器、正式美术/动画/P1 音频、AI 队友、实时守城、初始基地地点选择和剧情任务面板。

## 领域、迁移与开发工具合同

- 普通 `startNewProfile` 使用当前有限 starter profile：基础步枪/手枪、对应弹匣与普通弹药、小型胸挂/背包、基础防具、医疗和维护物；资产以真实实例进入 Stash，角色不预先穿戴。
- 不从任何已存在档案移除全目录资产。已完成 `bootstrap.warehouse_catalog.content_54` 的开发档案保持原样；旧 content v53 开发目录档案仍可通过原有幂等迁移补齐 v54 内容。
- 完整发布目录不再是普通新档副作用。新增显式开发者目录命令，只在 Base 且无 pending Raid 时运行，以独立事务 ID 原子填满每个已发布定义；重放不重复，空间不足和保存失败均零修改。
- F10 运行时开发面板扩展到 Base/Raid。Base 中可点击 `GRANT PUBLISHED CATALOG`；Raid 中继续保留武器调参、迷雾、无限弹药和高危工具。开发目录会写入当前开发档案，因此按钮和结果明确标注开发用途。
- schema 保持 v38，content 升至 v57，rules 保持 v29；轻型职责显式接受普通新档已有的基础护甲与轻甲，新增事务事实使用已有 `committedTransactions`，不新增保存字段。

## 首次整备合同

- 环境目标链继续非强制：`找到仓储 -> 完成轻型搜刮职责 -> 找到出击口 -> 完成`。玩家随时可以自由移动、使用其他设施或以不满足职责的配装出击。
- `PrepareLoadout` 不再只检查任意武器，而是消费稳定 `loadout_archetype.light_scavenger` 的只读 `LoadoutReadinessProjection`：合法武器、至少 30 发真实随身兼容弹药、躯干防具、胸挂和背包全部满足后才前进。
- 目标文本显示当前缺口与兼容弹药数量；UI 不按显示名、颜色或格位猜测准备度。
- 领域查询不修改 Profile。库存命令成功后刷新目标；拒绝、保存失败或只把弹药留在 Stash 均不能错误推进。

## 自动化、人工验收与回滚

- 新档测试：只含 starter 定义和有限数量，不含高级 DMR/LMG、重型防具或远征背包；目录事务标记存在但不造成隐式全目录发放。
- 旧档测试：content v53 目录档案仍幂等补齐；content v54/v55/v56 档案资产、revision 和高水位不因加载而变化；v57 不重抽旧 Raid 或改写已有资产。
- 开发目录测试：Base 成功、重复、容量不足、pending Raid、保存失败全部覆盖资产唯一所有权和零修改边界。
- 教学测试：只有 Stash 弹药、缺胸挂/背包/防具、错口径均保持 `PrepareLoadout`；完整轻型职责才前进。
- 完成聚焦测试、Windows Debug 全目标、完整 CTest 和 exact-head Windows/Ubuntu CI 后，由用户以正常新档完成一次“仓储—整备—出击”，并在另一个开发档案验证 F10 目录按钮。

风险是破坏依赖全目录新档的旧自动化、把开发目录误作发行奖励、或让教学变成强制门禁。通过区分 `makeNewAlphaProfile` 与显式开发事务、保留旧迁移、只读准备度和非阻塞目标控制。回滚使用普通 revert；不得删除已有实例或重写旧事务历史。
