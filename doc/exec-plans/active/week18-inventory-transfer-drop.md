## 范围

本计划包含：

- 玩家背包与一个 6×6 第二 `GridInventory` 之间的指定位置转移。
- 核心层首个可用位置转移能力及其确定性测试，为后续搜刮逻辑复用。
- 玩家背包物品丢弃为 `GroundItem`，位置在角色逻辑碰撞体的脚底中心并限制在世界边界内，与角色朝向无关。
- 双容器鼠标命中、拖拽预览、合法性提示和明确的丢弃区域。
- 一个代码绘制的世界柜子实体、近距离 F 交互和“普通背包/柜子容器”视图门控。
- 贴住屏幕右边缘的半透明竖向丢弃条；为后续垃圾桶图标保留替换位置。
- 指针手势结束或取消后清除选中状态；空闲指针不绘制 hover 或持久蓝框。
- 删除背包方向键/Enter 行为、黄色键盘焦点、键盘放置模式和界面提示。
- 自动测试、文档、问题台账和人工验收记录。

本计划明确不包含：

- 自动生成第二容器战利品、拾取地面物品或完整搜刮生命周期。
- 柜子碰撞阻挡、开门动画、搜索计时和正式柜子/垃圾桶美术资源。
- 堆叠、旋转、拆分、数量系统、持久化或网络同步。
- 大规模重写 `App` 或改变 `GridInventory` 的总体存储结构。
- 把任意网格外释放解释为丢弃；只有明确丢弃区域接受丢弃。

## 交互契约

- Tab 只打开玩家 10×6 背包；不会显示或命中第二容器。
- 角色进入柜子交互范围并按 F 时打开玩家背包与右侧 6×6 柜子容器；该次 F 不再同时拾取地面物品。
- 柜子是世界中可见、可交互但暂不阻挡移动的实体；靠近时显示交互提示。
- 网格内拖动使用抓取偏移确定预览原点，物品虚像跟随鼠标平滑移动。
- 释放到同一容器的合法位置调用 `tryMove`；释放到另一容器的合法位置执行跨容器事务式转移。
- 玩家背包中的物品可释放到贴住屏幕右边缘、贯穿大部分高度的半透明 `DROP` 长条。
- 第二容器物品不能直接丢弃，必须先转入玩家背包。
- 释放到其他空白或窗口外仍然取消，不产生所有权变化。
- Tab 关闭优先于 Esc 取消，二者都优先于同帧鼠标释放；关闭/取消帧不得提交移动、转移或丢弃。
- 方向键、主键盘 Enter 和数字键盘 Enter 在背包中均无库存语义；Tab 和 Esc 保留。
- Idle 状态不绘制 hover/选中轮廓；Pressed/Dragging 可继续显示操作中的候选与虚像，release/Esc/Tab 后清除手势选择。

## 类型、调用路径与所有权

- 新增 `inventory_transfer.{h,cpp}`，提供无副作用查询和事务命令。源容器在提交时移出 `ItemInstance`，目标放置失败或抛出时恢复原容器原位置。
- `InventoryContainerId` 标识玩家/第二容器；拖拽状态保存源容器、稳定 ID、真实源原点、抓取偏移和当前目标。
- 指针释放产生带源/目标容器的放置请求或玩家物品丢弃请求，`App` 负责调用领域 API。
- `GameplayWorld` 新增第二容器所有权，并封装玩家物品到 `groundItems_` 的丢弃提交。
- 新增 `StorageCabinet` 世界实体并让它拥有第二 `GridInventory`；`GameplayWorld` 只转发受控库存访问与近距离交互查询。
- `InventoryOverlayState` 区分 Closed、PlayerOnly 与 Container，防止普通 Tab 路径意外暴露外部容器。
- `GroundItem` 继续唯一拥有丢弃后的 `ItemInstance`；任何稳定 ID 不得同时存在于两个库存或库存与地面中。

## 必须维护或新增的不变量

- `ItemInstance` 始终只有一个所有者；失败转移/失败丢弃不消耗物品。
- 跨容器转移成功保持稳定 ID 和 `ItemDefinition` 不变；失败时两个容器在占位、顺序和所有权上均不变。
- 转移前验证目标边界、碰撞和重复稳定 ID；同一容器不得走跨容器 API。
- 丢弃仅来自玩家背包；成功后玩家足迹完全清除且地面新增同一稳定 ID。
- 输入状态保存稳定 ID，不保存可能因 `vector` 重分配而失效的业务对象引用或指针。
- Esc/Tab 同帧仲裁继续满足 `doc/architecture/INVARIANTS.md` 的取消优先语义。

## 风险、替代方案与失败语义

- 最大风险是跨两个 `GridInventory` 的异常安全。采用“完整预检 → 目标预留/准备 → 移出 → 放入 → 失败恢复原位置”，并以双容器快照测试验证。
- `GridInventory` 暂无通用事务对象；本切片使用窄服务函数，避免提前引入大规模架构。
- 世界丢弃在移出库存前为 `groundItems_` 预留容量，并让提交后的构造路径不抛出；预留失败保持库存不变。
- 若发现现有 `GridInventory` 无法保证恢复路径，将暂停窗口接线，先修正领域接口并记录偏差。
- 回滚本功能时删除新增服务、第二容器和 UI 路由即可；不修改物品序列化格式或远端历史。

## 发现记录

- Week16 文档已预期多容器转移应使用独立事务服务，而不是把跨所有权逻辑塞入 `GridInventory::tryMove`。
- 当前 64 像素格尺寸下，10×6 与 6×6 面板可以并排放入 1280×720 逻辑画布，并在下方保留丢弃区。
- `GridInventory::remove` 会移动并擦除元素；任何交互状态都必须依赖稳定 ID，而不能缓存对象地址。
- MSVC 的 `/showIncludes` 让增量构建日志很长，但实际本轮全目标构建只需要补编译变更目标；测试执行约数秒。

- 2026-08-07：UI 仅暴露指定格拖放；首个可用位置转移保留为核心 API 和测试能力，供后续搜刮快捷操作使用。
