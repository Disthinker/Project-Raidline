# Home Region 核心设施空间化与持久布局 v1 ExecPlan

状态：已完成。PR #132 通过 Windows Debug 全目标、226/226 定向测试、1396/1396 完整 CTest、exact-head Windows/Ubuntu CI 与用户正常游玩验收，并以 merge commit `0b5be88` 进入 main。

## 玩家结果与依赖

玩家可在基地建设模式中选择仓库、医疗所、宿舍或工坊，通过“移动设施”进入绿/红虚像放置，并把核心设施调整到基地板块内的合法位置。移动后设施的碰撞、世界表现、运营定位和功能入口立即使用新位置；重启游戏后位置保持。不同主基地地点各自保存独立布局，迁徙不会覆盖原地点的设施安排。

本切片依赖既有建设镜头、统一设施管理、快速操作、运营总览与完成通知，不改变这些设施的等级、人员、队列、功能规则或资源消耗。供应、物资分配和 Raid 出击口继续作为站点固定基础设施，不提供移动或回收。

## 领域、存档与客户端合同

- `ProfileState::baseFacilityLayout` 以稳定 `RegionalBaseSiteDefinitionId → BaseFacilityDefinitionId → normalized center` 唯一保存空间事实；世界坐标由当前站点的 Base parcel 投影，不把 SDL 坐标或显示文本写入存档。
- 当前空间化设施固定为仓库、医疗所、宿舍和工坊。每个已发布基地站点必须恰有这四个定义；未知、重复、缺失、非有限或越界的布局拒绝加载。
- `queryBaseFacilityLayout` 是纯查询；`executeBaseFacilityLayout` 重验 ProfileRevision、事务 ID、安装状态、站点、Base parcel、玩家、环境、地面资产与其他设施阻挡。拒绝、过期版本和保存失败保持 Profile 指纹不变。
- schema v40 保存完整站点布局。schema v39 及更早存档按旧可见坐标确定性补齐所有已发布站点，不重排资产、不改变当前基地或推进时间。
- `BaseWorld` 只消费 Profile 投影覆盖位置并重建既有碰撞索引；不拥有长期布局。运营总览、完成标记和功能交互继续查询同一 BaseWorld 设施位置。
- App 复用建设镜头、缩放、世界—屏幕投影和鼠标输入仲裁。虚像只表达领域查询结果；左键提交，Esc 取消，非法位置为红色，合法位置为绿色。新增提示全部提供中英文。

## 验证与人工验收

自动化覆盖纯查询零修改、成功提交、事务幂等、过期版本、储备设施、越界/阻挡拒绝、所有基地站点默认布局、BaseWorld 覆盖位置与碰撞索引、schema v40 往返、schema v39 迁移、跨进程持久化和保存失败零提交。完成 Windows Debug 全目标、定向测试、完整 CTest 与 exact-head Windows/Ubuntu CI 后交给用户正常游玩验收；Codex 不启动游戏。

人工验收：在基地按 `B`，分别通过管理卡片或右键菜单移动仓库、医疗所、宿舍和工坊；确认虚像在合法位置为绿色、与建筑/设施/储物箱/玩家重叠或越界时为红色。放置后确认角色和子弹碰撞使用新位置、右键和管理卡片仍能打开真实功能、运营总览能定位新位置。退出到主菜单或桌面并重开，确认位置保持。供应、分配和出击口不应出现移动入口。若已解锁基地迁徙，可往返两个地点确认布局互不覆盖。

回滚采用普通 revert。回滚代码后 schema v40 存档不能由旧主线读取，因此若该 PR 尚未合入只需关闭分支；若已发布则必须先保留 v40 读取兼容或提供前向迁移，不可直接删除字段。
