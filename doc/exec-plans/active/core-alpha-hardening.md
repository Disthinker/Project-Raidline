# Core Extraction Alpha：Hardening ExecPlan

## 1. 产品结果与完成定义

本宏切片把已经接受的 Persistent Base 与 Extraction Loop 收束为可长期反复运行的 Core Extraction Alpha 候选版。除稳定性、恢复一致性、内容合同、连续多局与发布证据外，还收束用户验收发现的库存交互和角色显示回归；这属于已承诺 Alpha 能力的可玩性修复，不扩大系统范围。

完成门槛：

- 连续 10 次混合成功/失败 Raid 及至少 3 次跨进程重载后，Profile、资产 ID 高水位、所有权、弹药、货币和 Settlement 仍合法且无重复提交。
- 主档/备份的有效、缺失、损坏及旧 pending Raid 组合均有确定结果；新 Raid 在磁盘保留精确出击前 Profile，关闭程序后无损回滚，旧 pending 存档也迁回 Base 而不执行全损。
- 最低出击能力查询统计散装、弹匣和枪膛中的兼容弹药，不误发救济；救济资产的来源标签在拆分、压弹、卸弹和失败结算中保持。
- Alpha 固定供应满足 25% 向下取整且最低 1 的回收基线，所有当前可达购买/拆分/压卸弹/回收路径无正收益。
- 三组出生/撤离和三组敌人部署均可由稳定 seed 选中；6～9 个 Loot 快照覆盖中央、外围和资源路线，保存重载不重抽。
- focused、全量 CTest、Windows/Ubuntu exact-head CI 通过；最后由用户执行集中真实窗口验收，开发代理不启动游戏。
- Base 与 Raid 共用同一按住拖拽内核和领域预览；正常游玩即可完成整理、配装、局内外压弹、装匣、指定换弹、Raid 弹匣卸弹和治疗，并支持 Shift 奔跑，不存在只为验收设置的动作按钮。

## 2. 基线、依赖与排除

- 基线：`origin/main@ed45baa`，PR #59 已通过自动化与用户 7/7 验收并合入。
- 分支：`codex/core-alpha-hardening`。
- 唯一范围合同：外部只读 GDD `05_Core_Extraction_Alpha_首阶段功能规格.md`。
- 已接受依赖：PR #58 Persistent Base、PR #59 Extraction Loop。
- 不实现多地图、高危、刷新敌人、特殊撤离、部位/复杂伤势、耐久/故障、任务、基地成长、最终逻辑弹道替换或正式美术/音频。
- Week29 分支与正式 Grab/Scratch/Bite 美术继续暂停；不生成、发布、接入资源，也不修改美术 manifest。

## 3. 审计结论与修复范围

可复用：唯一 AssetRegistry、revision/事务、原子领域候选、schema v2、pending Raid、幂等 Settlement、PCG32 命名流、三配置 MapDefinition、固定经济与救济来源标签。

需要修复：

- `hasMinimumRaidCapability` 与 `isReliefEligible` 只统计散装弹药，未统计弹匣和枪膛，可能在已经具备 30 发可用弹药时误发救济。
- 原实现把 pending Raid 写入主档/备份并把进程退出结算为全损，和用户最终确认的“关闭程序回滚到出击前存档”规则冲突。
- 价格基线、恢复矩阵、十局跨进程序列和三配置可达性缺少一个统一的 Alpha 完成门槛。

停止扩展：V0 180 秒 Timeout、实体 Projectile 和旧 `ItemInstance` 仅保留在兼容路径，不为 Alpha 增加消费者。

## 4. 实施步骤与退出条件

1. **恢复与救济合同（初始实现，后由步骤 5 覆盖退出语义）**
   - 最低能力查询统一统计合法散装弹、弹匣弹和枪膛弹。
   - 初始实现曾把 pending Raid 同步到恢复备份；步骤 5 已改为在磁盘保留精确出击前 Profile，并只为旧 pending 存档提供无损回滚迁移。
   - 退出条件：误发救济回归、出击前主档/备份恢复、旧 pending 迁移及 Deploy 保存失败原子性测试通过。

2. **内容与长序列门槛**
   - 校验固定供应的 Alpha 回收价格基线；验证三路线插槽与三组配置可达。
   - 增加 10 局成功/死亡/主动退出/进程关闭回滚混合序列，至少 3 次保存后重新加载，并持续验证 Profile 指纹、资产所有权、高水位、货币和幂等记录。
   - 退出条件：新 Hardening focused test 全部通过，不需要测试专用生产框架。

3. **发布证据与人工验收**
   - Windows Debug 增量构建、focused、全量 CTest、架构边界检查、exact-head CI。
   - 更新项目状态、风险和 Alpha 总计划，归档已接受的 Persistent Base 与 Extraction Loop 计划。
   - 自动化与 CI 完成后才交给用户执行 GDD 1–8 清单及四项产品判断。

4. **玩家反馈返工：统一库存与角色显示**
   - Base `Tab`/仓储 `E` 使用统一双栏 Profile 界面；Raid `Tab` 使用同一拖拽内核和个人布局。
   - 4 像素阈值后才开始拖动；原物不动、虚像跟随，绿色/蓝色/红色和动作文字共同显示查询结果。Shift 数量在按下时锁定向上取半；Base 双栏库存用 Ctrl+左键快速转移，旧 F/Ctrl+右键入口移除。旋转/取消/窗口失焦/revision 过期均不提交。
   - `ProfileDropTarget` 覆盖精确格、装备槽、弹匣压弹和武器装匣；预览与提交使用同一 Inventory/WeaponAmmo 命令规则。
   - Base 装匣即时并在空膛时自动上膛；Raid 指定弹匣复用 2 秒换弹动作，中断零提交。卸弹、显式上膛和 Medkit 改为右键情境动作。
   - 用户追加修订 Raid 卸弹限制：右键随身弹匣启动 3 秒可中断动作，完成时优先将全部弹药原子写入背包、再尝试胸挂通用格；空弹匣、空间不足或中断保持 Profile 不变。
   - Base、Raid 世界与个人页使用现有批准主角资源；不生成或发布新美术，不修改 manifest。
   - 用户明确覆盖外部 Alpha 规格中“Raid 不允许拖匣到武器”的旧限制；外部 GDD 保持只读，本记录作为技术冲突与产品授权证据。

5. **玩家追加修订：退出回滚、Raid 压弹与奔跑**
   - Deploy 先保存精确出击前 Profile，再只在内存创建 pending Raid；Raid 内命令不覆盖磁盘回滚点。死亡和主动放弃仍全损，关闭程序重开恢复出击前状态。
   - 旧版本 pending Raid 存档通过显式 rollback 清除该局生成 Loot、恢复入场 HP 和装备资产，不再提交 `AbnormalQuit` 全损结果。
   - Raid 将散装弹药拖到弹匣时启动按目标数量计算的可中断动作：每发 0.2 秒，最低 0.5 秒、最多 6 秒；完成时原子压入，中断零消耗。
   - 左/右 Shift 在 Raid 提供 1.5 倍基础奔跑；本轮不引入耐力、负重或移动技能系统。

## 5. 自动化门槛

- Economy：散装/弹匣/枪膛能力等价；缺件补齐成本正确；救济幂等且来源不可洗白；当前供应回收价严格符合 Alpha 基线。
- Persistence：schema v2 往返、v1 迁移、主档/备份有效/缺失/损坏矩阵、精确出击前回滚、旧 pending 无损恢复、两份损坏明确失败、保存失败不交换内存状态。
- Lifecycle：10 局混合尝试、3 次以上重载、成功/死亡/主动退出结算、进程关闭精确回滚、重复 Settlement、失败后救济再出击及成功 Loot 保留；每次提交后 Profile 验证通过。
- Map：稳定 seed 可覆盖三组出生撤离和三组部署；每个快照 6～9 Loot 且三路线至少各一；序列化往返指纹不变。
- Architecture：`raidline_domain`/`raidline_simulation` 保持 SDL-free，业务源码只进入一个生产库。
- Interaction：共享 4 像素阈值、抓取点、旋转、数量锁定、Tab/Esc 仲裁和 revision 失效；Profile 格子/装备/弹药动作查询与提交保持原子；Raid 压卸弹覆盖可发现性、数量/目标选择、中断零提交和完成时弹药守恒；奔跑覆盖左右 Shift 与 1.5 倍位移。

## 6. 提交、PR 与回滚

- 提交 1：ExecPlan、恢复/救济/内容合同及 focused tests。
- 提交 2：长序列与恢复组合、项目状态和验收证据。
- 同一 Hardening PR 只收束 Alpha，不夹带后续产品系统。
- 若 pending 备份策略回归，可单独回滚 Persistence 提交；领域查询和测试不依赖客户端。若长序列暴露资产不变量问题，PR 保持 Draft，不以文档声明替代修复。
- 不自动合并；用户明确授权后才由 Release Control 合入。

## 7. 集中人工验收（自动化及 CI 后由用户执行）

1. 新档忽略提示，自行完成仓储、配装/弹药和出击。
2. Raid 内通过拖动弹药完成一次压弹、通过右键弹匣完成一次卸弹，并使用 Shift 奔跑，随后完成换弹、治疗、Loot 整理和撤离。
3. 成功后确认位置与资产保留，出售 Loot、补给并再次出击。
4. 分别验证死亡和主动退出全损；在另一局中整理或消耗物资后强制关闭程序，重开应恢复到该局出击前状态且不生成失败结果。连续真实失败后可用救济恢复最低出击能力。
5. 空手、无弹或不完整配装可经二次确认进入；非法所有权或存档失败必须阻止进入。
6. 连续完成 10 次混合成功/失败 Raid，期间至少 3 次完整退出并重开，无复制、吞失、死档或流程卡死。
7. 三种地图配置至少各体验一次，比较中央、外围和资源支路。
8. 清敌后可安全搜索，无倒计时和敌人刷新；若节奏偏弱只记录为后续数据平衡，不扩展 Alpha 系统。

最终由用户判断：继续出击吸引力、失败惩罚、整备摩擦和固定地图路线取舍是否成立。
