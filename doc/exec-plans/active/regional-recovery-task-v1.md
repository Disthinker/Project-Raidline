# Regional Recovery Task v1

## 产品结果与范围

玩家可在基地的失物记录界面选择一条完整记录，支付地图定义给出的费用后委托 NPC 寻回。全局同时只有一个任务；任务按世界时间推进，完成后玩家将成功寻回的物品领取到仓库。取消不退款，整条记录按委托时锁定的年龄退回失物列表。

唯一产品事实来源为只读 GDD 的 `systems/07_Loot撤离与结算.md`。本切片不实现 Raid 内自行找回、尸体或敌对幸存者携带、保险、寻回 NPC 升级、精确成功率展示、新美术或新音频。

## 基线与依赖

- 分支：`codex/regional-recovery-task-v1`
- 基线：`origin/main@7185d55`，PR #101 已按用户验收授权普通合并。
- 依赖：schema v24 的 LostRaidRecord、稳定 AssetInstanceId、世界时间、仓库布局、事务与 revision。
- 正式美术、音频及资源 manifest 均不在本计划范围。

## 状态所有权与领域合同

- `ProfileState` 最多拥有一个 `RecoveryTask`，并维护独立 `RecoveryTaskId` 高水位。
- 委托时，整条 LostRaidRecord 从待处理表移除；其所有权根原子迁移到 `RecoveryTaskAssetLocation`。容器内容与已安装弹匣继续保存父子关系。
- 成功结果在委托时由跨编译器稳定的确定性抽取冻结。界面只显示高/低寻回倾向，不显示尚未冻结的精确概率产品承诺。
- 新 Raid 失败可继续建立 LostRaidRecord，不覆盖活动任务。活动任务从待处理表移除，因此不会随随后 Raid 结算老化。
- 取消：不退费用；全部资产回到同一 LostRaidRecord 和原装备根槽；年龄保持委托时数值。
- 到时：只将状态变为可领取，不改变资产所有权。
- 领取：成功资产树尽量保留原父子结构；父项失败而子项成功时，子项独立放入 Stash。Stash 放不下则全事务拒绝且任务保持可领取。失败资产只在成功领取事务中删除。
- 拒绝命令必须保持 Profile fingerprint、revision、货币、ID 高水位与资产总量不变。

## 内容与持久化

- 每张地图以版本化内容定义声明寻回费用与耗时；禁止按地图显示名或 UI 文本硬编码。
- 保存 schema v25 新增任务、高水位与任务资产位置；schema v24 迁移为空任务。
- 保存、回读、备份和原子替换继续由 SaveRepository 负责；损坏任务、重复所有权、未知地图、倒退高水位均拒绝加载。

## 实施步骤与退出条件

1. 内容与领域合同：地图报价可验证；开始、推进、取消、领取均有无副作用查询/明确 receipt。
2. 所有权与存档：Profile 校验、fingerprint、schema v25 往返及 v24 迁移完成。
3. 会话与时间：基地自然时间和休息均可将任务推进到 Ready；所有变更通过 GameSession 持久化事务提交。
4. 基地流程：失物记录可选择；无任务时可委托，有任务时可查看剩余时间、取消或领取；中英文均可读。
5. 自动化：focused tests、全量 CTest、Windows Debug 构建和 Windows/Ubuntu CI 全通过。
6. 人工验收：仅在自动化完成后交给用户正常游玩，不由 Codex 启动游戏。

## 回滚与提交边界

本计划只在一个独立 PR 中交付。回滚为普通 revert 该 PR；schema v24 仍可迁移，v25 存档不会被旧版本静默加载。禁止自动合并、重写历史、强推或删除分支。

## 验收场景

- 两条失物记录中选择一条委托，费用扣除且另一条继续存在。
- 任务期间再失败一次，新记录正常产生且活动任务不老化。
- 休息/自然时间到期后显示可领取；领取成功资产进入 Stash，任务清空。
- Stash 空间不足时领取失败且资产、任务、货币不变。
- 取消后不退款，记录年龄不因任务期间的 Raid 追加。
- 重启后任务、剩余时间、成功结果和资产状态保持一致；重复事务不重复扣款或复制物品。
