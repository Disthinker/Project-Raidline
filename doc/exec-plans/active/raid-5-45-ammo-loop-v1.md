扩张弹只通过工坊生产取得。精密组件可回收 80 资金，扩张弹拟定每发回收 2，整批 36。组件原有基地贡献及其它用途保留。以满血普通感染者（12 生命）和无改装制式5.45步枪为调参基准，在有效射程内躯干命中，标准普通弹 3 发，扩张弹 2 发。卡宾枪可获得同样的单发加成，击杀发数按该枪原伤害计算。

## 实施顺序

1. **冻结数据与供弹合同。** 在 `assets/content/v1/core.json` 拟新增一个弹种和一条工坊配方，沿用原口径、堆叠、重量、资产 ID 与装卸弹路径。弹药定义在 `item_definition.h` 和 `content_registry.cpp` 识别无甲加成，旧弹缺省为零。复用 `base_manufacturing_domain.cpp` 的材料预留及领取事务。新增弹从 `profile_state.cpp` 的共用仓库发放目录排除，核对商店、补领、开发发放及掉落入口。现有六条配方原值保留。
2. **接通每发射击和命中。** `game_session.cpp` 基地及对局分支沿用真实枪膛与射击查询，冻结本次成功击发所消耗弹种的穿甲及效果。对照 `weapon_ammo_domain.cpp` 成功回执，空膛、卡壳、失败事务维持现有扣弹和取消语义。沿 `world_shooting_runtime.cpp`、`shot_resolution.*`、`logical_ballistics.*` 到 `hit_resolution.cpp` 传递冻结数据。用真实撞击距离和部位护甲判定加成，护甲耐久用原始伤害，普通弹命中结果不变。已经飞出的子弹不随换匣、上膛、换枪或后续瞄点变化。复用现有投射和命中，不加实体或热路径目录扫描。
3. **接通工坊和检视。** 工坊配方列表沿用现有分页，第七项进入下一页。检视复用现有文字区与滚动区域，轮盘复用八分区和选中详情，不增加全屏层或按键。弹种与数量沿既有对齐线，短名拟用「5.45 HP」，完整名留在检视。窄窗口优先保住匣顶及余量，使用测量与既有裁剪。用已批准的通用表现或文字、图形占位。
4. **兼容回读并做联合验证。** 按现有版本规则拟升内容版本 75 → 76，存档信封 schema 60 保持。旧枪膛和弹匣仍使用原稳定弹药 ID 和顺序。若基地防守保存飞行中的扩张弹，使用可选的冻结伤害字段和有效射程，旧检查点缺字段按零加成读取并保留旧校验兼容。核对 `combat_runtime_checkpoint_json.h`、`base_defense_state.cpp`、`save_repository.cpp`。显式延续内容 75 的固定 4 倍镜来源及迅捷感染者兼容，保证未结算对局的既有快照不重抽，保留原订单及旧档备份策略。

四段属于同一交付。先锁定数据与伤害合同，工坊、命中链和只读显示可并行实施，最后用一个候选串起整段流程。范围内保留原瞄具、窗口准星、菜单、射击模式、换弹、经济和撤离政策。新增一款弹和一条配方，不扩展地图、敌人、美术、音效或 UI 专项。

### 一次联合验收

1. 从边境交换站带回精密组件，或使用已带回的库存。在「工坊与生产」完成一批扩张弹，领取 18 发。
2. 混装一个 5.45 弹匣，保留一发与匣顶不同的膛弹。在检视和长按 **R** 的轮盘中分清膛弹、匣顶和余量。
3. 在对局用同一支制式5.45步枪比较普通感染者和有甲感染者的躯干。确认扩张弹对无甲目标省弹，增强普通弹对完好胸甲更有效。
4. 正常撤离并重开。检查仓库余量、混装顺序和枪膛状态。
