# Combat：射击表现收尾 ExecPlan

状态：代码与本地自动化完成，等待提交、精确提交 CI 和用户正常游玩验收

基线：`origin/main@33da892`（PR #71 已通过精确提交 CI 和用户正常游玩验收后合入）

分支：`codex/combat-feedback-finish`

产品输入：用户要求枪口火光伴随快速消散且不遮挡视野的烟雾；每次开枪引起不影响瞄准和正常视物的轻微屏幕抖动；枪口闪光需要短促照亮玩家周围且边界柔和、不刺眼。暂不制作角色或枪械射击动画。完成后射击手感阶段收工。

## 1. 玩家结果

- 每次成功击发立即出现短促枪口焰、低不透明度烟雾和柔边暖色局部闪光；烟雾在约 0.22 秒内消散，不形成遮挡。
- 世界画面产生至多约 2 像素的短促轻微抖动；实际准星、相对鼠标输入、后坐力、随机散布和命中方向不受该偏移影响。
- 枪口闪光只作为代码绘制的短寿命表现，不进入敌人感知、内容照明或持久化系统。
- 不添加角色射击动画、枪械射击动画、正式美术、纹理、音频或 manifest 变更。

## 2. 状态与边界

- simulation 保存最多八个短寿命击发表现记录，输入只来自已经接受的 ShotResolution；无弹、故障拒绝、冲刺阻断不会创建表现。
- 只读投影包含本发稳定 ID、枪口位置/方向、火光强度、烟雾透明度和消散进度；它没有碰撞、伤害、资产或存档身份。
- SDL client 以投影绘制火光、烟雾与柔边径向渐变，并把归一化抖动映射为极小世界 viewport 偏移。准星、库存、HUD、暂停菜单和调试面板在恢复 viewport 后绘制。
- 连射刷新新记录但并发有界；效果衰减不改变逻辑弹道、曳光或 HitResult。

## 3. 自动化与人工验收

- 单元测试覆盖非法配置/输入零修改、方向归一化、火光先于烟雾消失、烟雾生命周期、连射并发上限与抖动归一化边界。
- GameplayWorld 集成测试覆盖成功击发同帧发布、来源与逻辑弹道一致、阻断击发不发布、生命周期结束后清理。
- Windows Debug 全目标、focused tests、全量 CTest、exact-head Windows/Ubuntu CI 后，交由用户正常游玩验收单发/连射的火光、烟雾、柔边闪光与轻微抖动。开发代理不启动游戏。

## 4. 风险、排除与回滚

- 风险是连射亮度叠加、烟雾遮挡和抖动干扰压枪。通过 0.18 烟雾透明度上限、0.22 秒生命周期、八记录上限、柔边低 alpha 与约 2 像素 viewport 上限控制。
- 不恢复 Week29 正式攻击动画或候选生产，不合并旧 Week29 分支，不修改外部只读 GDD。
- 整个切片可回滚到 `origin/main@33da892`；不影响射击领域、弹药、资产、存档、结算或已发布资源。
