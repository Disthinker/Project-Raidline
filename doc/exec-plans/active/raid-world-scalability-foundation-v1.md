# Raid World 可扩展性能基础 v1

## 产品结果

在不增加正式敌人内容或尸潮玩法的前提下，让当前 RaidRuntime 能够用确定性、有预算且可测量的方式处理更大的敌人与静态空间集合。当前正常玩法保持不变；开发构建可用 `F9` 查看帧时间与 simulation 工作量，未来增加敌人上限、障碍或地图尺寸时必须先通过结构化压力门槛。

## 基线与分支

- 基线：`origin/main@1d2fea1`，PR #99 的第二代表性地点和多人围攻热点修复已通过用户验收、Windows/Ubuntu CI，并以普通 merge commit 进入主线。
- 分支：`codex/raid-world-scalability-foundation-v1`。
- 本切片不改变 schema、content version、Raid 结算、资产所有权或产品数值。

## 当前瓶颈

- `EnemySquadCoordinator` 的分离计算逐敌人扫描全体成员，随敌人数量平方增长。
- 视线和移动碰撞逐敌人扫描当前空间全部障碍，随敌人与障碍乘积增长。
- 导航昂贵查询已有每子步上限，但固定起点扫描在敌人数超过一个刷新周期容量时不能证明后序敌人公平获得预算。
- simulation 只有查询数量的局部诊断；客户端没有帧时间平均值、慢帧和结构化工作计数，真实窗口卡顿无法快速定位到子系统。
- 当前 8 敌人/26 障碍门槛只能防止旧热点复发，不能证明 32/100 敌人数量级没有新退化。

## 实现合同

1. **公平调度**：每个 Raid 空间保存独立导航轮转游标。每个 simulation 子步从游标开始选择需要刷新的敌人，不改变敌人更新和攻击提交的稳定顺序；预算不足时沿用旧路径，后序敌人必须在有界时间内获得查询。
2. **敌人近邻索引**：分离只查询覆盖 separation radius 的空间格，候选仍按稳定敌人索引求和，保持确定性与现有行为。输出实际邻居候选检查次数供压力测试使用。
3. **静态障碍宽阶段**：每个 Raid 空间构造不可变障碍网格。视线和移动只检查线段/扫掠包围盒覆盖格中的候选，候选保持原障碍顺序；导航静态图继续按空间与 actor size 缓存。
4. **性能投影**：simulation 只发布确定性工作计数，不读取时钟。SDL client 单独采集事件、更新、渲染和整帧 wall time 的滚动平均/最大值；`F9` 仅切换只读覆盖层，不暂停或屏蔽玩法输入。
5. **无饥饿与失败关闭**：非法空间索引构造显式失败；索引候选不得漏掉实际碰撞或遮挡。死亡敌人不消费感知、近邻或导航预算。

## 自动化门槛

- 原有碰撞、贴墙、视线、最后已知位置、攻击窗口和 8 敌人压力回归全部保持通过。
- 空间索引结果与全扫描参考在边界、长线段、横跨多格和随机固定样本上相同。
- 100 名敌人至少在 120 个 1/120 秒子步内全部获得一次导航查询；轮转不能因前序敌人刷新而饿死后序敌人。
- 32 敌人/64 障碍与 100 敌人/96 障碍压力场景记录总耗时、最慢更新、导航查询、邻居检查、LOS 候选和碰撞候选。墙钟上限仅作为 Debug 数量级警戒线，结构计数才是跨机器硬门槛。
- Windows Debug 全目标、完整 CTest 和 exact-head Windows/Ubuntu CI 通过。

## 明确排除

- 不增加正常 Raid 敌人数量、尸潮规则、新敌人类型、地图、武器、Loot、美术、音频或 manifest。
- 不引入 ECS、服务定位器、通用事件总线、任务图或无消费者的 Job System。
- 不在本切片承诺最低配置硬件上的最终 100 敌人 60 FPS；Release/RelWithDebInfo 的 P95/P99、共享流场、地图分块渲染与安全并行化由测量结果决定后续切片。

## 玩家验收

自动化与 CI 完成后，用户只需在现有 Raid 正常吸引多名敌人、穿越密集掩体并进入室内外，确认追击、碰撞和攻击没有行为回退；按 `F9` 可观察覆盖层，但不需要使用刷怪或单步验收按钮。开发代理不启动游戏。

## 提交、PR 与回滚

性能调度/空间索引、客户端遥测、文档与证据可形成多个内部可回滚提交，但共同交付一个 Draft PR。合入前关闭 PR 即可弃用；合入后普通 revert 对应 merge commit，不重写 schema、内容或玩家档案。
