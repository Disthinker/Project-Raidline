# Home Region 设施作业点空间合同 v1 ExecPlan

状态：开发完成，等待 exact-head CI 与用户正常游玩验收。分支 `codex/home-region-facility-work-sockets-v1` 从用户已验收并合入的 PR #137 / `origin/main@95f830c` 创建。

## 玩家结果与依赖

空间化核心设施不再只是一个建筑矩形和入口标签。仓库、医疗所、宿舍、厨房/净水和工坊各自拥有一个确定性的作业点；工坊制造、医疗所治疗、设施升级或工坊产物待领取时，对应作业点在世界中明确突出。玩家仍从 PR #136 的入口服务点按 `E` 打开功能，不会因为本切片改变已有操作路径。供应、物资分配和出击口目前是地点级固定服务节点而非可迁徙的 `BaseFacilityDefinition`，继续只使用入口服务点，本轮不为它们伪造持久设施定义。

本切片依赖 PR #136 的入口/交互/作业区几何及 PR #137 的设施世界状态投影。它只建立 SDL-free 空间投影和代码图形占位，不创建 NPC、排班、寻路、独立室内或新的设施任务。

## 领域与表现合同

- `BaseFacilityWorkSocketKind` 使用类型安全枚举表示 `StorageHandling / MedicalBed / DormitoryBunk / KitchenProcessing / WorkshopBench`；不以显示名判断设施职责。
- `projectBaseFacilityWorkSocket` 从稳定设施 DefinitionId、设施中心和占地确定性投影作业点。每个已发布空间化核心设施当前恰有一个主作业点；投影不持久化、不分配实例 ID，不改变 Profile。
- 作业点必须完整位于既有 `workZone` 内，因此设施、地面容器和其他阻挡物继续通过统一放置查询被拒绝，App 不另猜净空规则。
- `BaseFacilityWorldServiceProjection` 只在 `Working` 或 `OutputReady` 时给出活动作业点职责；建设、制造、居民治疗与产物待取复用现有权威任务事实。
- 世界平时以低对比代码矩形和双语短标签显示作业点；活动作业点使用 PR #137 的状态颜色突出。建设模式显示全部作业点及其保护范围。
- 设施入口仍是玩家交互点；本轮不让玩家直接点击作业点发起任务，也不改变功能页、时间、费用、存档版本或内容版本。

## 实施顺序与验证

1. 在设施布局领域增加稳定作业点类型和纯几何投影，覆盖五类已发布空间化核心设施，并验证边界、确定性和非法输入。
2. 在设施状态投影中标记当前活动作业点；验证状态优先级和查询零修改。
3. BaseWorld 暴露设施作业点投影，App 使用代码图形、状态颜色和中英文标签渲染；建设阻挡继续消费统一 `workZone`。
4. 重建受影响目标，运行设施布局、设施管理、BaseWorld、双语和持久化定向回归；完成 Windows Debug 全目标、完整 CTest 与 exact-head Windows/Ubuntu CI。
5. 交由用户正常游玩验收；Codex 不启动游戏。

人工验收：在基地观察五类空间化核心设施的作业点名称与位置；开启建设模式确认全部作业点及保护区清楚且无法被设施或地面储物箱覆盖；启动工坊制造、居民治疗或设施升级后，只有对应设施作业点使用活动状态颜色；制造完成后工坊工作台显示待领取；移动设施、迁徙并重启后作业点仍跟随设施且原功能入口正常。供应、物资分配与出击口保持现有入口操作。

## 风险、回滚与明确排除

风险是占位标签过密或作业点超出小型设施净空区，因此投影尺寸按设施占地夹取，并用单元测试保证完整落在 `workZone`。状态和几何均为只读派生值，回滚采用普通 revert，不需要存档迁移。

本切片不实现 NPC 实体、行为树、排班、路径、工作动画、设施内部、家具资产、设施旋转、供电/管线、设施损坏、自动生产、实时守城或 AI 小队；不生成或接入正式美术/音频，不修改 Manifest。
