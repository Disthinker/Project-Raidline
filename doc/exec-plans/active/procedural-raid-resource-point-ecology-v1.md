# Frontier Exchange 资源点生态 v1

## 产品结果与唯一范围

本宏切片让 `Frontier Exchange` 的搜刮从 6～9 个无身份的离散掉落点升级为可识别、可规划的资源点生态。每局冻结普通资源点、高价值资源点和三个地标专属资源点；玩家可依据资源点风险、容量、已知位置、撤离距离和自身背包空间选择路线。资源点与其中 Loot 均在 Deploy 时一次生成，不刷新、不随重新加载漂移。

唯一范围来源是 GDD 的“程序化 Raid 内容扩展——首张可玩随机大地图”Macro 2，以及已合入的 Macro 1 布局合同。PR #111 已由用户正常游玩验收，并以 merge commit `636a40b` 进入 main。本切片分支为 `codex/procedural-raid-resource-ecology-v1`，基线为 `origin/main@636a40b`。

本轮继续使用 SDL 几何、色块、中英文标签与已批准物品 Sprite；不生成或接入新美术，不修改美术 Manifest。

## 明确排除

- Macro 3 的巡逻、守点、伏击和声响响应遭遇生态；本轮不增加敌人数量或重构 AI。
- 完整经济重做、动态价格、资源刷新、无限再生和全部正式物品内容。
- 程序化室内、第二地图主题、正式 Prefab 编辑器、AI 小队和实时尸潮。
- 正式美术、Grab/Scratch/Bite 动画和 P1 音效扩展。

## V0 差距与复用策略

- 可复用：`ContentRegistry` Loot 表、稳定 `AssetInstanceId`、`RaidGroundAssetLocation`、Pending Raid、逻辑区块投影、战术地图揭图/资源情报和幂等 Settlement。
- 需要重构：普通 Raid Loot 不再从旧坐标表抽取并逐个请求泛化 Loot 锚点，而由冻结资源点的容量与 Loot 表驱动。
- 需要新建：资源点内容原型、资源点稳定快照、分区/地标放置约束、命名随机流、资源点内精确掉落位置与战术地图投影。
- 停止扩展：旧 `central/perimeter/resource` 路线标签和 6～9 个离散 Loot 仅为旧固定图兼容合同，不再作为 Frontier Exchange 的内容增长路径。

## 状态所有权与领域合同

`ProceduralOutdoorDefinition` 定义不可变资源点原型：稳定 ID、显示名称、种类、Loot 表、风险等级、容量、实例数量、占地区域，以及允许分区或绑定地标。内容加载拒绝重复 ID、未知 Loot 表、未知地标、不合法数量、容量、风险和互斥约束。

`RaidGeneratedMapLayout` 新增 `RaidResourcePointSnapshot`，冻结实例 ID、定义 ID、显示名称、种类、Loot 表、风险、容量、区域、分区和可选地标。资源点区域通过 `RaidMapAnchorKind::ResourcePoint` 进入同一锚点合法性、道路可达性和完整占地避让流程；它不是 App 自行推断的表现标签。

`RaidLootSnapshot` 记录所属资源点实例和点内槽位。资源点使用独立稳定随机流，实际物品、数量、稳定资产 ID、全局 Loot slot、精确位置和布局哈希均在 Deploy 时冻结。旧 schema 快照的来源字段为空，并按旧合同读取，绝不重新生成。

资源情报或 F10 完整静态地图可以显示全部资源点；否则战术地图只显示已揭开的资源点。世界内资源点使用区块裁剪投影，只呈现可见区域。上述表现权限不改变揭图格、情报库存或存档。

## 实施步骤与退出条件

1. 增加资源点内容、快照、锚点约束与版本合同；内容坏引用和旧档兼容测试通过。
2. 在 Deploy 中以独立随机流生成普通、高价值和地标专属实例，接入道路可达、完整占地避让与确定性回退。
3. 按资源点容量生成真实 Loot，冻结稳定资产、槽位和位置；验证资产唯一所有权、数量范围、同 seed 一致及不同 seed 差异。
4. 接入世界区块投影、双语标签和战术地图的揭图/资源情报权限。
5. 通过 Windows Debug 全目标、完整 CTest、提交、推送和 exact-head Windows/Ubuntu CI，再交由用户正常游玩验收。

## 自动化与人工验收

自动化至少覆盖 128 个固定 seed：三类资源点数量与内容合同、允许分区、地标绑定、道路可达、与非碎屑物件及关键锚点无非法重叠、资源点容量与 Loot 总量一致、Loot 表引用合法、稳定 ID/slot 唯一、同 seed 布局与 Loot 一致以及坏种子固定回退。

保存测试覆盖 v36 往返、schema v35 快照兼容、缺失资源点、未知定义、重复实例、非法点内槽、篡改布局哈希和重复加载。区块投影测试保证只查询摄像机附近资源点；战术地图测试保证迷雾、资源情报和 F10 完整静态地图的权限边界。

用户正常游玩验收不使用单步按钮：至少三次不同 seed 出击，观察普通、高价值和地标资源点的布局差异，按需求与撤离距离选择路线，搜刮后成功/失败结算，并跨进程重开确认本局资源点与 Loot 不漂移。

## 提交、PR、风险与回滚

本切片只包含 Macro 2。自动化和 exact-head CI 通过后创建一个 Draft PR；用户验收前不把它写成 main 已实现事实，也不自动合并。

主要风险：Loot 数量放大导致存档和绘制成本增长；由点级容量上限、区块裁剪和小型冻结快照控制。资源点过密导致路线选择退化；由分区配额、完整占地与最小间距控制。高价值点变成无条件最优路线；本轮只冻结风险等级和地图位置，Macro 3 再让遭遇消费风险，不在 App 层伪造敌人压力。

回滚按表现、战术地图、生命周期/验证、存档、内容与文档逆序普通 revert；禁止重写历史、强推或删除已验收的 Macro 1。
