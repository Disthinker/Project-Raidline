# 基地应急供电与燃油后勤 v1

**已验收 · RL-BASE-EMERGENCY-POWER-AND-FUEL-LOGISTICS-v1**

去灰烬工场搜建材，建起发电机房。去边境交换站找到燃油罐后，决定当局用油撤离，还是从其他出口把油带回基地。把油投入工坊，可以提前拿到照明弹，下次去医院搜索暗区。基地急需恢复居民岗位时，也可以把这批油用于加快居民治疗。

## 玩家规则

| 环节 | 拟定规则 |
| --- | --- |
| 建造发电机房 | 「灰烬工场」现有工业紧固件和铜线卷可按原规则转为建材。通过「基地建设」投入 **6 建材、2 名施工人员、480 游戏分钟**建一座。完工进入设施储备，随后在主基地合法位置部署。首次完工计 **2 点基地威胁**。 |
| 选择燃油用途 | 「边境交换站」的「货运装卸间」沿用现有燃油罐来源。用燃油撤离时，仍只在成功结算扣除。带回基地的油先入仓库，再在发电机房选「工坊生产」或「居民治疗」。确认时从仓库扣 **1 桶**，绑定当前合法订单。缺油、目标无订单或上一批油尚有余量时无法开启新批次。 |
| 加速当前工作 | 每桶提供 **180 游戏分钟**运行额度。运行时，该订单按已计算的基础进度 **2 倍**推进，原有人员、设施等级、士气和地点等规则照常生效。工坊供电适用于现有生产配方，包括照明弹。护甲蓝图研究沿用原速度。居民供电只加快已有居民治疗，玩家即时医疗、治疗费用和床位按原规则。 |
| 暂停与恢复 | 累计运行每 **60 游戏分钟**计 **1 点基地威胁**，每桶最多 **3 点**。手动停机、订单完成或取消、相关设施收起或基地迁徙时停机，余量保留。可在部署后手动恢复到同类合法订单，本批用完前方向固定。停机、用尽或缺少发电机时，已完成的进度保留，仍可运行的订单按原速推进。 |

以上数值是本轮拟定玩法。供电是可选加速，原有设施收起、迁徙、岗位、死亡、撤离和世界时间规则继续生效。发电机房使用现有几何占位和界面组件。地图、掉落、键位和正式美术音频沿用当前内容。

## 实施方案

1. **施工与部署。** 在 `assets/content/v1/core.json`、`content_registry`、`base_construction_domain` 添加一级机房和一次性施工项目，沿用现有单施工队列、储备和放置校验。接入 `base_facility_layout_domain`、`BaseWorld`、`GameFlow` 的稳定设施 ID。两处主基地迁徙核心位已由四座必需设施使用，机房作为可选设施随基地收起，抵达后由玩家手动部署。静态布局核算显示三种开局选址和旧地块均有空间，拟采用 **180×120** 占地，默认建议中心为地块内 (1040,320)。现场提交仍核对已有设施、工作区、地面物、工事和玩家。实施时用真实放置规则核对各选址和迁入基地。旧档中的活动防守沿用已冻结场景，新增未拥有设施不改变原碰撞与几何身份。
2. **投油与控制。** 复用 `ProfileUiCommand` 和 `GameSession::requestProfileUiCommand` 的后台存档流程。按稳定 ID 在同一持久候选里扣除仓库内指定燃油罐并建立供电批次。暂停、恢复也走同一事务。只绑定一个订单 ID，保存目标类别、启停、剩余分钟和累计威胁所需余数。重复确认只处理一次，写入失败保留燃油、运行状态与订单，沿用现有重试。货运燃油掉落和撤离仍走原路径。供电不会消耗局内燃油或代替撤离凭证。
3. **按世界时间分段结算。** 现有 `applyBaseManufacturingThrough`、`applyResidentTreatmentThrough` 分别由基地实时、休息、Raid 出发／返程、局内和防守恢复等路径调用。将新增供电结算接到这些共同时间边界，遇到目标完成、燃油耗尽、停机或日结时按实际先后处理。按分钟累计供电实际产生的额外进度，同一分钟到达完工与用尽时，订单只完成一次，已运行的整小时照常计威胁。保留旧订单的起始时间和基础工期校验，单独记录加速所贡献的进度，避免重算或回拨已经完成的工作。工坊在途到期后仍按原结算边界发布产物，居民治疗沿用原完成规则。发电威胁经 `base_siege_domain` 的总容量、预警和保护规则入账。旧的日结、威胁降低和防守逻辑继续处理总量。停止后不补扣燃油或威胁，真正暂停与离线不推进。
4. **界面与存档。** 在现有建设目录和设施详情加最小交互，显示将扣的油、被绑定的订单、剩余运行时间和威胁成本。开机、停机与失败反馈放在同一控件附近，等待保存时防重复点击，工坊与医疗订单只补充各自的供电状态。按项目 UI 栅格和 UI/UX Pro Max 的确认、等待、错误恢复规则执行。旧档默认无机房、无供电与加速记录，原订单与已冻结对局不重算。内容拟升至 85，按最终持久字段确定格式并显式迁移。检查 81／65、82／66、83／66、84／66 的主档、备档，尤其是已在制的破拆楔组和冻结对局的破拆资格。保留 84 及先前玩法的版本支持，升级前归档原始主备档。异常退出按出击前快照恢复，防止返程或供电进度重复提交。

## 联合验收

1. 去「灰烬工场」带回建材，在「基地建设」施工并部署发电机房。确认只获得一座，能从外部交互。
2. 去「边境交换站」的「货运装卸间」取得一桶「燃油罐」，走原有其他撤离点带回并入库。开始生产照明弹，给工坊供电。确认只扣一桶，休息推进时订单加快，手动停机后恢复原速且余量保留。
3. 领取照明弹，带到「医院片区」，用它搜索「区医院内部」暗区，再正常撤离。居民治疗供电、燃油耗尽、迁徙停机、保存失败和异常退出由自动化覆盖。

验证一次大步推进与多次分段推进一致，覆盖同分钟完成与耗尽、午夜、威胁上限、日常与防守恢复、跨进程、满仓、重复确认和燃油撤离扣费。交付 Windows Debug 全量检查，原 **14 项 3 ms** 的负载与门槛全部沿用。负重卸包、医院图纸与粉笔和货运破拆一起回归。沿用桌面 **Project Raidline Debug**，通过验证后才指向新候选，保留现有程序和存档副本供回退。
