# Survival Loadout：武器耐久、故障与维护 ExecPlan

状态：实施中

基线：`origin/main@ea918ab`（PR #62 已由用户验收并合入）

分支：`codex/survival-loadout-durability-malfunction-repair`

产品输入：外部只读 GDD 的 `systems/03_武器装备弹药与治疗.md`、`systems/05_战斗命中与反馈.md`、阶段减法规划和当前仓库领域不变量。GDD 保持只读；本计划只交付首个有完整消费者的整枪状态闭环。

## 1. 玩家结果

基础步枪不再是无损耗工具：成功击发会磨损，状态下降后可能发生通用武器故障。Stovepipe 已经发生的子弹与磨损保留，玩家必须保持瞄准并快速反向扫动鼠标完成清障。玩家可在 Base 或 Raid 中把维护包直接拖到武器上；Base 安全维护不降低最大耐久，Raid 的八秒应急维护会永久损失一部分当前最大耐久且可被行动或受伤中断。

## 2. 权威状态与领域合同

- `AssetRecord` 唯一保存整枪当前最大耐久、当前耐久和隐藏故障类型；使用 0.01 固定精度，不保存浮点数。
- 基础步枪出厂/初始耐久为 100.00，每次成功击发磨损 0.10。未成功击发、空枪、被故障阻断和零耐久拒绝均不磨损。
- 可靠性分级：61～100 为 0%，31～60 为 0.5%，11～30 为 3%，1～10 为 12%，0 为损坏。领域先乘内容定义中的型号可靠性基点，再进行一次总故障判定和一次加权类型选择。
- 当前 Rifle 故障权重只包含 Stovepipe。它发生在成功击发后：枪膛弹已消耗、耐久已磨损，但不会自动送入下一发。
- `ClearWeaponMalfunctionCommand` 显式清除 Stovepipe 并从已装弹匣送入下一发；不得借用 Fire/Chamber 命令猜测。
- `WeaponMaintenanceCommand` 通过纯查询返回修复量、消耗量、最大耐久变化和动作时长；提交重验 revision、资产位置、容量及 Profile 不变量。
- Base 维护即时完成且最大耐久不变。Raid 维护耗时 8 秒，修复容量 25.00，最大耐久损失为实际修复量的 10%，最低保持出厂上限的 20%。只清故障而无耐久缺口时最低消耗 0.01 容量。
- 拒绝命令保证 Profile 指纹、revision、货币、弹药总量和稳定 ID 高水位不变。

## 3. 输入、动作与表现边界

- UI 只显示通用 `MALFUNCTION`，不暴露隐藏类型。瞄准继续有效。
- 清障手势要求一秒内四次反转；每段至少为 1280×720 逻辑视口短边的 5%（36 像素），相邻方向夹角至少 120°。
- 射击、换弹、治疗、冲刺、库存和 Grab/OffBalance 重置手势；普通伤害不重置。
- Raid 维护使用类型安全 `WeaponMaintenanceRaidAction`。移动与本帧输入同时生效后中断；射击/冲刺只负责打断，必须松开再按才执行。受伤、库存、换弹、治疗及受控同样中断，且不消耗维护包或写入部分进度。
- Base/Raid 个人页把维护包拖到武器时显示蓝色 `REPAIR` 预览；Base 立即提交，Raid 关闭库存并开始动作。武器与维护包卡片显示当前数值，HUD 显示武器状态和维护进度。
- 维护包使用代码 fallback 表现；不生成、发布或接入正式资源，不修改美术 manifest。

## 4. 内容与持久化

- 内容版本升级为 `survival-loadout-content-3`，新增 WeaponCondition、故障权重和 WeaponMaintenance 定义校验。
- 新 Profile 获得一份基础维护包；固定供应可购买后续维护包。
- schema v5 保存武器故障；既有耐久字段保存武器的 0.01 固定值。v1～v4 迁移为出厂满耐久、无故障，v4 的 `survival-loadout-content-2` 作为显式旧版本读取。
- 关闭程序仍加载出击前保存的 Profile，因此 Raid 内磨损、故障和维护结果与其他 Raid 内状态一起回滚；正式撤离/失败结算沿用唯一 Settlement 合同。

## 5. 明确排除

- Misfire、Double Feed、退膛弹和抛出弹的动态 Raid 地面所有权；当前架构没有通用地面弹药资产位置，不能吞弹或凭空生成。
- 护甲维修、维修 NPC、付费全修、组件耐久、组件替换、改枪台与武器配件。
- 故障动画、维修动画、正式图像/音频、runtime 资源发布和美术 manifest。
- 特殊弹、混装弹深化、贯穿、击退、断肢、战术电子、多地图和高危阶段。

## 6. 自动化与人工门槛

- 领域：各可靠性边界、单次判定、成功射击磨损、Stovepipe 弹药守恒、阻断/损坏零修改、清障送弹、维护查询/提交一致、Base/Raid 最大耐久规则及失败高水位不变。
- 输入：段长、角度、四次反转、一秒窗口、过期裁剪与重置。
- 动作：Raid 维护开始、八秒完成、移动/伤害/战斗/库存/受控中断和重新按下门控。
- 存档：schema v5 往返、v1～v4 迁移、非法故障、非法耐久、损坏主档与安全备份。
- 客户端：拖放目标、蓝色预览、供应购买、数值/HUD 和库存输入仲裁。
- 交付：Windows Debug 全目标、focused、全量 CTest、exact-head Windows/Ubuntu CI。
- 自动化与 CI 全部通过后，由用户进行一次正常游玩验收；开发代理不启动游戏。

## 7. 提交、风险与回滚

- 领域/内容/schema、会话/输入/动作、客户端投影与文档可形成可审计提交，但同一 PR 交付完整玩家闭环。
- 任一阶段失败可回滚至 `origin/main@ea918ab`；schema v5 只在完整闭环一起交付，不能让 main 保存无法消费的武器状态。
- 当前 App 仍偏大；本切片只增加现有 Profile 投影的消费者，不进行无行为重写。
- 只有 Stovepipe 不代表完整版故障种类已取消；RL-WEAPON-002 明确记录地面弹药所有权依赖。
