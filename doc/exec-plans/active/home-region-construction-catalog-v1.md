# Home Region 基地建设项目目录 v1 ExecPlan

状态：已完成。PR #135 已通过 Windows Debug 全目标构建、1410/1410 完整 CTest、exact-head Windows/Ubuntu CI 与用户正常游玩验收，并以 merge commit `c37fe32` 进入 main。

## 玩家结果与依赖

玩家在基地任意位置按 `B` 后，可在“购买/建设”页面统一查看所有已发布建设工程和可购买的可放置设施。工程卡片明确显示目标等级、建材、劳动力、工期与当前状态；合法工程可直接开始，活动工程可从同一卡片取消并返还建材。目录超过四项时使用明确分页，不再静默截断后续设施。

本切片依赖 PR #132 的权威设施布局、PR #133 的储备部署事务和 PR #134 的厨房/净水首次建设生命周期。设施现场右键升级仍作为快捷入口，但区域迁徙页不再直接执行厨房工程，只在缺少迁徙核心设施时打开统一建设目录。

## 领域与客户端合同

- 新增 SDL 无关的建设目录投影，从不可变 `BaseConstructionProjectDefinition` 和 `queryStart/queryCancelBaseConstruction` 生成 `Start / Cancel / Complete / Blocked` 状态。App 不按显示名或设施类型猜测合法性。
- “购买/建设”目录先列建设工程，再列可购买的可放置物品；“已有”目录继续列 Reserve 核心设施和 Stash 中未放置设施。两页共享每页四项的稳定分页与边界夹取。
- 点击工程卡片只发送对应开始/取消命令。失败显示领域消息并保持 Profile 不变；成功继续使用现有原子保存和运营通知。
- 区域页在候选基地已解锁但缺少厨房/净水时，按钮打开 `B` 建设面板并定位到包含该工程的目录页，不再保留第二套开始/取消实现。
- 不改变 schema、content、建设数值、单工程队列、设施布局、世界时间或迁徙门槛。所有新增界面文本提供中英文。

## 验证与人工验收

自动化覆盖目录状态、活动工程取消、已完成工程、另一个工程占用、分页夹取、定义顺序、失败零修改、区域页不再直接提交工程，以及现有建设、设施部署和跨进程回归。完成 Windows Debug 全目标、定向测试、完整 CTest 与 exact-head Windows/Ubuntu CI 后交给用户正常游玩验收；Codex 不启动游戏。

人工验收：按 `B` 打开建设面板，确认“购买/建设”同时包含厨房/净水、宿舍、工坊、医疗工程及基地储物箱并可翻页；检查工程卡片成本、人员、工期和状态；开始一个工程，确认卡片变为取消且其他工程显示被队列占用；取消后建材返还；重新开始并推进完成，确认工程变为完成、首次设施进入“已有”等待放置；在区域迁徙页缺少厨房时点击提示，确认只跳转建设目录且不会直接开始工程。
