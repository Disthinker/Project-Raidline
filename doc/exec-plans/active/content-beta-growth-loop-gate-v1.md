# Content Beta 成长闭环与配装准备度 v1

## 产品结果、基线与范围

本切片把已经进入主线的武器、口径、防具、容器、Loot 来源、制造和补给组织成可理解的“配装目标 -> 地图目标 -> 再出击”闭环。玩家在 Raid Gate 能选择轻型搜刮、均衡作战或重型专精三种职责，并看到当前真实配装是否满足武器、随身兼容弹药、防具和携行结构要求，以及建议前往的地图与风险提示。

依赖基线为已经用户验收并合入的 PR #119，`origin/main@ecd8288`。分支为 `codex/content-beta-growth-loop-gate-v1`。本切片是 Content Beta Macro 4 的收束交付，不扩展第二地图主题、更多物品目录或新的经济系统。

明确排除：自动配装、总战力评分、推荐唯一最优装备、动态价格、随机词条、新地图、组件改枪、特殊弹、正式美术、资源 Manifest 和额外音频。现有射击手感、装备槽、库存操作、失败损失和寻回合同不改写。

## 内容与领域合同

- 内容注册表新增稳定 `loadout_archetype.*` 定义。每个职责明确可接受武器、防具、胸挂、背包、最低随身兼容弹药、建议地图与是否建议高危。
- 三个首发职责固定为：轻型搜刮、均衡作战、重型专精。差异由真实武器/装备/口径和来源形成，不使用武器品质色或客户端显示名猜测。
- `LoadoutReadinessProjection` 是 SDL 无关的纯查询。它只读取 `ProfileState` 与 `ContentRegistry`，返回每一项要求的通过状态、兼容弹药数量、缺口和建议地图。
- 武器必须真实装备；弹药只统计玩家实际随身携带的枪膛弹、已装/随身弹匣内弹药和兼容散弹。Stash 中的弹药不计入出击准备度。
- 客户端只选择要查看的职责并渲染 Projection。选择不持久化、不修改 revision，也不触发资产移动；出击仍由既有 Deploy 命令和二次危险确认控制。
- 推荐地图是产品引导，不是物品来源的新权威。实际来源仍由固定供应、制造配方和 Loot 表决定。

## 版本、迁移与不变量

- content 升至 `content-beta-growth-loop-content-56`；schema 保持 v38，rules 保持 v29。
- content v55 显式兼容；已有物品 DefinitionId、实例 ID、位置和 pending Raid 的冻结内容/rules 不变。
- 新职责定义不进入存档，旧档无需迁移字段。加载旧 Profile 或旧 pending Raid 时不得重抽 Loot、替换装备或改变资产位置。
- 查询前后 Profile 指纹、revision、货币、稳定 ID 高水位和资产数量必须完全一致；未知或错误内容定义在 ContentRegistry 加载阶段拒绝。

## 自动化与正常游玩门禁

- 三个职责定义 ID 唯一，全部引用已发布且类别/装备槽正确，建议地图存在。
- 轻型、均衡、重型各有一套可达到 READY 的真实配装；错口径、只有 Stash 弹药、缺防具或错误容器必须明确显示缺口。
- 枪膛、已装弹匣、胸挂/背包内弹匣和散弹计数不重复；切换职责只改变 Projection，不改变 Profile。
- content v55/schema v38、rules v29 pending Raid、重复 Settlement、异常退出回滚、制造、失物与两种寻回保持兼容和幂等。
- 所有新增 UI 文本提供中英文；颜色关闭或占位图缺失时仍可读懂职责、缺口和地图建议。

用户最终正常游玩：在 Raid Gate 依次查看三种职责；故意制造一次缺武器、错口径或缺防具状态并看到明确缺口；整理一套 READY 配装进入建议地图，带回升级后再查看另一个职责；经历一次失败或寻回并确认准备度反映真实资产。验收不依赖专用单步调试按钮。

## 提交、PR、风险与回滚

本分支只交付 Content Beta Macro 4。提交按计划、内容/领域、客户端、测试/状态收尾组织，最终形成一个 Draft PR；未经用户授权不合并。

主要风险是把 Stash 弹药误算为随身、重复计算枪膛/弹匣、把推荐地图误当来源权威、客户端按名称猜兼容，以及开发期完整目录补齐削弱自然成长验证。通过 AssetLocation 树查询、定义 ID/口径查询、只读 Projection、真实来源门禁和明确的开发期目录说明控制。回滚使用普通 revert；content v55 兼容和已持久化稳定 ID 不得删除，不重写历史或强推。
