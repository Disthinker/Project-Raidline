## 玩家结果与本片上限

基地威胁触发原有三分钟预警后，玩家选择亲自防守或现有自动防守。亲自防守是一场有限的基地事件：敌人从外围接近核心防线，玩家使用自己的武器/弹药/医疗截击；有限波次处理完且防线未失守即成功，玩家倒下或突破达到上限则软失败。结果复用现有公共资源、士气、建材与 7/12 日安全期，之后可以继续整备和 Raid。

- 一个事件模板，覆盖当前已发布主基地地点及三个开局地块；不增加地图主题或候选基地。
- 初始调参基线为 3 波、单场 24～36 名现有感染者、同时活动不超过 16 名；至多两个来向、突破上限 6。人数/节奏由冻结的基地人口、士气和地点在有界范围内决定，不看玩家装备强化敌人 HP/伤害/护甲。数值是工程调参候选，不是长期 GDD 常量。
- 仅玩家本人参战，不建立居民单位、NPC 守军、队友、指挥轮盘或旧“两支四人组”。
- 不做防御工事、设施耐久/永久损坏、自由筑墙、炮塔、陷阱、昼夜照明、新 Loot 或击杀奖励。
- 自动防守仍可取得相同基础成功收益；不强迫每场手动战斗。
- 只使用现有批准表现、代码几何和双语文字；不生成或接入美术/音频，不修改 Manifest。

## 状态、职责与事务

采用 Warning → ActiveRealtime → Resolved 窄状态，不引入万能活动/ECS/事件总线。

1. ProfileState::activeBaseDefense 持有活动快照，baseSiege 持有唯一事件序号及最近结算序号。事件 ID 由 ProfileId 与 siegeSequence 构成，模式不进入 ID；同一序号不能同时由自动和实时各结算一次。Begin/Settle 使用领域查询、expectedRevision 和明确 receipt；Checkpoint 是服务层完整状态捕获。新的战斗命令 ID 同样绑定事件，重启后的新事件不撞旧事务。
2. BaseDefenseSnapshot 保存模式、规则版本、地点/局部地块/布局身份、seed、人口/士气/地点输入、公共消耗与软失败预览、全部波次/入口/防线、当前波、敌人稳定 ID/位置/HP/阶段、已突破 ID、时间和已提交结算。还需保存玩家位置、在途逻辑弹道、敌人攻击计时/命中已消费标记、受伤保护时间、调度及随机流状态，或在可证明等价的安全点规范化；恢复必须保持一次性攻击/命中语义，纯粒子、烟雾和镜头抖动可以丢弃。定义只读共享，快照不保存裸指针、资源或另一个 Registry。
3. BaseDefenseRuntime 只负责有限敌人和波次/防线模拟，产出明确突破或战斗结束事实。BaseWorld 组合当前基地活动；GameSession 负责唯一 Profile、持久化、模式仲裁和结果。禁止复用 PendingRaid/RaidResult/LostRaidRecord/Raid Settlement 来表示基地战。
4. 将 auto 与 realtime 共同的奖励/损失/清威胁/安全期应用抽入单一领域结果函数。UI 不能通过修改 Security 假造胜负，也不能直接提交任意成功布尔值；实时结束必须关联服务已验证的同一冻结事件。
5. 正常外围敌人/有限 Loot 与攻城敌人来源、ID 和生命周期隔离。本次战斗不触发外围返回/救回的第二次时间结算，不刷新普通 Loot，不把普通敌人计入波次或胜负。

## 场地、安全与敌人行为

- 普通模式保留当前核心/缓冲安全，不允许日常敌人借新代码进入核心。
- 仅 ActiveRealtime 的 Siege 来源敌人朝当前 CoreDefenseZone 推进。它在核心边界形成明确可见的防线，抵达并满足短接触确认后记一次突破并退场；不让敌人在设施/仓库内部持续游荡，不直接攻击设施或删除资产。突破次数属于本次事件，不是科技核心 HP。
- 本版交战区域明确为 Perimeter 加本次标明的核心外接近走廊；走廊只允许覆盖 TransitionBuffer 的指定部分，不覆盖 SafeCore。只有 Siege 来源可在活动走廊中行进/攻击，其他缓冲带仍安全。攻击框不能跨线伤害站在 SafeCore 的玩家。敌人抵达核心外侧防线即记突破退场，以有限承压表达失守，不开放整个核心内战斗。事件结束清除走廊例外和 Siege 命中暂态。该局部例外及“核心外承压替代设施破坏”的首版妥协须随计划确认。
- 攻城敌人发现玩家时交战，丢失目标后继续向防线，不回出生点。玩家退避不能让所有敌人停住，不能通过躲藏自动守住事件。
- 战斗入口远离玩家、设施入口与 BaseGround，至少有一条经障碍索引/导航验证的路到目标；三开局地块、迁徙后的每个已发布地点都要覆盖。
- 无合法空间时拒绝开始并保留预警/自动路径，不生成半场战斗；准备确定性的合法回退来向，不能把敌人瞬移穿墙。敌人因拥堵暂不能激活则延迟，在有限预算内换同一快照的合法点，不无限加敌。
- 预警与活动期间统一冻结设施安装、移动、收起、换位、迁徙和新建设；已有运行队列、库存/医疗/补给继续沿已有权威时钟与即时整备合同。需补齐遗漏的布局命令门禁而非仅禁 UI 按钮。真正 Esc 暂停冻结模拟，离线不推进。

## 结果与玩家损失边界

- 所有已计划敌人均已击杀或形成突破，且突破低于上限：成功。仅检查 Siege 来源，不要求清地图上所有普通敌人。
- 玩家倒下、突破达到上限：软失败。已有消耗的弹药/医疗/耐久保留，个人资产位置不变，不创建 Raid 失物记录，不产生全损或基地覆灭。
- 主角倒下沿用 Base 救回健康下限和安全落点；若复用外围救回时间成本，只能在同一最终候选中应用一次，不能另调用完整外围结果后再次结算。
- 推荐首片实时模式只支付真实个人战斗消耗，不额外扣一份自动防守 Security 费用；这是提交确认前需要写清的模式差异。成功复用现有有界建材/士气和 7 日安全期；失败复用现有公共储备/士气及至多一名空闲普通居民的保护上限与 12 日安全期。开始前明确预览，不提高损失上限，不创第二货币或额外战利品。
- 自动模式继续按原 Security 成功条件和原消耗运行。自动与实时绑定同一事件；实时开始后旧预设不能在倒计时归零另结算。
- 主动“放弃本次防守”须清楚二次确认后形成同上限软失败；退出到主菜单/桌面不等于放弃，执行下面的恢复合同。

## 持久化、迁移与性能合同

这是 Base 活动的恢复型合同，不改变 Raid 的出击前回滚。

- 开始先保存完整一致的事件/资产/时钟检查点，成功才激活敌人；失败保留原预警、资产与 ID 高水位。
- 正常退出保存当前一致检查点，重开恢复同一事件；保存失败保留当前活动并提供重试，不能假称退出保存成功。用户强制终止只能恢复最近已持久检查点，不离线推进、不重抽 seed、不自动判胜/负。未持久尾段可能整体回退，不能声称没有逐次落盘却“崩溃绝不回退任何一发”。建议检查点间隔 250ms、单个在途写入和一个可合并候选；未持久窗口超过 1000ms 时暂停活动等待写入/重试，实施时以压力证据冻结并报告实际最大窗口。不得只保留击杀而返还对应消耗。
- 每份检查点原子包含资产/弹药/医疗/玩家伤势、世界时间/日结与战斗位置/HP/波次/突破。严禁 Base 侧路保存新资产却遗漏旧波次，或重开恢复死亡敌人但保留奖励。
- 开始、终局、正常退出是必须等保存成功的持久化屏障；波次边界/防线突破只产生逻辑检查点请求，在上述有界窗口内合批异步提交，不逐突破等待 IO 或停模拟。磁盘 IO/序列化不得挂在射击和逐敌回调；必要时用 SaveRepository 下唯一窄写入队列接收不可变检查点，工作线程不接触活动 Registry/SDL，不引入通用任务系统。
- 同时只写一个检查点，更新序号单调；失败进入明确可重试的暂停保护态，不继续生成不可持久结果、不部分回滚资产。开始与终局 receipt 只在保存成功后确认；终局重复提交不再次扣费/发奖励/延长安全期。
- 预计首次需要 schema v46：旧 v45 初始化无实时活动，保留既有威胁/预警/预设/历史结果，不伪造历史 Siege ID 或重新生成旧 Raid。若实现前主线版本前进，以最新已接受版本顺序迁移。防守 JSON 定义仅在有真实消费者时升 content，Raid rules 不因基地战升级。
- 命名随机流用于来向/波次，冻结最终结果；恢复不重抽。保存验证拒绝重复敌人 ID、越界 Socket、规则/布局错配、不一致波次、篡改快照和重叠活动。
- 敌人模拟共享 Raid 已有空间索引、导航预算和攻击配额能力；保留最多 10 攻击者与 0.25 秒受伤间隔。不按敌人数同步增加寻路/保存次数，不在每帧复制整份 Profile。

## 实施顺序与退出条件

一个可玩宏切片、一个 PR，内部可回滚提交：

1. 领域/存档：事件快照、模式排他、共同结果、v45 迁移、开始与终局事务。退出条件：旧自动路径、拒绝不变、幂等、保存失败/旧档回归通过。
2. simulation/服务：合法 Socket、有限波次、核心目标、共享导航预算、伤害/消费与一致检查点。退出条件：所有当前地点与三地块可达，敌人不停追出生点，保存/重开同事件且不重叠外围结算。
3. SDL：原预警入口加亲自防守，现有场景显示来向/波次/突破与结果；全中英文，不新增大型管理页。复用 F10 鼠标面板提供到合法预警的开发入口，不直接伪造胜负/奖励，正常游戏不依赖它。
4. 集成交付：自动/手动成功/倒下/突破/主动放弃/退出恢复长序列，性能门禁与全部既有回归；全目标 Windows Debug、完整 CTest、精确 head Win/Ubuntu CI 后再交用户正常游玩。

每步门禁失败在本 PR 内修复，不推进后续 NPC/工事内容。每次头文件或类布局修改均重建所有消费者。

## 自动化与正常游玩门槛

自动化至少覆盖：

- 全部基地地点/三开局地块及代表性设施阻挡布局的合法入口、防线和道路；普通核心安全不变，只有同事件来源触发突破。
- 失去玩家后继续推进、接触只计一次、有限总量、并发上限、正常外围敌人不参与结果；坏布局确定性拒绝/回退，不穿墙。
- 自动与实时/预设倒计时排他；同 SiegeId 用不同 TransactionId 也只能结算一次；保存失败、重开、重复按钮不能复制资产或收益。
- 弹匣有序弹药、枪膛、药品次数、耐久/伤势/时钟与敌人结果一致；不产生失物记录，不删除个人资产，人口/公共损失不超过旧自动上限。
- 开始/波中/突破/终局的跨进程检查点，截断主档、安全备份、旧 v45 预警和 pending Raid、重试/异常终止。
- 16 名战斗敌人、1000 静态阻挡和 1000 资产；同时保持现有 100 敌人 Raid 压力回归。Debug 最慢 simulation 子步仍低于现有 25 ms 门槛；F9 分开记录事件更新、导航、检查点复制/序列化/提交。持续射击、多人伤害、库存与后台保存同时运行，主线程检查点构造/复制目标为 P95 ≤4ms、P99 ≤8ms，另报告整个帧的分位与最大值；不能用 simulation 25ms 合格替代保存不卡顿证据。数字是现有环境的 Debug 防回退门槛，不是发行硬件承诺。持续射击与多人伤害热路径不得包含同步全档 IO。
- 新文本/按钮/输入仲裁双语，F10 只能创建合法测试前置，Esc 真暂停、重开不离线扣时。

用户正常游玩只需一次集中流程：保留原档后用隔离验收档进入合法预警，亲自截击完成一场成功，观察换弹/治疗和防线压力；另一次验证倒下或突破软失败及现有自动防守。中途正常关闭再打开应恢复同场，战后确认物品原位、真实消耗、一次结果、安全期和正常整备。无需手工逐测全部坏档分支，代理不启动游戏。

## 本轮用户正常游玩（自动化完成后）

1. 在已建立的基地按 F10，用鼠标点击“触发基地防守预警”，关闭面板；也可沿正常威胁进入预警。选择“亲自防守”，按来向提示到核心外标记走廊截击。库存压弹/装匣/医疗仍沿已有 Base 即时操作，F10 不负责伪造胜负。
2. 观察三波、下一波倒计时、已处理数与突破数；真实击发消耗弹药，站回核心不会阻止敌人逼近防线。可打开 F9 观察基地模拟与检查点复制/落盘数据。
3. 中途 Esc→返回主菜单→继续，应恢复同一场战斗、弹药及波次；Esc 暂停不推进。通过战斗胜利，或让防线突破/玩家倒下观察软失败，再核对个人物品仍在原处、消耗没有返还、结果只结算一次。
4. 若选择放弃，Esc 菜单需再次确认；这与保存退出不同。战后可继续整备/Raid，后续预警仍可选择原自动防守。

下一项具体候选：本片用户验收与合入后，先评审固定防御位置和 1～2 种基础阻挡工事，明确放置/回收、敌人绕行、布局保存与成本，再进入独立分支；不自动开展 NPC 守军或新增美术。
