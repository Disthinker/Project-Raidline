# Project Raidline 交付完成定义

一个产品切片或缺陷只有同时满足以下条件才完成：

- 范围与活动 ExecPlan 一致，明确排除项没有被顺带实现。
- 权威所有者、查询/命令/结果、失败原子性、稳定 ID 与持久化影响已说明并测试。
- 代码可读、无已知生命周期未定义行为，不保留跨容器结构变更的悬空引用。
- 受影响目标完成增量构建；头文件/类布局变更已重建所有消费者。
- 自动化按根 AGENTS 的改动类型完成，绑定准确候选树/构建；C++ 交付全量 CTest、C++ PR 精确 head 的 Windows/Ubuntu CI 通过。配置维护只检查格式、引用、加载和相关无副作用行为，不跑无关游戏全套。
- 玩家可见行为按 ExecPlan 完成真实窗口验收；记录步骤、预期、实际与偏差。
- 当前状态、已知问题和 ExecPlan 证据已更新。
- 待验收候选可为未提交工作区的范围清单/内容哈希+构建；自动化通过不是人工验收。明确验收当前候选后执行已约定 Git 交付；commit/本地 merge/远端 push/PR 状态分别记录。远端只在已有明确授权时执行，不能把“完成”定义当发布许可；必要 CI/依赖未就绪记录已验收交付受阻。
- 未经授权没有生成/发布美术、修改 manifest、自动合并、强推或重写历史。

教学讲义、学习台账和重复周报不是完成条件。需要解释复杂机制时可以写维护者文档，但它必须服务交付和接管，而不是为了教学配额存在。
