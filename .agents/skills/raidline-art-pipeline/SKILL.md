# Art Pipeline

Check the latest real package authorization under root AGENTS and [art-controller](../../../doc/coordination/roles/art-controller.md). This maintenance reopens no game production package. Older pause records do not override newer human instructions; catalog indexing has independent scope and never grants runtime publication. Review access does not authorize generation, art/work writes or manifest edits.

Choose the task path:
- **Read-only planning/asset review:** inspect relevant manifest/spec entries and estimate reuse/work; report IDs/use/spec/style/source/license and remaining authorization. Read ART_BIBLE.md for a style decision; do not load every art document for a path lookup. No need for art means no ceremonial art call.
- **Explicitly reopened production/derivation/publication:** read [production rules](references/production.md), art/PRODUCTION_TASK_PROTOCOL.md, the relevant spec and script before action. Apply the current package's exact authorization; this skill grants none.

Published assets are runtime inputs; art/work candidates are not. Preserve approved identities with new versioned paths, never overwrite them. Inventory UI/drag feedback stays code-rendered; collision/pickup bounds come from gameplay data, not alpha edges.

Handoff carries task/plan/package version and human authorization source, requested output and owner per path. Art-control is the default sole writer of official game asset paths/manifest only when publication is authorized; main reads and integrates code. A different writer requires a clearly approved path/phase handoff and the former owner to stop writing. Validate correlated native replies using THREADS; a result file alone does not wake the other thread.

Return source/asset IDs, approval state, checks and unresolved visual risks. Technical validation does not replace visual approval. External catalog indexing belongs to the art-control task and does not grant game publication authority.
