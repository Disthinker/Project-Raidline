# 只读取当前模式的简短格式

## 开发计划

【开发计划｜任务名称｜版本】

- 目标与策划依据；本次包含/明确不做。
- 文件路径 | 新增/修改/删除 | 主要变化及原因。先核查本地；新路径写“拟新增”。
- 现有→预期行为；涉及的输入/UI/领域/保存/性能/资源合同。
- 美术：是否需要、复用/新包、规格与写者、生产/发布授权是否缺失。
- 验证：自动化范围；用户前置→操作→预期；影响、风险与回滚。
- Git 检查点/交付方式：沿用哪条已授权规则；无授权则不 commit/push/PR。
- 状态：待用户批准，尚未实施。task_id / plan_version / baseline。

## 完成及复验

【开发完成｜任务名称｜候选版本】

- 实际关键文件与行为；计划偏差及原因。
- candidate_id：commit 或文件清单+内容哈希/代码树+构建。准确区分未提交工作区与 HEAD。
- 实际构建/测试/CI，绑定候选和日志；失败、未执行、排队分别列出。
- 人工验收：正确构建/启动入口，新档/场景要求，每项前置→普通操作→预期。
- 相关已知问题/影响；下一建议（未获实施授权）。
- 状态：待用户验收，未合并交付。实质修改重新编号，不沿用旧验收。

## Bug 分析与修复计划

【Bug 分析与修复计划｜问题名称｜方案版本】

- 现象/预期；已复现、部分复现或尚未复现。
- 已确认原因及证据（真实文件/函数/调用）；单列未验证假设。
- 最小合理修复的路径、逻辑与原因；局部/跨模块/结构性及依据。
- 受影响共享逻辑/调用方、必须保持的行为；相邻回归范围，不空称“无影响”。
- 验证原问题、邻近功能和回滚；有实质取舍时给推荐与必要替代。
- 状态：待用户批准，尚未修复。拒绝只改方案；获批后执行，再报候选等复验。

短任务可合并栏目，不能省略目标、真实文件、行为、验证及授权状态。配置维护的人工清单针对配置和无副作用行为，不要求启动游戏。
